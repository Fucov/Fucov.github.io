00 / EXECUTIVE SUMMARY

先判断技术主线，再选择论文题目

核心判断：三条研究线都在把优化对象从静态算子扩展到动态状态和动态执行。A 关心“未来哪些状态会被再次使用”，B 关心“下一步由哪张卡以什么代价完成计算”，E 关心“怎样表示、保留和恢复非 Token-indexed 的模型状态”。

A

Agentic Serving

将 Session / Tool / Subagent 的语义、时间不确定性和 Cache Residence 连起来。

长期价值：跨模型、跨架构、跨引擎的控制面能力
B

MoE & Expert Parallelism

从静态 Placement 走向每 Step 的 Token–Replica–Network 协同。

长期价值：硬件拓扑、并行原语和运行时性能模型
E

Hybrid State

从存储完整 Recurrent State 走向 Checkpoint、Replay、压缩与质量约束。

长期价值：新模型架构共用的状态接口与成本模型
研究路线建议：长期主线优先 A × E（Agent 生命周期驱动的异构状态管理）；近期快速取得性能剖析与工程结果的支线优先 B（通信/负载受限的 MoE Runtime）。这是对当前资源和已发表工作密度的判断，不是对未来录用概率的预测。

最重要的三项否定性结论

  1. Agent-aware Cache Eviction、Harness Lifecycle Hint 和 PD+Cache 联合管理都已经有研究，单纯做“预测式 LRU”或“状态标记”重复度高。
  2. MoE 的动态副本分配、每 Step LP 和 Comm–Compute Overlap 已有强 Baseline。单独做一个 Greedy EP Dispatch 很难支撑系统论文。
  3. Hybrid 的 PIC、Suffix Replay、State Compression、Decode 输入缓冲均已有公开工作。把它们堆叠在一起，并不自动形成方法创新。

02 / RESEARCH TRACK A

Agentic Serving：把下一次复用纳入调度

Agent 工作流具有“推理 → Tool 等待 → Resume → 再推理”的暂停—恢复特征，状态生存期与 Cache 最近访问时间错位。它同时是时间问题（何时返回）、空间问题（状态在哪个 Tier/节点）和语义问题（哪些消息未来有效）。

Decision: Keep / Demote / Prefetch / Recompute / Transfer
min E[restore_time + transfer_cost + memory_pressure + SLO_penalty]
subject to: GPU/Host capacity, correctness, future reuse uncertainty

研究脉络与代表性突破

Preble · ICLR 2025共享 Prefix 与负载均衡联合路由（历史基础）
CacheScout · 2026.07学习 Agent 转移，预测未来复用
KVTether · 2026.09显式生命周期信号
Evolving · 2026.11跨计算角色与缓存状态联合调度

基础工作：Preble · ICLR 2025 证明了分布式 Prompt Cache 命中与 Compute Load 是耦合关系，但其问题设定尚不是 Agent Harness 的语义驱动控制。

Evolving Infra

Agent-Adaptive LLM Serving at Scale
原文 ↗
Joint Scheduling / PD
研究问题
面对 Agent 的阶段性波动，固定 PD 角色与独立的缓存决策为何浪费资源？
核心方法
解耦计算角色和状态管理：在线规划器调整 Prefill/Decode 资源，Agent-aware 分布式 KV 管理器处理保留、淘汰与传输。

复用价值
这是‘联合优化’的重要竞争基线，简单联合 Cache 和 PD 已不具新颖性。

研究空白应怎样表述？

已覆盖尚值得验证的 Gap容易失败之处
转移概率驱动 Prefetch/Retention在返回时间具有长尾和分布漂移时，预测分布能否改善 P99 和资源机会成本？Oracle 上界不足；预测误差大于节省时间
消息级 Dead/Live/Idle不同 Harness 的 Cache Hint 是否可以形成统一的最小语义协议与可验证一致性模型？简单透传新字段，缺少独立系统创新
PD+KV 联合调度当状态由 Full KV、Recurrent State、Draft State 混合构成时，如何估计真实 Restore 代价？与 Evolving Infra 过度重叠；测量只在合成 Trace 有效
Token-level Phase-aware Eviction在信息不可恢复风险下如何把任务质量纳入 Cache/Storage 联合预算？质量指标不足、难以证明正确的近似边界
扩展阅读：PACE (2026.11) 讨论 Token 保留之后仍可能存在的位置与可检索性问题；CoMixKV (2026.11) 探索多 Agent 的 Layer/Bit-width 共享预算。这两篇强调了“命中率≠有效质量”与“状态之间的精度竞争”。
03 / RESEARCH TRACK B

MoE Expert Parallelism：从热点分布到真实执行时间

Expert Parallelism 的 Layer 完成时间受最慢 Rank 影响。如何在真实 Topology、专家副本数量、CUDA Graph 以及通信—计算重叠限制下，重新分配下一批 Token，是 2026 年最激烈的系统优化问题之一。

min over assignment π: max_rank T_rank(π)
T_rank ≈ critical_path(dispatch, grouped_GEMM, combine, overlap)
constraints: replica ownership, bandwidth, memory budget, graph stability

上面的 Critical Path 写法比直接把 Dispatch + GEMM + Combine 相加更贴近现代 EP 引擎：重叠机制会改变总时间。EP 是否值得做，必须区分 层内路由偏斜 与 跨节点通信瓶颈，并测量真实 Dispatch/Combine 时间分布。

研究演进

Semantic Parallelism数据与专家放置共同调度
Waterfill / LPLB已有副本上的低成本 Dispatch
LLEP / MegaFlux动态复制专家与移动计算
Relief / OverlapAdvisorStep 级 Solver + 真实关键路径模型

Relief

A Per-Step Load-Balancing Engine for Expert-Parallel MoE Serving
原文 ↗
Per-step Dispatch / Solver
研究问题
每个 Decode Step 都重新优化副本分配，求解器开销会不会比 MoE 层更昂贵？
核心方法
使用成对双向松弛、整数折半，低成本逼近最优 LP；讨论 GPU Kernel、FPGA 和专用硬件部署。
论文证据
论文报告接近每 Step 负载最优；其专用 On-die 方案相对静态放置可回收最高 37.3 个百分点的有效利用率。
覆盖边界

六个极易混淆的概念

概念真正改变了什么不能直接推断
Router Top-k模型选择逻辑专家改变逻辑 Top-k 可能影响模型语义与质量
Expert Placement逻辑专家在哪些 Rank 驻留放置均衡并不保证每一步 Token 均衡
Replica Dispatch同一个逻辑专家的 Token 分配到哪个物理副本没有冗余副本时没有分配自由度

Elastic EP改变 EP Rank 规模与生命周期重配置速度和线上连续服务能力必须单独测
现实性检查：如果当前只能使用 TP8、未启用 EP 或跨节点互联不可控，则先做 Layer-level Trace / Microbenchmark，不应直接宣称已具备多节点动态 EP 实验条件。B300 的 NVLink 域与 RDMA 域需要分开评测。
04 / RESEARCH TRACK E

Hybrid Attention：新型 Recurrent State 的系统生命周期

Full Attention 的 KV 通常按 Token 存储；GDN/KDA/Mamba 一类线性或递推层把历史聚合进持续更新的状态。状态大小可以不随 Context 长度线性增长，但其恢复、压缩、回滚与跨片段复用方式与标准 KV 完全不同。

Illustrative recurrence: Sₜ = F(Sₜ₋₁, xₜ)
State representation: checkpoint Sₖ + compact input records {xₖ₊₁ ... xₜ}
Choice: Keep / Compose / Quantize / Replay / Recompute / Move

关键研究转变：以前问“如何更快执行 KDA Kernel”，现在更应该同时问“什么形式的状态在整段推理生命周期中最划算”。特别是 Speculative Decode 的 Rollback、Prefix 缓存匹配与 Agent 恢复，可能共享底层表示，却对精确性有不同要求。

2026.07 · Preprint · E

HYPIC

Accelerating Hybrid-Attention LLM Serving with Position-Independent Caching
原文 ↗
Segment Composition / PIC
研究问题
全注意力的 Token-indexed KV 可以拼接；线性状态没有逐 Token KV，非连续片段缓存如何实现？
核心方法
保存片段状态转移算子和 Zero-start End-state，组合线性层状态；对 Full Attention 在片段接缝处有限重算。
论文证据
在四种混合模型和五类负载上，平均 TTFT 改善 2.45×，峰值吞吐最高 2.0×；与全重算质量差异控制在论文给出的范围内。
覆盖边界
状态组合依赖具体递推算子，不能直接普适迁移到所有 GDN/KDA/Mamba 变体。
复用价值
为非连续上下文复用建立代数层面的新操作原语。
2026.07 · Preprint · E

LinearKV

One Cached State Suffices for Position-Independent Caching in Hybrid LLMs
原文 ↗
Initializer / Approximate Reuse
研究问题
真的需要精确组合所有缓存的状态片段，才能获得高质量生成吗？
核心方法
用单个已缓存的局部状态作为线性层初始化，Full Attention 仍用既有 PIC 流程；对比严格组合与近似初始化。
论文证据
论文报告：两种 GDN 模型上两类方法相近；在其 Mamba-2 实验中严格组合可能显著损害质量。
覆盖边界
‘单个缓存状态足够’不是严格的普适定理；任务、模型与选择器会影响结果。
复用价值
精确代数与最优推理效果未必同义，必须把质量纳入状态优化。
2026.08 · Preprint · E

Tail-Replay

Escaping the Curse of Linear Attention in Prefix Caching for Hybrid LLMs
原文 ↗
Suffix Replay / Granularity
研究问题
如果没有相应的 Recurrent Checkpoint，能否恢复任意 Token 边界上的混合模型状态？
核心方法
精确保留 Full Attention KV；线性状态利用过去信息逐渐衰减的性质，仅重放较近后缀近似恢复。
论文证据
LongBench / RULER 测试中，使用 5%–10% 重放预算维持论文报告的 92.8%–99.9% 全重算质量；32K Prefix 下 TTFT 相对全 Prefill 提高 9.1–14.3×。
覆盖边界
对长程精确依赖、不同衰减机制可能失效；只保留质量平均数不足以保证 Agent 的关键事实准确性。
复用价值
提示‘算一些比存全部更划算’，但重放预算须由质量与系统负载共同约束。
2026.08 · Preprint · E

DASC

Decay-Aware State Compression for Hybrid Linear-Attention Serving
原文 ↗
State Compression / Precision
研究问题
不同 Head 和 Channel 的长期记忆保留能力是否相同？压缩哪些部分损失最小？
核心方法
从模型权重推导 Retention Horizon，按 Head / Channel 保留长程贡献较大的状态单元，必要时通过有限后缀刷新。
论文证据
作者在 Kimi-Linear 场景中报告 KDA Checkpoint 约 2.63× 压缩；在相同缓存预算下，平均 TTFT 降低 42.6%、输入吞吐提高 68.4%。
覆盖边界
特定压缩配置与任务精度边界相关；长跨度精确事实恢复和高负载运行时抖动值得单独验证。
复用价值
把状态组织优化到 Head/Channel 粒度，适合做质量—容量权衡分析。
2026.10 · Preprint + Implementation · E

ReplaySSM

Cache SSM Inputs, Not State
原文 ↗
Decode / Speculative / Low Precision
研究问题
Recurrent State 每个 Decode Step 都读写，为什么成了高并发 Hybrid 模型的 HBM 瓶颈？
核心方法
把状态表示为 Checkpoint + 最近输入缓冲，低频 Flush；允许廉价 Speculative Rollback，并把读精度与递推更新精度解耦。
论文证据
在 B300 Batch=256，四种混合模型上的标准 Decode 加速 1.20–1.47×（相对调优 vLLM）；相关工程已见于 vLLM/FlashInfer 等路径。
覆盖边界
ReplaySSM 重点是 Decode 递推表示和 Speculation，不等于解决 Agent 多轮 Prefix 与跨层级缓存；也不适宜再提出简单的‘输入缓存替代状态’。
复用价值
对 B300 + KDA/GDN 最有即时复现价值，且为 A×E 提供新的状态表示基线。

05 / CROSS-DIRECTION SYNTHESIS

A × B × E 的交汇：推理状态、计算和网络的联合决策

A → BAgent 返回突发会改变 Batch、Token 路由和 MoE 热点，Cache 优化未必改善 EP Critical Path。
A → EAgent 重入使 Hybrid State 的 Checkpoint / Replay / Restore 成为首要路径，缓存价值不再简单按 Token 或 Byte 计算。
B → EHybrid MoE 同时拥有路由专家计算与复杂状态更新，Expert Communication 和 State Memory 流量会竞争硬件资源。

一个统一但可分阶段实现的抽象

An execution unit = (future-use distribution, state representation,
compute placement, transfer/restore cost, quality constraint, SLO)
Policy = choose {replica, tier, representation, restore path, execution plan}

这不是要求一次性开发涵盖全部层级的庞大调度系统，而是用同一个成本与正确性框架拆分多个可发表、可复现的小问题。先做 A×E 的成本归一，再根据真实 Trace 决定是否把 B 的 EP 关键路径并入模型。

怎么判断论文不是“已有方法简单组合”？

  1. 新现象：记录一个现有方法无法解释的稳定性能或质量失效，例如同等命中率却有完全不同的 Agent P99。
  2. 新模型：以清晰的状态、约束和可计算近似描述失效机制，产生能预测的 Cross-over Threshold。
  3. 新机制：策略能够跨负载/模型提升 Pareto Frontier；解释为何它在某些条件下应关闭。
  4. 系统证据：实现于真实 SGLang / vLLM 路径，具备端到端、微基准、消融和成本开销的闭环。

07 / IMPLEMENTATION AND EVALUATION

四周预研：先测机制，再决定半年投入

Week 1 · 研究假设与 Trace 基线

确定模型/硬件/并行方式；采集 Agent Session、Tool Wait、Prefix 命中、KV Age、状态字节、MoE 每层 Expert Histogram。优先使用公开 Trace 和受控合成工作负载；公司内部数据不得放入公开 HTML、仓库或外部 API。

Week 2 · 建立三种跨越成本

A：Keep vs Host Offload vs Recompute；B：Static EP vs LPLB/Waterfill vs Topology-aware Oracle；E：Full Recurrent Checkpoint vs Replay/Compress/Flush。每个交叉点至少给出均值、P95、P99 与置信区间。

Week 3 · 验证结构性假设

改变 Agent 返回分布、Context 长度、Reuse Working Set、MoE 热度偏斜、EP 内/跨节点链路和 State 衰减模式。保证 Baseline 的并行与精度约束一致，检查收益是否仍然成立。

Week 4 · 最小原型 / 选题门槛

只实现最稳定的一个机制，形成 Macrobenchmark + Microbenchmark + Ablation + Overhead Breakdown；如没有稳定改善或没有明确超越近两个月论文的贡献，则暂停扩大实现。

论文评估中的三个硬门槛

  • 公平性：比较同模型、同质量要求、同系统约束；报告 Baseline 已开启的所有优化与软件版本。
  • 归因：端到端提升必须对应到某条系统关键路径的减少，并说明 Planner 自身开销。
  • 鲁棒性：至少跨两类负载形态、两种模型或设备配置检验，而非只挑收益最大的单点。
