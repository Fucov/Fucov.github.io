Abstract

Original Abstract Summary

vLLM v0.32.0 aggregates 814 commits into a stable serving release. It expands low-precision KV cache support across NVIDIA and AMD hardware; advances Model Runner V2 with GPU n-gram speculation, elastic expert parallelism and pipeline plus prefill-context parallelism; reduces startup and multimodal transfer overhead; extends MoE communication and KV connectors; and adds RL-oriented sleep, versioned outputs and weight-transfer controls. The release also ships security hardening and several breaking defaults.

中文摘要

该版本把“模型适配”上移为 runtime 共性能力：KV cache 可以按硬件与模型选择 NVFP4、FP8 或 4-bit 路径，MRV2 纳入投机解码与弹性 EP，大规模服务侧补齐 DeepEPv2、NCCL 对称内存、NIXL/Mooncake connector，RL 场景则强化 sleep、权重传输和版本追踪。它是工程集成型贡献，不是单一算法论文。

Technical Analysis

Problem

前沿 LLM serving 的瓶颈已跨越单一 attention kernel：长上下文受 KV 容量与连接器影响，MoE 受跨节点 All-to-All 与布局影响，RL rollout 还要求频繁释放显存、同步权重并追踪版本。零散优化若不能进入统一 runtime，部署者仍需维护大量模型和硬件分支。

Method

以 Model Runner V2 为执行骨架，将 GPU n-gram、弹性 EP、MLA 的 PP+prefill context parallelism、stock torch.compile 等能力统一；KV 路径按模型/硬件选择低精度格式；大规模 serving 同时改进 DeepEPv2、NCCL symmetric-memory reduce-scatter、NIXL/Mooncake/MoRIIO/KVCR connectors；启动阶段预下载/预热 FlashInfer kernel 并用共享内存 tensor arena 降低跨 worker 拷贝。

Architecture

请求进入 Python/Rust frontend 与 least-loaded API worker；scheduler/engine core 由 MRV2 组织 prefill、decode、speculation、PP/PCP/DCP/EP。模型状态分为 weights、KV/SSM state 与 multimodal tensors：前两者可通过 sleep/weight-transfer/KV connectors 跨阶段或跨节点移动，后者经共享内存 arena 分发。底层 kernel/communication 层覆盖 FlashInfer、DeepGEMM、AITER、DeepEPv2、NCCL symmetric memory、NIXL、Mooncake 与多硬件后端。

Key Innovation

关键新增量是把低精度 KV、混合并行、MoE 通信、connector、RL 生命周期和多硬件 kernel 纳入同一稳定版本，并给出面向真实模型/硬件的默认值与兼容边界；这比孤立 microbenchmark 更接近可部署系统。

Experiments

Release notes 汇总各 PR benchmark，硬件与负载不统一：GLM-5.x FP8 KV/HiSparse 主要在 SM100/B200；SM90 使用 fp8_ds_mla；API worker 路由使用 Qwen3-0.6B、32 input/1 output 短请求；NCCL symmetric-memory MoE reduce-scatter 报告 9.6–16% latency 降幅；DeepSeek-V4.1 1M context 的 long-context indexer prefill 最多降低 25% TTFT。没有单一端到端基准覆盖全部特性。

Editorial Assessment

Why It Matters

vLLM 是生产级开源 serving 的事实接口层之一。大版本同时改变 KV 默认精度、通信后端、并行执行和安全默认值，直接影响容量规划、升级风险与多硬件可移植性；对 agent/RL 平台，显存释放和无停机权重传输尤其关键。

Limitations

性能数字来自不同 PR、模型、硬件和负载，缺少统一可复现实验矩阵；部分能力为 opt-in 或受特定 GPU 架构限制。Python 3.10、宽松 CORS、cascade attention、AsyncTP/compile SP pass 等被移除或改变，升级需兼容性验证。稳定 release 不等于所有组合均已覆盖。

03
FlashInfer v0.7.2

共同点：低精度 KV、MoE、投机验证与 Blackwell/Rubin kernel。核心区别：FlashInfer 是 kernel/runtime library，vLLM 是端到端 serving 引擎。新增量：vLLM 将预编译 kernel 下载、autotune 预热和具体模型路径接入调度/服务层。

04
LMCache / Mooncake

共同点：跨层级 KV 传输、P/D 解耦与远端缓存。核心区别：它们聚焦 KV 数据平面；vLLM 同时负责请求调度、模型执行与 connector 生命周期。新增量：NIXL、Mooncake、MoRIIO、KVCR 等连接器在统一 engine 内的兼容与观测。

05
vLLM v0.31.0

共同点：DeepSeek-V4.1、低精度 KV、MoE 与 CUDA Graph 路径。核心区别：v0.32.0 新增 MRV2 GPU n-gram/Elastic EP、更多 KV 格式、RL sleep/权重传输和大规模 connector。新增量：814 commits 的新稳定版本，而非无实质更新的重复收录。
