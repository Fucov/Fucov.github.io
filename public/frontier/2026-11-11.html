Abstract

Original Abstract Summary

The paper presents a one-sided expert-parallel all-to-all for MoE inference inside an NVLink domain. It removes the metadata exchange and expert-major repacking common in existing paths, and offers Fence and Sentinel synchronization protocols for throughput- and latency-oriented regimes.

中文摘要

论文针对小批量 MoE 推理中由同步、元数据交换和重排主导的固定开销，设计单边通信与 rank-major 缓冲布局，使通信结果可直接进入 grouped GEMM。

Technical Analysis

Problem

DeepEP/NCCL 类路径在小 token 批量下受固定同步与额外拷贝支配，dispatch 与 combine 每层都可能耗费数十微秒。

Method

源 rank 根据本地路由直接写入目标 GPU 的对称内存；Fence 以系统级 fence 与 flags 同步，Sentinel 以数据到达本身作为完成信号。

Architecture

NVLink symmetric memory → rank-major dispatch workspace → 索引化 grouped GEMM（FlashInfer Prims-TS）→ rank-major combine workspace；通过 FlashInfer MoEEpCommunication 暴露模块化接口。

Key Innovation

避免预先交换 token count/expert id，也避免把接收 token 再复制为 per-expert contiguous layout；通信与 MoE compute 后端解耦。

Experiments

NVIDIA Blackwell GPU、不同 EP 规模与每 GPU token 数；对照 DeepEP、DeepEP+DeepGEMM 与 MegaMoE。论文明确最大收益集中在小批量；完整表格见原文。

Editorial Assessment

Why It Matters

MoE 解码常处于小批量固定开销区间；把布局和同步协议共同设计，能直接缩短每层通信关键路径。

Limitations

仅覆盖单一 NVLink 域；跨节点 RDMA 不适用同一细粒度 load/store 协议。代码开放状态未在 arXiv 页明确披露。

Editor Note

S 级：系统问题清晰、NVIDIA 第一方硬件证据强；复现性因代码未确认而扣分。

Abstract

Original Abstract Summary

TKNP decouples model-weight placement from attention ownership. A single model copy is distributed as balanced layer blocks, while each node computes attention for locally owned requests and the active node executes dense layers for the full batch.

中文摘要

TKNP 利用解码阶段 dense 与 attention 的扩展规律不同：dense 计算保留节点内 TP，而 KV/attention 按请求跨节点分片，从而同时扩展 KV 容量并避免 partial-attention 合并。

Technical Analysis

Problem

DP 复制权重挤压 KV，TP 受 KV-head 数约束且把 dense collective 推到跨节点，DCP 又需要跨节点合并局部 attention。

Method

单份模型权重按平衡 layer block 放到不同节点；活动节点执行全批量投影/MLP，各节点对本地请求和本地 KV 做 attention。

Architecture

层块轮换 active root；节点内 TP+NVLink all-reduce，节点间 scatter/gather 仅传当前 token activation；capacity-aware request assignment 保持 KV 均衡。

Key Innovation

把 dense 的权重共享域与 attention 的状态所有权分离，使 attention 横向扩展而不复制整份权重或合并 partial results。

Experiments

Llama 3.1 405B 与 Nemotron-4 340B，最多 64×H100；长上下文、高并发；在相同 GPU 数下对比 DCP 与 DP。

Editorial Assessment

Why It Matters

这是针对超大模型解码的并行维度重构，可把跨节点带宽用于小 activation 而不是 dense collective 或 KV 聚合。

Limitations

需要层块调度和请求归属管理；低并发或短上下文时收益可能缩小；实现虽基于 vLLM，代码公开状态未核实。

Editor Note

S 级：在 340B/405B、64 H100 上给出系统级证据；部署复杂度与代码状态是主要风险。

Related Work

01

都扩展 KV 容量；TKNP 不拆单个请求的 attention，因此不需跨节点归并。

02
Tensor Parallelism

TKNP 保留节点内 TP，但阻止 dense all-reduce 跨节点。

03
Data Parallelism

DP 复制模型；TKNP 仅保存一份跨节点分块权重。

04

都采用阶段/资源解耦；TKNP进一步重构 decode 内部并行。

Abstract

Original Abstract Summary

ShadowPrefill addresses prefix-cache loss when an agent router switches models within a session. It opportunistically prefills the unchosen model using SLO slack, spills shadow KV to host memory, and falls back safely when the shadow is incomplete.

中文摘要

系统把“未来可能切换的模型”视为需要后台保温的缓存目标，以受控影子 prefill 提前支付模型切换的上下文重算成本。

Technical Analysis

Problem

Agent 每步路由可降低模型成本，但模型一切换就失去该模型的 prefix KV，长上下文导致切换调用显著变慢。

Method

从服务中请求的逐迭代 slack 和 idle gap 中借用算力；保护正式请求 SLO；shadow KV 可 spill 到 host；不完整时冷切换。

Architecture

LLMRouter 决策层 + 两模型服务实例 + shadow prefill controller + GPU/host KV tier + cold fallback。

Key Innovation

把路由器的未来切换概率与服务实例的瞬时 SLO 余量联动，避免为影子工作预留专用容量。

Experiments

24 个模型对、5 组 agentic benchmark；包含平均 63K context 的生产 coding-agent trace；比较同模型与切换调用。硬件细节见论文，摘要未完整披露。

Editorial Assessment

Why It Matters

Agent serving 的成本优化若忽略状态迁移，会把节省的模型费用重新付给 prefill；该工作提供可部署的状态预热机制。

Limitations

需要双模型可用且有可收割 slack；模型组合与路由分布变化会影响命中；未确认代码开放。

Editor Note

S：真实 workload 与 SLO 保护证据强；跨更多模型家族和长期容量竞争仍需验证。

Abstract

Original Abstract Summary

The work models lookup-table placement using per-layer prefetch deadlines, session reuse and device contention. SlackTier starts all lookups at each step, prioritizes the short-window layer, and divides a small GPU row cache across layers.

中文摘要

论文指出查找表的正确 tier 不是只由热点决定，还由表所在层距 step 起点的截止期决定，并在 SGLang 中实现 deadline-aware 层次存储。

Technical Analysis

Problem

DeepSeek-V4.1 的 203GB Engram 表占据大量 host DRAM；简单移到 NVMe 会造成 decode stall，而不同层可隐藏的 I/O 时间差 30×。

Method

测量层级读延迟与预取窗口，建立 slowdown 模型；step 开始即发起查找，先处理短窗口层，再分配小型 GPU row cache。

Architecture

SGLang decode CUDA Graph → 异步 lookup scheduler → GPU cache/host DRAM/NVMe/RDMA tiers → bit-exact gather。

Key Innovation

把 per-layer deadline 作为 placement 一等约束，并利用跨层计算覆盖 I/O；同一远端表副本可服务两个实例。

Experiments

4×H200 节点；DeepSeek-V4.1、agent/chat replay、4 块 NVMe；另测 RDMA 远端内存与 Qwen3.8 PLE。

Editorial Assessment

Why It Matters

模型参数开始包含超大稀疏查找结构，服务内存管理必须同时理解层位置、复用和 I/O deadline。

Limitations

结果依赖 Engram/PLE 类可提前确定索引的结构；NVMe 拓扑和 contention 可改变结论；代码未确认开放。

Editor Note

A+：实验把容量释放转化为 KV 吞吐收益，证据链完整；通用性受模型结构限制。

Abstract

Original Abstract Summary

ForeSpark introduces work-conserving speculation for parallel drafters. It predicts acceptance before drafting, jointly allocates draft and verification lengths by a global sort, and redistributes verification after drafts are available.

中文摘要

论文把 speculative decoding 的资源控制从“只限制验证”扩展为“草稿与验证联合调度”，针对高负载下大量 draft 从未被验证的问题。

Technical Analysis

Problem

并行 drafter 一次生成整个 block；高负载时 draft 可占 step time 40%，多数 token 因未获验证预算而直接丢弃。

Method

context-aware pre-draft estimator 预测各候选长度接受率；global-sort scheduler 联合分配预算；post-draft 阶段把验证资源给最有希望 token。

Architecture

vLLM scheduler → pre-draft estimator → parallel drafter → joint budget allocator → target verifier；保持目标输出分布不变。

Key Innovation

在 batch 耦合约束下，以轻量全局排序同时控制两个预算，而不是沿用 autoregressive drafter 的单请求长度控制。

Experiments

vLLM 原型；与 DSpark 和 autoregressive decoding 对比；在 matched per-request generation rate 与 latency SLO 下测 throughput/load。完整 GPU 型号以论文为准。

Editorial Assessment

Why It Matters

推测解码进入多请求在线服务后，goodput 的瓶颈从接受率转向共享 step 的预算浪费，调度成为核心。

Limitations

最大加速不可跨负载拼接；预测器误差与 batch composition 会影响收益；代码未核实。

Editor Note

A+：机制直接命中高负载浪费，vLLM 端到端证据较强；机构与开源状态未核实。

Abstract

Original Abstract Summary

ADIndex accelerates DeepSeek Sparse Attention indexing through layer-wise calibration, group-level distillation and shared token banks with query-specific refinement. It targets the indexer rather than the sparse attention kernel itself.

中文摘要

论文观察到相邻 query 的检索重叠随层显著变化，据此为每层选择 group size 与 bank budget，并让轻量 group indexer 蒸馏原 DSA 的检索分布。

Technical Analysis

Problem

DSA 虽减少 attention 计算，但 indexer 仍为每个 query 扫描全前缀；128K 时可占 prefill GPU 时间 54.2%。

Method

离线统计每层 Top-K union；选择 G/P 配置；蒸馏 group indexer 构建共享 bank，再用原 indexer 做 query-specific refinement。

Architecture

冻结 backbone/DSA teacher → group-level distribution distillation → layer-specific bank config → shared full-prefix scan → per-query Top-K refinement → Sparse MLA。

Key Innovation

同时利用跨 query 与跨层异质性，把共享候选集预算按层配置，而非统一复用策略。

Experiments

DeepSeek-V3.2、GLM-5.1；LongBench、LongBench v2、RULER；128K/256K context；对标准 DSA 及 HISA/MISA/IndexCache/PIVOT 类方法。硬件细表见论文。

Editorial Assessment

Why It Matters

稀疏 attention 的下一瓶颈正在从 attention kernel 转移到 token selection；该工作给出端到端验证。

Limitations

需要额外蒸馏和离线校准；模型/层分布变化需重校；摘要未披露代码。

Editor Note

A+：问题和结果鲜明，但复现性与硬件细节需依赖正文。

Plumbline: When the Loss Lies, Validating LLM Training Correctly

Abstract

Original Abstract Summary

Plumbline is a production LLM-training correctness system at Amazon. It validates lifecycle stages, individual training steps and whole runs, and reuses those checks for root-cause tracing across models and frameworks.

中文摘要

系统不把下降的 loss 当作正确性证明，而是为数据、层实现、并行设置、checkpoint 与最终 served model 建立独立可信参照和噪声边界。

Technical Analysis

Problem

分布式训练错误可能来自用户代码、框架、依赖或硬件，且可保持 loss 正常直到最终评测才暴露。

Method

correctness-first reference comparison + modular checks；Day-0 全扫描新模型；诊断 agent 在人工审批下选择检查并缩小根因。

Architecture

data/lifecycle checks、single-step anchor checks、whole-run checks、record/replay diagnosis tools 与 agentic orchestrator；规则按系统版本固化。

Key Innovation

用同一组可组合检查贯穿 onboarding 与故障追踪，并跨 13 个 framework-model 组合复用。

Experiments

Amazon 生产使用；3 个框架（AutoModel、Megatron-SWIFT、Miles）、5 个模型、13 个组合；对真实 Day-0 onboarding 和故障进行人工确认。

Editorial Assessment

Why It Matters

大模型训练浪费往往来自“数值看似合理但语义/配置错误”；前置验证可避免昂贵长跑和错误 checkpoint 扩散。

Limitations

每个 check 有定义边界且仍需人工确认；尚未开源，论文称未来发布；不能证明未覆盖路径完全正确。

Abstract

Original Abstract Summary

HiLo replaces adapter-parameter broadcast with compressed gradient dissemination and deterministic optimizer replay at rollout workers. Spar combines spectral truncation, adaptive rank allocation and error feedback under a communication budget.

中文摘要

工作针对 learner 与地理分散 rollout workers 的 LoRA 同步瓶颈，让每个 worker 持有优化器状态并从同一解码梯度重建一致策略版本。

Technical Analysis

Problem

降低训练 LoRA rank 会限制容量，而高秩 adapter 在带宽受限网络中频繁广播会阻塞 on-policy 更新。

Method

传播压缩梯度；各 worker 重放 AdamW/Muon 状态转换；Spar 对梯度做谱截断、按预算分配 rank 并用 error feedback 累积残差。

Architecture

learner → gradient compressor/wire format → ordered WAN dissemination → worker optimizer replay → version consistency/recovery check → rollout。

Key Innovation

把同步对象从参数改为可重放的梯度与优化器转换，使训练 rank 与通信 rank 解耦。

Experiments

on-policy distillation 与 reward-guided post-training；Knights and Knaves、Countdown-4 等；对 full sync、低秩与多种 compressor/optimizer 情况。硬件与 WAN 模拟细节见正文。

Editorial Assessment

Why It Matters

异步/广域 rollout 集群增长后，policy freshness 与同步带宽成为 actor–learner 系统关键矛盾。

Limitations

worker 必须复制优化器状态并保证可复现执行；乱序/恢复复杂；摘要未披露大规模生产集群验证和代码。

Venue

Abstract

Original Abstract Summary

The paper attributes slower BF16 RL post-training to weight sticking under round-to-nearest conversion from FP32 shadow weights. Stochastic rounding lets small updates affect the BF16 weights probabilistically and recovers FP16-like convergence without raising the learning rate.

中文摘要

在 RLVR 的低学习率区间，小更新常不足以改变用于 rollout/训练的 BF16 权重；随机舍入让这些更新以无偏方式逐步显现。

Technical Analysis

Problem

标准 mixed-precision BF16 在相同学习率下比 FP16 收敛慢；提高学习率虽减轻 sticking，却增大相对参考模型的 KL。

Method

定位 FP32→BF16 round-to-nearest 造成的多步停滞；改用 stochastic rounding，同时保留 BF16 动态范围且无需 loss scaling。

Architecture

FP32 master/shadow weights → optimizer update → stochastic BF16 quantization → BF16 rollout 与训练 forward；与 FP16/高 LR BF16 对照。

Key Innovation

把 RL 后训练的精度差异解释为权重更新可见性问题，而非单纯数值范围，并给出局部可替换的舍入策略。

Experiments

多个模型与数据集上的 RLVR；同学习率 BF16/FP16、提高学习率 BF16、stochastic rounding BF16 对比。摘要未披露具体硬件、模型名与步数。

Editorial Assessment

Why It Matters

精度格式不仅影响吞吐，也会改变 on-policy 数据生成与更新可见性；训练框架需把舍入模式纳入算法配置。

Limitations

缺少摘要级具体数值与硬件；随机舍入内核开销及跨框架一致性需验证；代码未披露。

Editor Note

B：机制有价值但量化证据与复现信息有限，不应把“匹配”外推到所有 RL 配方。
