Abstract

Original Abstract Summary

This release candidate extends FlashInfer with architecture-specific inference kernels and communication paths for Blackwell and Rubin-class GPUs. It adds low-precision decode, MoE and speculative-verification kernels, model-specific profiles, and MNNVL CuTe DSL collectives across 39 commits.

中文摘要

该候选版本不是单一算法论文，而是一批面向新硬件和前沿模型的底层交付：注意力、MoE、FP8/NVFP4、推测验证与机内高速互联被融合到可安装制品中。

Technical Analysis

Problem

前沿模型和新 GPU 的性能常受 kernel 缺失、量化格式转换和通信边界限制，通用实现难以充分利用硬件。

Method

以 CuTe DSL/CUDA 为主要实现，为特定 SM 架构、模型形状和并行拓扑提供 fused kernel、profile 与 JIT wheel，并扩展 MNNVL all-reduce。

Architecture

模型前端选择 kernel/profile；执行层融合 MLA 打包与量化、MoE norm/TP/EP、EAGLE verify 和低精度 decode；通信层加入 MNNVL CuTe DSL 后端。

Key Innovation

把模型适配、低精度计算与 GPU fabric collective 同步推进，减少跨库格式转换和 launch 边界。

Experiments

证据是 release diff 与代码；覆盖 B300/Rubin、Kimi K3、DeepSeek V4、Muse Spark 等路径。没有统一硬件矩阵或端到端基准，不能从提交名推断加速倍数。

Editorial Assessment

Why It Matters

FlashInfer 是多个 serving runtime 的 kernel 依赖；这些路径会影响新模型和新 GPU 能否快速进入生产。

Limitations

RC 而非 stable；39 commits 的正确性与收益尚需集成方验证。缺少统一性能数字，部分 JIT 轮子和架构路径体积较大。

Editor Note

89/A+。代码证据和工程影响强，因 RC 状态与缺乏统一实验扣分。

Abstract

Original Abstract Summary

KVCompass introduces a discovery plane for globally locating reusable prefix KV state without coupling identity to placement. A constant-time edge table supports variable-length prefix lookup, while routing balances reuse value against remote transfer and load.

中文摘要

KVCompass 把跨区域 KV 命中从“调度器本地目录”提升为独立控制面问题，并在命中收益、远端传输与负载均衡之间做在线决策。

Technical Analysis

Problem

分布式 prefix cache 的目录、放置和路由耦合会形成热点；跨区查找又可能让控制路径和远端传输拖垮尾延迟。

Method

以全局 discovery plane 维护前缀身份和位置，边缘表进行可变长前缀常数时间查找，路由策略联合估算复用、网络与 worker 负载。

Architecture

边缘请求先查 discovery plane，再选择本地复算、远端 KV 传输或负载更轻 worker；KV 数据面与路由元数据分离。

Key Innovation

将 prefix identity 与 placement 解耦，并给出跨三洲真实试验，不只局限于单集群 cache-aware routing。

Experiments

64-worker geo simulation 与 14-worker、三洲真实 testbed；对比现有路由和 Oracle，覆盖 P99 TTFT/E2E、吞吐和负载因子。

Editorial Assessment

Why It Matters

长上下文和 agent session 让 KV 成为分布式状态；全局可发现性是弹性扩缩容和多区域服务的基础。

Limitations

跨洲结果依赖网络和 workload 前缀分布；论文未在摘要中披露全部模型、GPU 与目录故障处理。代码开放状态未核实。

Editor Note

93/S。新颖控制面、真实三洲试验和强尾延迟结果突出；复现材料和完整硬件信息不足。

Abstract

Original Abstract Summary

Koi combines a hierarchical reasoning model with a deterministic causal graph and planner to configure heterogeneous LLM serving. It searches accelerator, parallelism, engine, replica and cloud choices under feasibility and SLO constraints.

中文摘要

Koi 将 LLM 负责生成候选和解释、确定性图负责约束传播与验证，避免让语言模型直接猜复杂系统配置。

Technical Analysis

Problem

异构 serving 的可行配置空间巨大，约 140 个变量跨硬件、并行、runtime 和部署层相互约束；黑盒搜索成本高且容易产生不可执行方案。

Method

分层 reasoning model 先分解目标并调用工具，因果图编码兼容性/容量/SLO 约束，规划器剪枝并验证候选。

Architecture

输入 workload/SLO/价格与集群资源；上层 RLM 选择子问题和工具；中层 causal graph 传播约束；下层 planner 输出可部署配置并回测。

Key Innovation

以 LM 的开放式推理补充确定性系统模型，同时用约束层阻止幻觉配置，兼顾可解释性和可执行性。

Experiments

真实异构集群，对比纯 LM、LM+tools 和系统基线；指标含 composite score、goodput 与 $/token。公开摘要未列出全部 GPU 型号和 workload 分布。

Editorial Assessment

Why It Matters

配置错误会吞噬 kernel 优化收益；Koi 指向面向多云/多 GPU 的自动容量规划与 runtime tuning。

Limitations

因果图维护成本、模型漂移和跨版本 runtime 兼容性尚不清楚；1.18× 来自特定集群，不能泛化为所有 workload。

Editor Note

92/S。问题重要、设计稳健、端到端成本结果清晰；代码和完整实验矩阵未核实。

Abstract

Original Abstract Summary

SigmaTrace traces communication beneath collective libraries at the verbs and mlx5dv layers, including GPU-initiated RDMA. It reconstructs communication events without source changes or binary instrumentation and scales to large NCCL/RCCL jobs.

中文摘要

SigmaTrace 把可观测点下沉到 verbs 设备接口，因此即使通信从 GPU kernel 直接发起，也能重建事件并关联 collective 行为。

Technical Analysis

Problem

现有 profiler 依赖特定库 hook 或 CPU launch；GPU-initiated communication 和持久 kernel 使这类观测失效。

Method

拦截/解析 libibverbs 与 mlx5dv 控制路径，追踪 queue pair、work request 和 completion，并重建跨节点事件。

Architecture

控制面记录资源和队列映射；数据面捕获 CPU/GPU 发起的 RDMA；离线分析将底层事件聚合为 collective、barrier 和流量偏斜。

Key Innovation

首次在不改源代码/不做二进制插桩的条件下覆盖 GPU-initiated RDMA，并验证到 1024 GPUs。

Experiments

NCCL 128-GPU AllReduce、RCCL 1024-GPU，以及 persistent BFS 与 MoE inference；指标为 tracing overhead 和诊断案例。

Editorial Assessment

Why It Matters

MoE EP、NVSHMEM/NCCL 融合和持久 megakernel 让通信越来越不可见；低开销追踪是性能回归与根因分析的基础。

Limitations

依赖 verbs/mlx5dv 生态，其他 NIC/transport 的可移植性未证明；诊断案例不等于自动修复。

Editor Note

91/S。可观测性缺口明确、规模与代码证据强；硬件/传输覆盖范围限制通用性。

Abstract

Original Abstract Summary

The work co-compiles draft and target models for speculative decoding, allowing cross-model operator interleaving and shared scheduling rather than compiling each model independently. An agentic MCTS compiler searches schedules under hardware constraints.

中文摘要

传统编译器把 draft/target 当作两个独立图，导致每轮验证前后 GPU 资源空闲。共轭编译在统一图内寻找可重叠、可交错的算子。

Technical Analysis

Problem

投机解码减少 target steps，却在每轮引入两个模型的串行执行；单独优化各模型无法消除跨模型气泡。

Method

构造联合计算图，用 agentic MCTS 搜索跨模型算子交错与内存可行的 schedule，再生成单 GPU 执行计划。

Architecture

draft 和 target 图进入统一编译 IR；搜索器评估依赖、占用和内存；runtime 按联合 schedule 发射 interleaved kernels。

Key Innovation

将编译优化边界从单模型扩展到一对协作模型，直接针对 speculative round latency。

Experiments

B300 与 RTX 5090，六种单 GPU draft/target 配置；报告 per-round latency、interleaved 方案与 utilization。

Editorial Assessment

Why It Matters

随着 draft/verify kernel 变快，跨模型 launch/资源空洞会成为主导；联合编译提供新的优化层。

Abstract

Original Abstract Summary

TideKV uses a layer-major chunked-prefill schedule. It keeps full-prompt KV only for the active Transformer layer and evicts at layer end, preserving global selection while lowering construction-time activation and temporary memory.

中文摘要

TideKV 解决“压缩后 KV 很小，但构建它时仍要先装下完整 prompt”的峰值问题；延迟到每层末尾淘汰，兼顾全局选择与低峰值。

Technical Analysis

Problem

post-prefill KV compression 不降低构建峰值；逐 chunk 提前淘汰又会在未见完整 prompt 时做错误选择。

Method

将 chunked prefill 的循环顺序改为 layer-major：一层内遍历全部 chunk，完成全局选择后在层末压缩/淘汰。

Architecture

同一时刻仅活动层保留 full-prompt KV；中间 activation/temporary 随 chunk 释放；最终 cache 兼容现有压缩方法。

Key Innovation

通过调度次序而非更激进压缩降低峰值，并保持被评估压缩方法的最终 cache size 与质量。

Experiments

A100、RTX 4090 与 Jetson；64K/128K 长上下文，对比 post-prefill compression，报告 transient memory、TTFT、可运行长度和质量。

Editorial Assessment

Why It Matters

Abstract

Original Abstract Summary

PlaneZip chooses among several lightweight bit-plane encodings for each 128-byte activation block before swapping it over PCIe. The design targets low-latency hardware compression rather than high-ratio general compression.

中文摘要

PlaneZip 利用 activation 的局部数值结构，为每个小块选择成本最低的表示，目标是减少 offload 带宽而不让压缩延迟抵消收益。

Technical Analysis

Problem

activation offload 受 PCIe 限制；固定压缩格式不能同时适配零稀疏、数值平滑和不同精度。

Method

每 128B block 在四种表示中硬件选择，结合 swapping policy 与带宽模型评估端到端开销。

Architecture

训练 runtime 识别可换出 activation；PlaneZip engine 在线编码并经 PCIe 传输；恢复时解码回 GPU。

Key Innovation

压缩选择粒度细、硬件面积小，专门匹配 activation 数据分布和 offload 时延预算。

Experiments

压缩比来自真实 activation；系统收益主要来自 trace-driven simulation，分别模拟 PCIe3 消费级与 PCIe4 数据中心环境、半显存预算。

Editorial Assessment

Why It Matters

对长上下文和大 batch 训练，offload 可把 OOM 转成带宽问题；专用轻量压缩有机会扩大可训练规模。

Limitations

系统结果主要是模拟而非真实硬件端到端训练；0.036 mm² 为估计。对 PCIe5/NVLink/CXL 与新低精度格式的收益未证明。

Editor Note

87/A+。硬件/系统协同新颖且数字完整；模拟主导和缺少公开实现限制证据等级。
