Abstract

Original Abstract Summary

LoRazor observes that LoRA adapters have request- and phase-dependent utility. It trims adapter computation during decoding and provides GPU kernels that operate only on active rows, enabling higher multi-adapter throughput with bounded quality loss.

中文摘要

LoRazor 将 LoRA serving 的适配器使用视为动态资源：StepTrim 在 decode 中提前释放适配器，GridTrim/RowTrim 让 kernel 只计算活跃行，并用 CUDA Graph bucket 固化常见形状。

Technical Analysis

Problem

现有 multi-LoRA runtime 长时间保留并重复计算适配器，即使其在生成后段的边际贡献很低；并发请求的活跃行不规则又让通用 GEMM 浪费工作。

Method

联合 StepTrim、GridTrim 与 RowTrim；按请求阶段和活跃行选择适配器工作量，并在 vLLM 调度与 CUDA Graph 中集成。

Architecture

vLLM 多 LoRA 路径 + 动态 adapter 生命周期管理 + active-row-aware CUDA kernels + shape-bucketed CUDA Graphs。

Key Innovation

把 LoRA 适配器从静态模型组件变成可调度、可回收的请求级资源，同时为稀疏活跃行设计专用 kernel。

Experiments

Llama-3.2-3B 与 Mistral-7B，四项任务；对照 vLLM multi-LoRA。硬件型号未在已核实材料中完整披露。

Editorial Assessment

Why It Matters

Multi-LoRA 已成为个性化 serving 的高密度场景；动态裁剪直接连接模型质量预算、显存和调度器。

Limitations

硬件与完整并发分布未充分披露；质量—吞吐阈值依任务而变，仍需生产流量验证。

Editor Note

证据覆盖模型、任务与端到端吞吐，且有 vLLM 实现；但复现与部署细节仍不完整。

Abstract

Original Abstract Summary

CoMixKV estimates the sensitivity of each agent-layer pair from attention error and allocates mixed KV precision under a shared memory budget, aiming to preserve task accuracy while reducing memory and batch completion time.

中文摘要

系统在线估计每个 agent–layer 对量化误差的敏感度，在共享显存预算下分配不同位宽；其重点不是单模型统一压缩，而是多 agent 阶段之间的协同配置。

Technical Analysis

Problem

多 agent 工作流同时持有长上下文 KV；统一位宽忽略角色与层间敏感度，容易在关键阶段损伤质量或浪费显存。

Method

以 attention error 构造在线敏感度，联合求解 agent-layer 位宽分配，并在运行时应用混合精度 KV。

Architecture

Manager–Analyst–Verifier 三阶段 agent pipeline；共享 GPU 上的 per-agent/per-layer KV precision manager。

Key Innovation

首次把 agent 角色和 Transformer 层级纳入同一 KV 量化预算，而非只做 token 或 layer 级压缩。

Experiments

Qwen3-32B，单 NVIDIA H20 96GB；5 个并发样本，每个 32,768 输入 + 2,048 输出。另有 Gemma-4-31B-it 质量实验。

Editorial Assessment

Why It Matters

Agentic/stateful serving 的瓶颈正从单次解码扩展到跨角色状态总量；联合预算比独立压缩更贴近真实工作流。

Limitations

固定三角色拓扑、单卡与有限并发；端到端收益包含具体调度/负载效应，不能外推到任意 agent 图。

Editor Note

实验条件和绝对数值清楚，但代码与跨硬件复现未披露，评为 A。

Related Work

Abstract

Original Abstract Summary

PACE combines planner-aware retention with bounded positional renumbering. It keeps states that future plan steps are expected to reuse and compresses position growth, preserving long-horizon agent behavior under a fixed KV budget.

中文摘要

PACE 不把所有旧 token 等价处理，而是由规划器标记未来步骤需要的状态；驱逐后再用有界位置重编号控制 RoPE 漂移，从而同时处理“保留什么”和“剩余 token 放在哪里”。

Technical Analysis

Problem

通用 KV eviction 只看注意力或新近性，无法识别工具代理未来计划中的关键状态；超长位置还会放大 RoPE 外推误差。

Method

planner-aware retention + bounded position renumbering；前者给未来依赖加权，后者压缩位置但保持次序与边界。

Architecture

Agent planner 产生依赖标签；KV manager 按固定预算保留状态；RoPE remapper 为剩余 token 分配有界位置。

Key Innovation

把显式规划依赖引入 KV 驱逐，并与位置系统共设计，而非只优化 cache 命中率。

Experiments

Qwen3-8B、Mistral-7B；单 NVIDIA L4 24GB + 128GiB host；100K/1M/2M token 合成编码会话，固定 2,048-token KV，比较 H2O、SnapKV。

Editorial Assessment

Why It Matters

它表明 stateful agent serving 的缓存策略需要理解任务结构，而非仅从注意力统计推断重要性。

Limitations

合成编码会话、7–8B 模型、单 GPU、主要使用 oracle planner、无并发实验且样本量有限。

Editor Note

结果强且消融清晰，但 oracle planner 与合成会话使生产外推仍需谨慎。

Related Work

01

02

SnapKV：共同点是压缩 KV；PACE 面向跨步骤 agent 状态。

03

StreamingLLM：共同点是固定窗口；PACE 保留语义依赖并重编号位置。

04

Abstract

Original Abstract Summary

The work replaces atomic Split-K accumulation with a deterministic reduction order in a Triton LoRA kernel for vLLM. It measures both numerical variation and downstream generation instability, then quantifies the performance cost.

中文摘要

论文将 LoRA kernel 的跨 K 分片结果写入中间缓冲，再按固定顺序归约，避免原子加法因执行顺序变化产生浮点差异。

Technical Analysis

Problem

原子 Split-K 高效但归约顺序不稳定，微小 FP32 差异会在自回归生成和结构化概率输出中放大。

Method

Split-K=8；第一阶段独立计算分片，第二阶段确定性归约；Triton 实现并接入 vLLM。

Architecture

vLLM multi-LoRA path → deterministic Triton partial GEMM → fixed-order reduction → output。

Key Innovation

把可复现性从随机种子提升为 kernel 归约协议，并量化微小数值差异对生成的实际影响。

Experiments

GSM8K、MBPP 与结构化概率任务；比较 unsplit、atomic Split-K=8 与 deterministic Split-K=8。硬件型号未核实。

Editorial Assessment

Why It Matters

金融、评测和 RL rollout 都要求可审计复现；该工作揭示 serving kernel 可直接改变上层结果。

Limitations

单一 Split-K 配置和 LoRA 路径；未披露跨 GPU、不同 Triton/driver 版本的可移植性。

Editor Note

问题具体、测量严谨、代价低；范围较窄，因此为 A。

Abstract

Original Abstract Summary

Detent treats kernel selection as a program and identifies the smallest set of batch-dependent values that must be fixed. It then tunes around those constraints to deliver batch-invariant serving and RL rollouts with near-stock performance.

中文摘要

Detent 不强制所有路径使用最慢确定性 kernel，而是分析引擎选择逻辑，只约束真正传播批次差异的值，再对工作负载调优。

Technical Analysis

Problem

动态 batching、cache split 和 kernel heuristic 会改变浮点计算路径，导致 serving 结果与 RL rollout/trainer logprob 不一致。

Method

程序化表示 kernel selection；最小依赖分析；固定关键选择值；按 workload autotune。

Architecture

适配 vLLM 与 SGLang 的 engine policy layer，覆盖 attention/GEMM 等选择点，并与 trainer logprob 对齐。

Key Innovation

将 batch invariance 表述为最小程序约束问题，而非全局关闭优化。

Experiments

多 GPU Llama-3.1-70B、Qwen3-30B-A3B；vLLM、SGLang；RL rollout 与 BF16 GRPO。精确硬件未在已核实材料中披露。

Editorial Assessment

Why It Matters

它把可复现性从离线调试要求变成 serving/RL 的系统契约，直接影响 reward、优势估计和训练稳定性。

Limitations

完整代码状态与硬件细节未核实；“Stock 崩溃”依赖特定 BF16 GRPO 配置，不能泛化到所有训练。

Editor Note

覆盖两大引擎和 RL 闭环，性能—确定性权衡突出；因部分一手细节未能完整核实，低于 S+。

Abstract

Original Abstract Summary

CVSA defines coverage as the softmax probability mass captured by the selected keys and proves its direct relation to per-step attention error. A verify-then-correct path recomputes only heads whose coverage is insufficient.

中文摘要

系统先执行稀疏选择并估计覆盖率；高覆盖 head 直接接受，低覆盖 head 才触发校正，从而把“猜测稀疏模式”变成带证书的自适应计算。

Technical Analysis

Problem

现有稀疏 attention 通常依赖启发式 top-k 或固定模式，缺少逐步质量保证，长上下文异常输入可能悄然失真。

Method

coverage 指标 + 误差等式 + per-head verify-then-correct。

Architecture

Sparse selector → coverage verifier → selective dense correction；按 head 自适应。

Key Innovation

用精确概率质量连接选择覆盖与 attention 输出误差，并把验证结果直接控制运行时回退。

Experiments

7B/70B 模型；LongBench、RULER；最长 128K decode。硬件型号未核实。

Editorial Assessment

Why It Matters

它为稀疏 attention 引入质量闭环，比固定稀疏率更适合 SLO 与可靠性要求并存的服务。

Limitations

硬件、代码与端到端 server throughput 未完整核实；中位 decode-step 加速不等于请求级加速。

Editor Note

理论证书和长上下文结果强，但工程复现信息不足。

Abstract

Original Abstract Summary

FRESCO constrains parameter updates so that they are orthogonal to a compact spectral basis of in-flight activations. This preserves the forward outputs seen by outstanding microbatches while allowing asynchronous pipeline updates.

中文摘要

FRESCO 保存未完成 microbatch 激活的低秩谱基，并将更新投影到其正交补；因此参数可前进，但旧激活对应的前向映射尽量不变。

Technical Analysis

Problem

深流水线和异步更新提高利用率，却让 forward 使用的参数与 backward/update 时不一致，造成收敛变慢。

Method

forward-equivalence constraint；compact spectral activation basis；gradient/update projection。

Architecture

pipeline stage 本地维护 in-flight activation 子空间，优化器前执行正交投影；无需完整参数快照。

Key Innovation

从保持前向映射不变而非预测未来权重出发校正 staleness，并用谱压缩控制内存。

Experiments

95M 语言模型；3 nodes×8 RTX3090（另有 A6000），每次 8 GPU，gloo；pipeline depth 1–32，虚拟深度 >8。

Editorial Assessment

Why It Matters

为异步流水线提供可解释的稳定性约束，可能减少深 pipeline 为吞吐付出的优化代价。

Limitations

主要为 95M 模型且主实验单 seed；多机互连较弱，尚未证明在超大模型/高速网络上的净收益。

Editor Note

方法漂亮、内存证据强，但规模与统计重复有限。

Abstract

Original Abstract Summary

OOM redesigns full-parameter MoE training around expert ownership, retained activations, local split-keep-replay execution, and calibrated cost models. It seeks to extend context and model scale on memory-constrained GPU systems without excessive host traffic.

中文摘要

系统不把 MoE 专家当作普通 dense 参数统一 offload，而是建立专家所有权、保留必要激活，并在本地拆分、保留或重放计算；成本模型按硬件与 workload 选择路径。

Technical Analysis

Problem

FSDP/ZeRO 式通用 offload 在 MoE 中产生重复参数/激活迁移，长上下文和大 expert 集合同时压垮 GPU 与 host memory。

Method

EP ownership、activation retention、local split–keep–replay、calibrated cost model。

Architecture

expert-parallel owner GPUs + CPU offload store + per-layer execution planner；按专家与激活生命周期安排迁移。

Key Innovation

把 offload 粒度与 MoE 路由/专家所有权对齐，并联合建模显存、主存、计算和 PCIe 代价。

Experiments

4×H100 与 4×24GB RTX4090；长上下文、122B MoE 与大 batch；对比 CPU-offloaded FSDP2、ZeRO-Offload、MegaTrain。

Editorial Assessment

Why It Matters

它直面全参数 MoE 训练的双重内存墙，并覆盖数据中心与消费级 GPU。

Limitations

仅 4 GPU 规模，跨节点网络与更大 EP domain 未验证；收益依 PCIe/CPU memory 和模型路由。
