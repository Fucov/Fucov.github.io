Abstract

Original Abstract Summary
The work treats synchronous dispatch and combine traffic as the main scaling limit for expert parallelism. EchoMoE references an earlier residual-stream state, communicates compressed deltas, periodically refreshes the reference, and adapts pretrained MoE models with far fewer tokens than original pretraining. The authors report lower communication and higher serving throughput with bounded task-quality loss.
中文摘要
该工作把 MoE 每层 All-to-All 中的 activation 视为“上一参考状态 + 小变化”，分别压缩 dispatch 与 combine 路径，并通过少量继续训练把模块接入现有 MoE。它的价值在于将通信压缩、模型适配和 vLLM/DeepEP 服务集成放进同一实验闭环。

Technical Analysis

Problem
大规模 EP 的两次同步 collective 受跨节点 RDMA 带宽限制，且即使通过 microbatch overlap 仍会落在关键路径。
Method
选择较早层激活为 reference，对当前激活与 reference 的差分做低维编码；以 stride 周期刷新 reference，并分别训练 dispatch/combine 编解码器。
Architecture
Transformer residual stream → reference selection/folding → compressed dispatch → expert compute → compressed combine → residual reconstruction。预训练 MoE 通过 4.32B-token adaptation 获得压缩路径；推理侧集成 vLLM 0.29.0 与 DeepEP，EP32/DP32/TP1。
Key Innovation
通信对象从“当前 hidden state”改为“跨层可预测残差”，让架构的层间相似性直接转换为网络流量削减。
Experiments
4 个 DGX H100 节点、每节点 8×H100 SXM5 80GB 与 8×400Gb/s ConnectX-7；主模型 Qwen3-30B-A3B，并覆盖 Gemma 4、Kanana-2、Nemotron-3.5-Lightning、Moonlight。18 个任务；单 seed。在线 serving 使用 5,017 个 held-out prompts、Poisson 到达率 16–512 req/s。

Key Results

来源报告：跨节点通信量降低 58%，总体 throughput 提升 22.6%；在受限 Ethernet 条件下最高 2.38×。不同压缩配置的质量损失不同，论文给出的“保持在 3.8 个百分点内”不是无损保证。4.32B-token adaptation 平均约 252 H100 GPU-hours。

Editorial Assessment

Why It Matters
它提供了“少量适配换持续通信收益”的现实路径，适用于已有 MoE checkpoint，而不是要求重新预训练。
Limitations
强结果主要来自固定 H100/ConnectX-7、EP32 配置；质量—压缩取舍依配置变化，单 seed 任务评估限制统计置信度。
Editor Note
我的判断：这是当日最完整的系统工作，因为模型改造、网络流量、硬件实测与公开实现相互闭环；“2.38×”只适用于带宽受限 Ethernet 实验。

Related Work

01 · DeepEP共同点：优化 EP dispatch/combine。区别：DeepEP 优化 transport/kernel；EchoMoE 改变要传的数据本身。新增量：跨层差分压缩。
02 · DeepSpeed-MoE共同点：多节点专家并行。区别：前者侧重并行/collective 组织；本工作通过模型适配降低字节数。新增量：可追踪的质量—流量曲线。
03 · LSH-MoE共同点：利用 activation 冗余。区别：EchoMoE 显式参考残差并同时处理 dispatch/combine。新增量：vLLM 在线服务与慢网络实验。

Authors
Yijun Sun, Xudong Liao, Zhuobin Huang, Kai Chen, Nikita Lazarev, Zhizhen Zhong
Institutions / Labs
Netpreme; HKUST; National University of Singapore
Publish Date
v1 submitted 2026-11-17 06:32:15 UTC；首次公共列表 2026-11-18
Venue
arXiv preprint · cs.DC / cs.LG；官方博客已于 2026-11-04 发布

Abstract

Original Abstract Summary
XM-Sparse studies sparse-attention serving over scale-up memory pools and identifies HBM-resident hot KV buffers plus the K-index cache as remaining concurrency limits. It offloads both with access-specific I/O: tile-pipelined retrieval fused into attention for dynamically selected KV, and coordinated GPU-initiated DMA prefetch for predictable K-index pages.
中文摘要
论文指出“有了高速扩展内存”并不会自动解决 sparse attention 服务：热 KV 和 indexer key 仍占据 HBM。系统将两类状态都下沉，但不使用同一 I/O 机制，从而在带宽、时延与 HBM 容量之间形成分工。

Technical Analysis

Problem
PCIe host offload 带宽/容量不足；即使换成 scale-up pool，热 KV buffer 与全驻留 K-index 仍限制 batch/concurrency。
Method
动态 KV 由 TMA retrieval 与 attention 做 tile-level pipeline；K-index 页以 GPU producer 生成 DMA 命令并优先级协调预取，避开 attention 与 MoE collectives。
Architecture
SGLang/HiSparse cache manager → hot-KV miss list → fused FlashMLA retrieval-attention；K-index access stream → GPU command producer → copy engine → HBM staging。数据路径与控制路径分离，CPU 只按 batch 发布命令。
Key Innovation
不是把统一 offload 后端换成更快链路，而是按 cache access pattern 分解 I/O：不可预测选择走 on-demand fusion，可预测层序走 ahead-of-time prefetch。
Experiments
2×Intel Xeon 6767P、2TB DRAM、8×B300 268GiB；4 GPU decode、4 GPU 作为 X-Mem memory nodes。DeepSeek-V3.2 671B 与 GLM-5.3 744B，FP8、DP4 attention、EP4 MoE；16K–1M LongBench v2，输出 128 tokens。容量超过物理 1TB 的部分通过重复映射模拟。

Key Results

来源报告：相对 PCIe ECHO，decode throughput 最高 4.98×；相对 HiSparse 最高 4.52×；在相同 X-Mem 后端上相对 naive integration 为 1.06–1.34×。在 GLM-5.3、128K context，batch/GPU 109→209、吞吐 1437.9→1849.3 tok/s/GPU。以上最大值来自不同模型/上下文条件，不能拼成统一加速。

Editorial Assessment

Why It Matters
长上下文稀疏注意力正在让 KV 与 indexer state 共同成为 memory hierarchy 对象；这为 CXL/NVLink memory pool 时代的 serving 提供了具体执行模板。
Limitations
依赖专有/新型 X-Mem 环境；超物理容量、固定 miss rate 与 round-robin expert routing 包含模拟；完整 XM-Sparse 核心代码未核实公开。
Editor Note
重收原因：11 月 4 日已有官方博客，11 月 18 日首次公开完整技术论文，新增了架构、8K LOC 实现描述、测试床与消融证据。

Related Work

01 · HiSparse共同点：SGLang 稀疏注意力 KV offload。区别：HiSparse 以主机 backing 为主；XM-Sparse 同时 offload K-index 并针对 scale-up fabric 做双路径 I/O。新增量：同平台 naive integration 消融。
02 · ECHO共同点：热 KV + 冷层存储。区别：ECHO 受 PCIe host 路径限制；XM-Sparse 使用扩展内存与 attention fusion。新增量：16K–1M 条件下的容量—吞吐实测。
03 · LMCache共同点：分层 KV 管理。区别：LMCache 更通用地跨 GPU/CPU/存储复用 KV；XM-Sparse 针对 sparse-attention 的动态 KV 与 K-index 分别定制。新增量：GPU-initiated DMA 与 traffic priority。

Abstract

Original Abstract Summary
The paper profiles masked diffusion MoE decoding and shows that repeated full-canvas logits post-processing can dominate after the expert backbone is quantized. It removes redundant entropy passes in a bit-exact tier and fuses entropy plus Gumbel-max sampling in an accuracy-parity tier, reporting end-to-end gains on a low-bandwidth edge accelerator.
中文摘要
自回归模型每个 token 只处理一个 logits 向量，而扩散语言模型在每个 denoising step 都处理整张 canvas。量化让 MoE backbone 变快后，这个长期被忽略的采样器反而成为最大耗时；工作通过减少全张量遍历和融合 kernel 重塑瓶颈。

Technical Analysis

Problem
diffusion decode 每个输出 token 约触碰 S 倍 logits entries；多次 temperature/softmax/entropy/sampling pass 在低带宽设备上放大。
Method
Tier 1 消除重复 entropy，保持 byte-identical；Tier 2 以单 pass entropy kernel + Gumbel-max 融合采样，在 benchmark accuracy 上保持一致。
Architecture
DiffusionGemma-26B-A4B（128 experts、top-8、30 layers、hidden 2816）→ W4A16 expert kernel → fused full-canvas sampler/stopper。对第二个 LLaDA2.0-mini MoE 复现瓶颈，对 dense diffusion 做反例。
Key Innovation
量化后重新 profile 整条 decode pipeline，发现优化 backbone 会把瓶颈转移到模型外的 logits control path。
Experiments
单 NVIDIA GB10 / DGX Spark，273GB/s unified LPDDR、119GB、batch=1、canvas=256、vocab=262,144；GSM8K、HumanEval、MATH；另测 LLaDA2.0-mini 与 dense diffusion。

Key Results

来源报告：W4A16 expert kernel 与采样器优化组合后相对 BF16 端到端 2.4–2.7×；LLaDA2.0-mini 中 pipeline 占 28.8%，融合 W4A16 路径 3.3×（accuracy parity）。dense diffusion 上该开销仅 3.6%，说明结论不能外推到所有 diffusion LLM。

Editorial Assessment

Why It Matters
这是一个典型“优化改变瓶颈”的系统结果：quantized MoE 越快，sampling control path 越不能被当作免费。
Limitations
核心数据来自单用户、batch 1、GB10 的低带宽边缘环境；代码与量化权重虽被论文声明发布，但固定一手 URL 未核实。
Editor Note
我的判断：机制洞见很强，但适用域窄于标题直觉；评分不进入 S 级，原因是硬件/负载覆盖有限且代码入口未核实。

Related Work

01 · LLaDA / masked diffusion decoding共同点：迭代 denoising。区别：既有工作强调并行生成；本工作剖析 logits 后处理。新增量：O(S) per-token asymmetry 的硬件实测。
02 · FlashInfer sampling kernels共同点：融合 logits processing。区别：常见 kernel 针对 autoregressive batch/token 形态；这里针对 canvas×vocab。新增量：bit-exact tier。
03 · MoE W4A16 kernels共同点：降低 expert compute/memory。区别：本工作说明 kernel 加速后系统瓶颈转移。新增量：第二 MoE 与 dense 反例。

Abstract

Original Abstract Summary
The study quantizes only the draft model’s KV cache while preserving the target cache and correction rule in BF16. It shows that apparent key sensitivity changes when key grouping changes, proposes K4V4 with per-channel keys and per-token values, and reports large draft-cache byte savings with a small average acceptance reduction across six model pairs.
中文摘要
标准推测解码同时保留 target 与 draft 两套 KV。该工作压缩 draft KV，并通过对照说明 K8V4 相对 K4V8 的优势可能是 quantizer layout 造成的。K4V4 方案显著缩小 draft cache，但尚未证明生产吞吐或峰值显存收益。

Technical Analysis

Problem
双模型 speculative decoding 的第二套 KV cache 限制长上下文与 batch capacity。
Method
key 使用 32-token grouped per-channel affine quantization，value 使用 per-token affine quantization，最近 128 key tokens 保留 BF16；target cache/verify 不变。
Architecture
BF16 target cache + bit-packed K4V4 draft cache + BF16 recent-key window；proposal 由量化 draft 生成，target 仍执行 correction rule。论文同时区分 sequential 与 batched verifier，后者存在未解释 mismatch。
Key Innovation
用 controlled intervention 将 bit allocation 与 quantizer geometry 解耦，纠正“key 总应分配更多 bits”的简单经验法则。
Experiments
六组 Qwen2.5/Qwen3/Llama/OLMo/SmolLM target-draft pairs；1K–32K context。1–2×RTX A5000 24GiB，229.45 GPU-hours；实现、SLURM、测试与输出 schema 公开。

Key Results

来源报告：K4V4 平均减少 draft cache 66.20%，target+draft 合计 23.95%；mean acceptance 57.93%→57.14%。Qwen2.5-1.5B 在 32K context 的 packed cache 为 260.2MiB，对比 BF16 896.0MiB。作者同时报告 prototype 比 BF16 speculative decoding 慢 18–33%，且未降低峰值显存。

Editorial Assessment

Why It Matters
它把 KV quantization 的“位宽选择”提升为 layout 与 outlier geometry 的共同设计问题，并提供完整负结果披露。
Limitations
不主张更快 kernel、更低峰值显存或生产吞吐；packed prototype 的 batched verifier 有未解释 mismatch，长上下文样本较少。
Editor Note
内存容量结果可信度高于端到端系统收益。我的判断是“强实验方法、未完成 serving 落地”，因此为 A 而非 S。

Related Work

01 · KIVI共同点：per-channel key / per-token value。区别：KIVI 量化主 KV；本工作只压缩 speculative draft cache。新增量：acceptance 与双 cache 总内存分析。
02 · EAGLE共同点：draft-target speculative decoding。区别：EAGLE 优化 draft representation/acceptance；本工作优化 draft state storage。新增量：不改变 target correction rule。
03 · Quantize What Counts共同点：讨论 K/V 精度分配。区别：其结论偏向 key 高精度；本工作证明结论随 quantizer geometry 反转。新增量：controlled key-only intervention。

Abstract

Original Abstract Summary
TailRoll attributes RL rollout waste to both cross-engine imbalance and step-critical stragglers. It migrates in-flight requests at chunk boundaries by replaying their prompt and generated tokens on a freer engine, and terminates a response when enough siblings in its GRPO group have completed, masking the partial trajectory from training loss.
中文摘要
异步训练可以隐藏部分 rollout 延迟，却不能消除 rollout 池内部的空闲。TailRoll 在不修改推理引擎/训练器的前提下观察 engine freeness、迁移仍有收益的请求，并在组内样本已足够时停止尾部响应，从“放在哪”扩展到“还需不需要生成完”。

Technical Analysis

Problem
长 CoT / agent 响应呈重尾分布；平均负载均衡无法消除最长序列决定 step makespan 的问题。
Method
控制面持续 observe–decide–execute：freeness 检测、tail-aware source-target pairing、prefill 成本门限、reservation/hop limit；终止器使用 k_min 完成兄弟样本作为充分条件。
Architecture
AReaL controller → vLLM rollout engines（请求迁移只传 prompt+generated tokens，目标端一次 re-prefill）→ GRPO group tracker → partial-output loss masking → FSDP trainer。无需共享 KV pool，但迁移付出重算 prefix 的成本。
Key Innovation
将请求级 live migration 与训练语义（GRPO group sufficiency）组合在一个 scheduler 中，分别处理 imbalance waste 与 straggler waste。
Experiments
2 个 Ascend 节点、每节点 16×910C 64GB；默认 8 NPU rollout（4 个 TP2 vLLM engines）+8 NPU FSDP training。Qwen3-14B/32B BF16，B=128×n=4，max_new_tokens=3072；多模态 trace、CodeAgent、multitask、AMC12；含 300-step reward run。

Key Results

来源报告：10 组配置中 rollout bubble 降低 21–74%，跨 engine KV imbalance 降低 44–79%；end-to-end RL 中 rollout time 降低 24–34%，long-CoT full step 降低 21–22%；p95 request latency 降低 28–37%，throughput 最高 +33%。奖励可比/更高的结论来自特定 300-step runs，不等于任意任务都可安全早停。

Editorial Assessment

Why It Matters
rollout scheduler 不再只看 engine queue，而开始利用训练算法的“样本充分性”语义；这是系统与优化目标协同的代表。
Limitations
主要运行在 Ascend 910C 与 AReaL/vLLM 路径；迁移需要 re-prefill，长上下文可能失去收益；部分比较存在 engine skew，完整矩阵缺少多 seed。
Editor Note
我的判断：结果证明 async 并不自动等于高利用率。值得关注的新增量不是迁移本身，而是“critical path + group sufficiency”决定是否继续生成。

Related Work

01 · Llumnix共同点：decode 中迁移请求。区别：Llumnix 迁移 KV blocks；TailRoll 只传 tokens 并 re-prefill。新增量：RL step critical-path 与 termination。
02 · Seer共同点：跨实例动态调度。区别：Seer 使用 shared KV/chunk migration；TailRoll 无共享存储并以 freeness+cost gate 驱动。新增量：AReaL 集成。
03 · verl partial rollout / Kimi k1.5共同点：不必让所有 trajectory 同步完成。区别：既有方案推迟/截断样本；TailRoll 以组内完成数和系统关键路径共同触发。新增量：partial output loss masking 与 live migration 组合。
04 · TIDE共同点：回收 RL rollout 侧闲置资源。区别：TIDE 在 rollout/training 角色间切换 GPU；TailRoll 在 rollout engines 之间搬请求并停止低价值尾部。新增量：请求级尾部控制。
