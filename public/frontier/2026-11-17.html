Abstract

Original Abstract Summary

NVFP4-MLA is a unified FP4 design for Multi-head Latent Attention that compresses the KV cache and executes attention in FP4. It combines residual protection for sensitive channels with two-dimensional block scaling, and evaluates accuracy, kernel throughput, and disaggregated serving.

Faithful English summary of the primary source; not a verbatim abstract.

中文摘要

该工作不是单独压缩 KV，也不是只替换 attention GEMM，而是把 MLA 的缓存格式、在线反量化与低精度计算联合设计；敏感通道保留残差，二维块缩放降低共享 scale 的误差。

Technical Analysis

Problem

长上下文 MLA 服务同时受 KV 容量、读带宽和 attention 计算约束。仅压缩缓存会在计算时重新放大，单独 FP4 计算又无法释放缓存容量。

Method

以 NVFP4 表示潜变量 KV；对误差敏感通道保留高精度残差；沿特征和 token 维组织二维量化块，使 scale 与访问/计算布局对齐。

Architecture

请求 prefill 生成 MLA latent KV → NVFP4 payload + block scales + sensitive-channel residual → 分层/远端 KV 存储 → Rubin FP4 attention kernel直接消费 → decode 输出。

Key Innovation

将缓存精度与 attention 内核精度作为同一个系统合同优化，而非两个独立量化阶段。

Experiments

DeepSeek-R1 与 Kimi-K3；KV 容量、Rubin kernel 和 disaggregated serving 三组实验。论文分别报告缓存压缩、内核加速、p90 TTFT 与吞吐，适用基线和工作负载不同。

Editorial Assessment

Why It Matters

FP4 若能同时覆盖缓存与计算，就可把容量、带宽和算力收益传导到服务 SLO，而非只形成离线微基准。

Limitations

主要依赖 Rubin/NVFP4 硬件路径；公开代码状态未核实。论文公开摘要未给出所有服务拓扑与请求分布细节，跨模型泛化仍待复现。

Editor Note

S+。问题、硬件路径与服务指标闭环完整；分数受代码未核实和新硬件复现门槛小幅扣减。

Abstract

Original Abstract Summary

Stint addresses KV thrashing in long-output reasoning workloads. It periodically snapshots fixed-length KV extents to a CPU pool, overlaps transfers with execution, predicts remaining length, and uses age-aware readmission and protection so preempted requests make durable progress.

Faithful English summary of the primary source; not a verbatim abstract.

中文摘要

长推理请求可能在显存压力下反复被驱逐、重算、再驱逐。Stint 把部分 KV 状态变成可恢复的进度检查点，并把何时恢复、何时保护与剩余长度预测联合到调度器中。

Technical Analysis

Problem

现有系统在内存饱和时允许同一请求多次丢失 KV；长输出请求因此可能数十秒无进展，尾延迟和公平性恶化。

Method

固定长度快照写入 CPU extent pool；fused K/V gather-scatter 与 double buffering 隐藏拷贝；remaining-length predictor 辅助容量决策；age-based readmission/protection 避免刚恢复即再次被抢占。

Architecture

GPU KV allocator → fixed-extent snapshot → pinned CPU pool → readmission queue → double-buffer restore → protected execution window；调度器同时维护年龄与剩余长度估计。

Key Innovation

把抢占从“丢弃状态后重算”改成“具有持久进度的阶段性执行”，并将恢复成本作为一等调度对象。

Experiments

Qwen3-32B、NVIDIA H200；olympiad-math 长输出 replay。对照为现有抢占路径；报告停顿时间、p99 TPOT、完成时间和吞吐。

Editorial Assessment

Why It Matters

长推理与 agentic serving 的会话状态越来越大，抢占不可避免；能否保存“已获得的进展”决定了调度器是否具备真正的 SLO 隔离。

Limitations

单一模型、GPU 类别和 replay；CPU 带宽与 NUMA 拓扑在更大规模下可能成为瓶颈。预测误差和极端突发负载的稳定性仍需外部复现；代码未核实。

Editor Note

S+。提出明确的新故障模式并给出端到端尾延迟证据；复现性因代码状态不明而扣分。

Abstract

Original Abstract Summary

This merged SGLang change accelerates the DeepSeek-V4.1 prefill indexer on Hopper with an FP8 DeepGEMM MQA-logits path, device-side candidate publication, and a numerically exact FP4-to-FP8 widening condition under a bounded binade spread.

Faithful English summary of the primary source; not a verbatim abstract.

中文摘要

该改动把 indexer 中逐请求 torch 控制流与 host sync 改为设备端批处理；对满足动态范围条件的 FP4 数据安全扩宽到 FP8，从而复用更高效的 Hopper kernel。

Technical Analysis

Problem

超长 prefill 的 indexer 在每层重复计算 logits、top-k 和候选发布；主机同步及非专用矩阵路径成为 DeepSeek-V4.1 的关键延迟。

Method

接入 DeepGEMM FP8 MQA logits；候选选择和发布留在设备；当 14-binade spread 条件满足时进行精确 FP4→FP8 widening；保留回退路径。

Architecture

Prefill hidden/QK states → FP8 MQA logits kernel → device top-k/candidate publish → indexer continuation；CPU 不再逐请求读取中间状态。

Key Innovation

把数值格式可安全扩宽的证明条件与设备端控制流结合，既降低 host orchestration，又保持可验证的精度边界。

Experiments

8×H200、DeepSeek-V4.1-Flash；32K×4 与 128K prefill；单层 128K indexer 微基准；GSM8K 与 RULER2 准确性。

Editorial Assessment

Why It Matters

在百万 token 模型中，辅助 indexer 也可成为端到端 prefill 瓶颈；减少主机同步与格式转换是系统性收益。

Limitations

仅 H200；DSpark 接受长度影响未核实。部分路径依赖 DeepGEMM 与特定模型实现，不能外推到通用 attention。

Editor Note

S。端到端、微核和准确性证据齐全；硬件与模型范围较窄。

Abstract

Original Abstract Summary

This SGLang change fuses Q/K normalization and rotary-position embedding for Qwen3 on ROCm, reducing five launches to one. It reports kernel, TTFT, throughput, and TPOT results on MI355X while separating the default AITER configuration from the non-AITER path.

Faithful English summary of the primary source; not a verbatim abstract.

中文摘要

融合核减少中间张量读写与 launch 固定成本；报告同时给出默认 AITER prefill 路径和未启用 AITER 时 decode 也被融合的结果，二者不可混为同一部署收益。

Technical Analysis

Problem

QK-norm 与 RoPE 的多个小 kernel 在 ROCm 上产生高 launch 与显存往返开销，尤其影响短到中等 prefill。

Method

在单个 kernel 内完成 Q/K norm、旋转位置编码和写回；根据 prefill/decode 及 AITER 是否接管后续路径选择性启用。

Architecture

Q/K projections → fused norm+RoPE kernel → attention；原先 norm、scale、sin/cos mixing 与写回的 5 个 launch 被折叠。

Key Innovation

将模型特定的归一化与位置编码边界融合，并用配置分层实验避免把非默认路径收益包装成默认收益。

Experiments

AMD MI355X；Qwen3-8B 与 Qwen3-32B TP8；AITER 默认开关分别测试。指标包括 kernel time、TTFT、input throughput 和 TPOT。

Editorial Assessment

Why It Matters

ROCm 服务性能常被小 kernel 和 launch 密度拖累；可审计的融合边界与配置条件比单一最大加速更有工程价值。

Limitations

限 Qwen3/ROCm；默认 AITER 下吞吐提升较小。非 AITER 的 decode 收益不可直接外推到生产默认配置。

Editor Note

S。实验条件与反事实配置披露非常清晰，工程影响可靠。

Abstract

Original Abstract Summary

This vLLM merge routes causal DSpark draft blocks for Kimi-K3 through CAKE under tensor- and decode-expert parallelism, with CUDA Graph replay and FP8 query/KV support. The PR provides kernel timings over long-context batches but not end-to-end acceptance or serving throughput.

该改动瞄准 speculative draft 阶段的因果 attention；不同头数、并行方式与上下文混合下收益差异明显，因此报告保留形状级结果，不把非因果 fold 的最大倍数当成端到端推测解码收益。

Technical Analysis

Problem

Kimi-K3 长上下文 DSpark draft block 的 attention 成本可能接近 main block，削弱推测解码净收益。

Method

在 causal draft 路径选择 CAKE kernel；支持 TP/DEP、CUDA Graph 和 FP8 Q/KV；按 batch/head/context 形状验证。

Architecture

Main model state → DSpark draft block → CAKE causal attention → draft tokens → verifier；执行可被 CUDA Graph 捕获。

Key Innovation

把 CAKE 从一般 attention 适配到 Kimi-K3 专用 draft block 与并行布局，直接优化 speculative decoding 的“额外计算”。

Experiments

GB300；单 draft layer；uniform 100K 与 40K–250K/600K mixed context；batch 1–128；TP4、TP8、DEP；另测 noncausal fold。

Editorial Assessment

Why It Matters

推测解码是否划算取决于 draft 开销与接受率的联合；本作缩减专用 draft block 的 attention 成本，并诚实暴露退化形状。

Limitations

未披露端到端 serving、接受率或最终吞吐；部分形状回退，TP8 无收益。只适用于 Kimi-K3/DSpark/GB300 路径。

A+。代码与形状证据充分，但缺少最终 speculative-decoding 闭环指标。

Abstract

The report describes a comprehensive MoE training stack in Olmo-core. It combines row-wise NVSHMEM expert parallelism, device-resident routing metadata, device-scheduled grouped GEMM, distributed optimizer and pipeline parallelism, MXFP8, recomputation, and topology-agnostic checkpointing, with scaling studies through 1.2 trillion parameters.

中文摘要

作者不是用单一 kernel 宣称“支持 MoE”，而是逐层拆解参数、通信、路由、激活与 checkpoint 的系统成本；主线以 DDP/分布式优化器配合 EP/PP，并给出从 12.9B 到 1.2T 的大规模测量。

Technical Analysis

Problem

MoE 的激活计算不随总参数等比例增长，但参数存储、通信、内核启动和 checkpoint 常随总规模增长；沿用 dense/FSDP 设计会让吞吐随专家数恶化。

Method

row-wise NVSHMEM EP 消除 dispatch/combine permutation；路由元数据留在设备；设备端调度 grouped GEMM；组合 EP/PP/分布式优化器/recompute；支持 MXFP8 与拓扑无关 checkpoint。

Architecture

Input tokens → device router/metadata → rowwise NVSHMEM PUT/GET → grouped expert GEMM → combine；外层 DDP/distributed optimizer + PP；checkpoint 以逻辑参数而非当前拓扑保存。

Key Innovation

以完整训练运行时而非孤立 MoE kernel 为优化单位，尤其把通信布局、路由控制流与 checkpoint 可迁移性联动。

Experiments

12.9B–1.2T 参数，最多 512×NVIDIA B300（8 GPU/节点），sequence length 8192、top-4、1 shared expert；各节另有 4-GPU 对照。MFU 以 B300 dense BF16 2250 TFLOP/s/GPU 计算，并非 FP8 峰值利用率。

Editorial Assessment

Why It Matters

开源 MoE 训练真正的门槛是各层合同能否同时扩展。该报告提供罕见的超大模型、硬件、拓扑与负面结果细节。

Limitations

B300 主导，跨 AMD/其他互连未验证；报告篇幅大且部分结果来自不同配置，复现成本高。2.38T 路径标注为实验性，不能与 1.2T 主结果混写。

CertiSum: Bitwise Deterministic MXFP4 Training Across Vendors and Layouts

CertiSum：跨厂商、跨布局的位级确定性 MXFP4 训练

先证明哪些低精度求和可精确，再只修复未认证输出，使不同 GPU 厂商与 DP/TP/CP 布局得到位级相同的 MXFP4 训练轨迹。

Abstract

Original Abstract Summary

CertiSum provides bitwise deterministic MXFP4 training across hardware vendors and distributed layouts. It certifies reductions whose rounding is provably exact, repairs only uncertified outputs, and merges exact partial results in a layout-independent order.

Faithful English summary of the primary source; not a verbatim abstract.

中文摘要

传统 deterministic mode 往往退回高精度或固定拓扑。CertiSum 把确定性变成逐输出认证问题：满足精确条件的结果走快速路径，其余结果进入修复与精确合并，从而降低“全量保守执行”的代价。

Technical Analysis

Problem

MXFP4 聚合对运算顺序高度敏感，不同厂商 kernel、并行布局和 collective 树会产生不同舍入，破坏复现实验与故障恢复。

Method

为 reduction 构造 exactness certificate；未认证输出用更稳健路径修复；跨 rank 以精确、布局无关方式合并部分和。

Architecture

Local MXFP4 compute → per-output certificate → fast exact outputs / repair queue → exact distributed merge → deterministic optimizer update；适配 DP/TP/CP。

Key Innovation

以“认证后选择性修复”替代所有输出统一高精度，兼顾确定性和低精度吞吐。

Experiments

Qwen3-8B，200 steps；AMD MI350X 与 NVIDIA GB200；多种 DP/TP/CP 布局。比较非确定 MXFP4、deterministic BF16 与 CertiSum。

Editorial Assessment

Why It Matters

低精度训练若不能跨拓扑复现，会增加故障恢复、回归定位和多供应商集群验证成本；确定性是基础设施能力而非纯数值偏好。

Limitations

Qwen3-8B 与 200 steps 仍较小；最高 60.5% 开销在部分配置不轻。代码状态未核实，超大 MoE 与更长训练轨迹尚待验证。
