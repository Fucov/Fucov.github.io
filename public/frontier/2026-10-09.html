Abstract

Original Abstract Summary

Zepp formulates MoE communication as constrained flow planning over GPU and NIC resources. It jointly selects expert placement, splits and merges traffic, and overlaps communication with computation, then compiles the plan into executable paths for diverse cluster topologies.

中文摘要

不同 GPU 拓扑、NIC 注入带宽、消息尺度和专家分布会改变 MoE 通信瓶颈。Zepp 将其建模为受资源约束的数据流规划问题，在执行前为 dispatch/combine 选择放置、拆并流及计算重叠方案。

Technical Analysis

Problem

通用 All-to-All 或手工分层策略无法同时适配节点内 NVLink、跨节点 NIC、负载不均和不同消息尺度，最慢阶段决定整层延迟。

Method

bottleneck-aware objective、expert placement、flow split/merge、GPU/NIC capacity constraints、compute-communication overlap 与 plan compilation。

Architecture

Router/traffic profile + topology → flow planner → placement and path plan → GPU/NIC communication schedule → expert compute overlap → combine。

Key Innovation

把 collective 选择提升为端到端受约束 flow optimization，并将 placement 与 transport 一并求解。

Experiments

A100/H100，2–32 nodes、8–128 GPUs；K2 MoE layer、LiveCodeBench traces、1 MB/64 MB 消息；与 7 个 baseline 比较 latency 和 scale。

Editorial Assessment

Why It Matters

MoE 系统逐渐进入多拓扑、多代 GPU 环境，自动规划比假定单一 fabric 的固定 kernel 更具可移植性。

Limitations

规划依赖准确 profile；动态负载变化与重规划成本仍需验证；端到端模型收益未披露为统一数字；最大值来自不同规模/消息条件。

Editor Note

Top 3。最值得关注的是“通信计划”而非某个单独 kernel；其收益随规模和消息大小剧烈变化。

Abstract

Original Abstract Summary

TokenRouter separates request-centric routing decisions from model-centric batched execution. Each LLM runs as an asynchronous subserver, while a throughput-model-driven scheduler delays and groups ready tokens to recover batch efficiency without violating latency objectives.

中文摘要

逐 token 路由会让一个请求在多个模型之间频繁切换；若按请求同步执行，会把每个模型的 batch 打碎。TokenRouter 将路由状态留在请求控制面，把模型调用汇聚到独立异步子服务，再按收益与等待成本决定批处理时机。

Technical Analysis

Problem

Mixture-of-models、反思与级联式推理需要 token 级动态切换模型，但 request-centric control 会导致小 batch、设备空转和同步阻塞。

Method

request/model execution decoupling、async model subservers、delayed batching、online throughput model、SLO-aware scheduling。

Architecture

Request router/state machine → per-model ready queues → scheduler → asynchronous LLM subservers → token return → next routing decision。

Key Innovation

把 continuous batching 从单模型队列扩展到跨模型、逐 token 路由图，并用性能模型决定“等多久才值得成批”。

Experiments

多 routing algorithms、workloads 与 model pairs；对照官方 R2R 等实现；报告不同 concurrency、SLO 与 engineering/scheduling 消融。

Editorial Assessment

Why It Matters

动态组合多个模型正成为 agentic serving 的常见形态，TokenRouter 提供了比串联多个 API server 更完整的系统抽象。

Limitations

最大 64.15× 来自特定组合，不能代表所有负载；需要稳定吞吐模型；跨节点 data movement、故障恢复与模型加载成本未充分披露。

Editor Note

Top 3。核心价值是执行模型转换，而不是路由算法本身；上线前应按真实到达过程复核尾延迟。

Abstract

Original Abstract Summary

PageWeaver groups queries by the KV pages they are likely to access, performs a bounded GPU-side search for affinity-aware regrouping, and executes the resulting groups with an ID-aware two-CTA sparse-attention kernel. The design targets request-dependent sparsity rather than a fixed sparse pattern.

中文摘要

条件稀疏注意力中，不同请求命中的 KV 页面集合并不相同，按到达顺序成批会丢失跨 query 的复用机会。PageWeaver 在 GPU 上有限搜索近似访问集合，把相似请求重排后交给专用 kernel。

Technical Analysis

Problem

稀疏注意力虽减少算术量，但随机 KV page 访问、低 cache locality 和请求间模式差异限制了实际吞吐。

Method

page-affinity signature、bounded GPU search、online regrouping、ID-aware two-CTA kernel、incremental scheduling。

Architecture

Requests → affinity extraction → GPU regrouping → query groups → sparse KV page gather → two-CTA attention kernel → output restore。

Key Innovation

把请求调度与稀疏 attention kernel 通过“页面访问集合”联合优化，而非只优化单个 request 的索引。

Experiments

H200、CUDA 12.9、FP8 E4M3 KV、MiniMax-M3、Union8、675 requests；多 capture、64K 重点负载，并报告 8K/32K/64K 和 B300 边界。

Editorial Assessment

Why It Matters

随着可学习/条件稀疏进入线上 serving，scheduler 需要理解 kernel 的数据复用条件；这是请求级调度与 attention memory locality 的直接结合。

Limitations

主结果集中于单模型/单稀疏模式；8K 有回退，B300 某些配置失利；在线 grouping 有开销，且代码未公开。

Editor Note

条件披露完整。1.70× 是 attention call 几何平均，不能与整模型 14.36% 直接拼接为同一加速。

Abstract

Original Abstract Summary

VFold reduces only the value-cache representation and reconstructs or combines folded values during attention, preserving the key cache used for score computation. The method is designed to compose with key-side pruning and low-bit KV quantization.

中文摘要

K 与 V 在 attention 中承担不同角色。VFold 不统一裁剪整份 KV，而是针对 value 表示做 folding，换取显存与 batch capacity，同时保留 key 侧的检索能力并允许与其他压缩法组合。

Technical Analysis

Problem

统一的 KV eviction/quantization 可能同时损害检索分数与内容聚合；value cache 占据一半 KV 容量，却缺少专门表示优化。

Method

value-only folding、lightweight reconstruction/aggregation、layer/model calibration，并与 KIVI/ThinK 组合。

Architecture

Full key cache + folded value cache → attention scores from keys → selected/weighted value reconstruction → attention output。

Key Innovation

将 K/V 的不同语义用于非对称压缩，并把 value folding 设计为可与 key pruning、量化正交叠加。

Experiments

三个模型、多长上下文任务；A100-80GB Llama-3.1-8B 8K input +256 output；比较 full cache、CommonKV、KIVI、ThinK，测质量、KV GB、TTFT、TPOT、max batch。

Editorial Assessment

Why It Matters

它展示了“容量收益”与“单请求延迟”并不等价：可扩大 batch，但 decode TPOT 可能变差，适合由 scheduler 按负载选择。

Limitations

给定 A100 配置中 TPOT 明显回退；25% 总 KV 缩减幅度有限；部署价值依赖并发度和 latency SLO。

Editor Note

入选但不是 Must Read：证据诚实且代码开放，性能权衡比单一压缩率更重要。

Abstract

Original Abstract Summary

Attic-KV asks a model to generate compact question-answer rehearsals and retrieval anchors before aggressive cache eviction. Those synthetic tokens preserve task-relevant information that would otherwise disappear, enabling training-free long-context cache compression.

中文摘要

极端 KV 保留率下，简单摘要或重新读入并不能可靠恢复已丢信息。Attic-KV 让模型主动对上下文提问并回答，将事实和定位线索压缩为可继续参与 attention 的 rehearsal token。

Technical Analysis

Problem

3% 等极端保留率会丢失长上下文细节；训练型方法成本高，而通用 reread/summary 未针对后续检索形成记忆锚点。

Method

self-question generation、answer rehearsal、anchor tokens、training-free insertion 与 cache eviction。

Architecture

Long context → self-question/answer generator → rehearsal + anchor tokens → compressed KV cache → downstream query attention。

Key Innovation

把 cache compression 从被动选择转为“压缩前主动排练”，借助模型自身构造未来可检索的记忆痕迹。

Experiments

RULER、多种 keep ratio 与 8 个设置；对照 full reread、no rehearsal、KVgrad、RestoreKV+；报告训练免费质量与压缩时间。

Editorial Assessment

Why It Matters

它为 stateful/agentic 长会话提供另一条路线：不是长期保存全部 token，而是在遗忘前生成低成本记忆。

Limitations

单作者、代码与部署实现未公开；rehearsal 会增加前置推理成本，且生成内容可能遗漏或幻觉；系统吞吐/延迟未充分评测。

Editor Note

刚过阈值。概念新颖，但在进入生产级 memory manager 前需要真实性、隐私与 amortized cost 评估。

The v1.15.0 release replaces full-logit scoring in SFT, DPO, KTO, GRPO, RLOO and distillation with a tiled Triton LM-head path that emits only requested token statistics. It also adds selective activation checkpointing for SFT and strengthens asynchronous GRPO, vLLM and MoE training paths.

中文摘要

这一版本把后训练常见的超大词表 logits 从“先完整生成再计算损失”改成分块投影并即时归约，从根源上避免显存峰值；同时将 TorchTitan 式选择性激活保存引入 SFT，并修复异步 rollout、MoE aux loss 与 vLLM 兼容问题。

Technical Analysis

Problem

大词表下完整 logits 张量可远大于 hidden states，成为 DPO/KTO/GRPO/RLOO/SFT 的显存上限；通用 gradient checkpointing 又会重复计算 attention。

Method

Triton tiled LM-head projection、on-kernel log-prob/entropy reduction、按需统计输出、SFT selective activation checkpointing、AsyncGRPO fixes。

Architecture

Trainer hidden states → fused tiled LM head → token statistics/loss（无完整 logits）→ backward；SAC 在 forward 保存 attention output、其余激活仍重算。

Key Innovation

把训练 API 所需的统计量下推到 LM-head kernel，而不是压缩或切分已经生成的完整 logits；同一机制覆盖六类 trainer。

Experiments

1×B300，但 PyTorch allocator 限制为 79 GiB；随机 BF16 Gemma-3-1B 权重、262K vocab、合成 token、SDPA。最大长度每次新进程二分；吞吐为 12 steps、丢弃前 2、3 轮 A/B/A/B 中位数。

Editorial Assessment

Why It Matters

TRL 是常用 post-training 基础设施，默认路径变化会直接影响 SFT、偏好优化与 online RL 的可训练上下文和成本。

Limitations

未测真实 H100、真实生成、多 GPU 或 FlashAttention；GRPO/RLOO 只测 scoring；默认 chunked-NLL SFT 原本已避免完整 logits，最大长度没有变化；部分旧扩展点属于 breaking change。

Abstract

Original Abstract Summary

The paper analyzes how quantized AdamW moments perturb future preconditioners, then introduces zero-inclusive preconditioner-space stochastic rounding (ZIP-SR) and zero-excluding EDEN calibration (ZE-EDEN). Both use NF4 first moments and targeted LM-head stochastic rounding.

中文摘要

AdamW 的二阶矩会先经过平方根与除法再影响更新，因此 state 值接近并不等于预条件器误差小。论文将舍入概率定义在实际更新空间，并对零点附近的失真分别设计 ZIP-SR 与 ZE-EDEN。

Technical Analysis

Problem

4-bit AdamW 的二阶矩误差会在指数滑动平均中递归传播；零包含可能产生过大更新，零排除又施加正下限并抑制更新。

Method

next-step preconditioner error analysis、ZIP-SR、ZE-EDEN block calibration、NF4 first moment、final-10% LM-head stochastic rounding。

Architecture

Gradient → FP working moments → moment-specific 4-bit quantizer/calibration → persistent packed state → decode → next AdamW recurrence/update。

Key Innovation

选择舍入坐标时显式考虑 optimizer state 如何经过非线性预条件器影响下一步，而不是只优化 state-space MSE。

Experiments

130M–2.7B GPT/Llama pretraining，20 tokens/parameter；8×H200，2.7B 用 8×B200；full SFT；对照 FP32 与 TorchAO 4-bit，测 validation loss、state storage 和诊断。

Editorial Assessment

Why It Matters

optimizer state 是全参数训练的固定大头；该工作同时给出理论失真解释、开源 PyTorch 实现和跨规模验证。

Limitations

训练规模仍低于 frontier 级；最终 10% 的 LM-head 特例增加策略复杂度；显存节省不等于端到端 step time 提升，论文未给统一吞吐结论。

Editor Note

强项是把量化误差与优化动力学绑定。部署时应同时验证收敛、通信格式与 kernel overhead。
