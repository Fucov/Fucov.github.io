Abstract

Original Abstract Summary

uGDS is a user-space storage framework that keeps NVMe command submission and completion control on the CPU while transferring payloads directly between SSD and GPU memory through PCIe peer-to-peer DMA. It exposes a common abstraction across NVIDIA CUDA and AMD ROCm and evaluates both microbenchmarks and an LMCache integration.

中文摘要

uGDS 将控制面与数据面拆开：CPU 在用户态管理 NVMe 队列和命令生命周期，数据则绕过主机缓冲区，在 SSD 与 GPU 显存之间直接 DMA。框架统一封装 CUDA 与 ROCm 的内存注册、地址转换和队列操作，并通过批量异步接口摊薄小 I/O 的控制开销。

Technical Analysis

Problem

传统 GDS 路径依赖内核/专用栈，跨厂商接口不统一；小块同步 I/O 的 syscall、bounce buffer 和队列管理会压过设备能力，也限制 KV cache 分层存储。

Method

用户态 NVMe 队列 + GPU memory pin/register + PCIe P2P DMA；CPU 只提交/回收命令，payload 不经 DRAM。批处理与异步 completion 让多请求并行覆盖控制开销。

Architecture

Xeon Platinum 8368Q、A100-SXM4-40GB、Samsung 990 PRO，Ubuntu 22.04、Linux 6.8、CUDA 12.4、GDS 1.9；框架另实现 ROCm 后端。LMCache adapter 将 KV offload/load 请求映射为 uGDS batch I/O。

Key Innovation

不把 GPU storage acceleration 绑定到单一厂商内核路径，而是在用户态统一命令控制与 GPU-direct 数据面；同一抽象既服务微小随机 I/O，也服务 LLM KV cache。

Experiments

比较 POSIX、SPDK/host staging 与厂商 GDS 路径，覆盖 4 KiB–8 MiB、同步/异步、读/写；随后在 LMCache serving workload 测 TTFT、goodput。论文披露平台配置，但多项最大值来自不同块大小与队列设置。

Editorial Assessment

Why It Matters

分层 KV cache 的瓶颈越来越靠近 SSD/PCIe 数据面。uGDS 给出可复现代码和真实 LMCache 集成，连接了 storage runtime 与 serving SLO。

Limitations

单 NVMe/单机配置为主，生产集群中的 NUMA、多个 SSD、共享带宽和故障恢复尚未充分验证；AMD 结果覆盖面少于 NVIDIA。公开仓库的长期维护与安全隔离仍需观察。

Editor Note

94/S，本日首选。抽象、跨厂商实现、微基准与 LMCache 端到端证据闭环完整；距离 S+ 的主要差距是多设备/多节点规模与独立复现。

Abstract

Original Abstract Summary

Gandalf studies SSD endurance when KV caches are offloaded from GPU memory. It uses attention-type-aware admission to avoid writing cache entries whose expected reuse cannot justify flash wear, and evaluates the policy with serving traces and an emulated SSD lifetime model.

中文摘要

Gandalf 不再把 SSD 当成无限可写的廉价层级。系统根据 attention 行为、请求复用信号和写放大成本决定 KV 是否落盘，在命中收益与介质磨损之间做 admission；低价值对象直接跳过写入。

Technical Analysis

Problem

KV offload 可缓解 GPU 内存压力，但高频写入会快速消耗 SSD TBW；传统 LRU/热度策略只优化 hit rate，忽略介质寿命。

Method

从注意力访问模式估计对象未来价值，用 endurance-aware score 进行 SSD admission；将容量、命中收益和写入损耗共同纳入决策。

Architecture

在线 serving trace 生成 KV 写/读序列，admission controller 位于 GPU cache 与 SSD tier 之间；FEMU 模拟 1 TB、1 DWPD/5 年 SSD，并累计写入寿命。

Key Innovation

把模型内部 attention type 转成存储层写入决策信号，避免只靠历史 recency 预测复用。

Experiments

与 LRU、LRU-K、Marconi、MeritKV、HotPrefix 和 workload-aware baseline 比较；评估寿命、写入量、hit rate。论文假定 WAF=1，且未给出真实多盘故障/性能数据。

Editorial Assessment

Why It Matters

一旦 KV cache 扩展到 SSD，成本模型必须包含耐久度而不只是带宽和容量。Gandalf 为长期 TCO 提供了可操作控制点。

Limitations

主要为 trace-driven 模拟；1 TB、1 DWPD、WAF=1 假设会显著影响绝对寿命。未披露开源代码，实时 admission 开销和多租户公平性未充分验证。

Editor Note

88/A+。问题真实且常被忽略，7.3× 有吸引力，但必须视为特定 endurance 模型下的相对值，而非生产 SSD 的直接寿命承诺。

Related Work

01
LMCache / HiCache

共同点：把 KV 下沉到较慢层级。区别：主要优化命中与搬运。新增量：Gandalf 将 SSD wear 纳入 admission。

02
Marconi

共同点：前缀/KV 缓存准入。区别：以命中价值和容量为主。新增量：Gandalf 显式优化 flash endurance。

03

共同点：按复用价值筛选 KV。区别：依赖热度/前缀特征。新增量：Gandalf 引入 attention-type-aware 价值与写损耗。

Abstract

Original Abstract Summary

MoEZip compresses KV caches in mixture-of-experts models by using expert-routing behavior as a query-independent signal for token importance. It targets severe retention budgets and evaluates long-context quality on LongBench and RULER, including controlled interventions on routing information.

中文摘要

MoEZip 认为 MoE router 不只决定 FFN 专家，也泄露了 token 在模型内部的结构价值。系统据此为历史 token 打分并保留高价值 KV，无需依赖未来 query；在极低 retention 下仍尽量维持长上下文检索和推理能力。

Technical Analysis

Problem

通用 KV eviction 往往忽略 MoE 模型特有的专家路由结构；query-aware 方法开销高，而 query-agnostic 方法在极端压缩下容易丢失关键 token。

Method

从多层 expert routing pattern 构造 token importance，结合层级预算选择保留位置；通过屏蔽或替换路由信息验证收益是否真正来自 router signal。

Architecture

MoE transformer 推理阶段读取已有 routing statistics，压缩 controller 在 attention KV cache 上执行 token selection；FFN 路由本身不改动。

Key Innovation

首次系统性把专家路由作为 KV cache 选择的跨模块信号，并用干预实验而非相关性单独支撑因果解释。

Experiments

Qwen3-30B-A3B 等 MoE 模型，LongBench 与 RULER，多种 retention ratio；与 KVZip、SnapKV、PyramidKV、AdaKV 等比较。公开代码状态未核实，硬件与 serving 吞吐未充分披露。

Editorial Assessment

Why It Matters

MoE serving 的 memory 与 routing 通常分开优化。MoEZip 展示了 router signal 可以反哺 attention cache 管理，为跨模块协同优化打开空间。

Limitations

核心证据偏模型质量，不是端到端 serving throughput/SLO；硬件、kernel 与动态 batching 影响未完整呈现。公开实现未核实。

Editor Note

87/A+。方法新颖且消融强，但系统含金量主要来自压缩策略；若后续公开 runtime 集成与 SLO 数据，评分仍有上升空间。

Related Work

01
KVZip

共同点：按重要性压缩 KV。区别：依赖 query-conditioned signal。新增量：MoEZip 用路由实现 query-agnostic 选择。

02
SnapKV / PyramidKV

共同点：长上下文 token eviction。区别：基于 attention observation/层级预算。新增量：MoEZip 使用 MoE router 的跨模块信息。

03
AdaKV

共同点：不同层分配不同 KV 预算。区别：主要由 attention salience 决定。新增量：MoEZip 增加 expert-routing 结构信号。

Abstract

Original Abstract Summary

Trace2World synthesizes executable agent-training environments from real interaction traces. It reconstructs workflow semantics, validates generated worlds against their sources, and trains agents in the accepted environments. The evaluation measures both environment fidelity and transfer from simulation to external benchmarks and real devices.

中文摘要

Trace2World 先从真实操作记录提取状态、动作、观察与工作流规则，再生成可重复、可扩展的训练环境。系统用源轨迹回放验证环境是否忠实，并淘汰容易被 agent 钻漏洞或无法复现原流程的世界，随后用于大规模训练。

Technical Analysis

Problem

真实设备 rollout 昂贵且不稳定；手写模拟器覆盖有限。自动生成环境若语义失真，会让模型学会模拟器捷径并在部署时失效。

Method

trace parsing + environment synthesis + workflow reproduction test + source validation；只把通过保真检查的环境送入训练，并比较模拟收益在真实/外部环境中的保留。

Architecture

1,570 traces → environment compiler → 50 sandboxed worlds → validation gate → Qwen3.5-9B rollout/training；评估层含内部任务、MobileGym、AndroidWorld、MobileWorld、AndroidDaily 与真实设备。

Key Innovation

把 environment synthesis 的成功指标从“能运行”提升为“复现源工作流且训练收益能转移”，并将验证门作为训练数据管线的一部分。

Experiments

1,044 tasks，每项 3 attempts、3 seeds；最终模型内部 success rate +20.2pp，MobileGym +16.2pp、AndroidWorld +5.4pp、MobileWorld +8.9pp、AndroidDaily +11.1pp；真实设备 +16.3pp。

Editorial Assessment

Why It Matters

Agentic RL 的稀缺资源是可信环境。Trace2World 同时提供合成规模、验证机制和跨环境转移证据，直接影响 rollout infrastructure 的设计。

Limitations

作者/机构和代码开放状态在本期未完整核实；主要覆盖移动/GUI 工作流，向浏览器、代码、企业 API 的泛化未知。环境合成成本与失败分布披露有限。

Editor Note

90/S。不是单纯数据生成：其核心贡献是可验证的环境基础设施与真实设备转移闭环。复现入口不足阻止更高评级。

Abstract

Original Abstract Summary

GIFT uses gradient-derived signals from the student to filter supervision during knowledge distillation and GRPO-style reinforcement learning. The method aims to spend optimization compute on examples or tokens that provide useful learning directions rather than treating all teacher outputs equally.

中文摘要

GIFT 不按 teacher 置信度或固定规则挑样本，而是观察这些监督对学生梯度的方向与幅度，保留更能推动当前模型学习的部分。该信号同时用于蒸馏和 GRPO rollout 过滤。

Technical Analysis

Problem

大规模 teacher traces 和 RL trajectories 中存在冗余、无效甚至与学生当前状态冲突的监督；均匀训练浪费 GPU compute。

Method

计算/近似学生侧 gradient utility，按 utility 过滤 token 或轨迹，再进行 distillation/GRPO；过滤阈值随训练阶段调整。

Architecture

PyTorch + verl 0.8.0.dev + vLLM + FlashAttention + Ray/Hydra；公开仓库提供训练配置，论文实验覆盖 32 GPUs。

Key Innovation

过滤标准直接连接到学生优化动态，并用同一原则桥接离线蒸馏与在线 RL。

Experiments

Qwen3 1.7B/4B/8B，多项数学与逻辑推理 benchmark；对比未过滤、启发式过滤和不同 gradient signal。具体 9.5% 为最佳相对增益，不代表所有模型/任务。

Editorial Assessment

Why It Matters

后训练成本越来越由 rollout 与长 teacher trace 决定。若过滤可在不丢质量的情况下减少无效 token，它可成为 actor/learner 管线的调度信号。

Limitations

梯度估计本身有额外成本；公开仓库仍需独立复现。最佳相对增益跨设置变化，不应视为固定收益。

Editor Note

Abstract

Original Abstract Summary

MOER stabilizes reasoning-oriented reinforcement learning by using expert-generated prefixes early in training, decaying their influence over time, and selectively rolling back problematic policy trajectories. A trust-region supervised update is combined with GRPO to reduce destructive policy drift.

中文摘要

MOER 用多个专家轨迹作为训练初期的“脚手架”，随后逐渐缩短/减少前缀依赖。若 rollout 显示策略退化，系统选择性回滚到更可靠状态，并以受约束 SFT 更新修复，再继续 GRPO。

Technical Analysis

Problem

纯在线 reasoning RL 容易因稀疏奖励、错误自举和分布漂移而崩塌；永久依赖 teacher prefix 又限制自主探索。

Method

expert prefix mixture + scheduled decay + selective rollback + trust-region SFT/GRPO；对高风险更新进行局部修复而非重启训练。

Architecture

Qwen2.5-Math-7B policy，训练循环在 rollout 后执行质量检测，将样本路由到 GRPO 或 rollback/SFT 分支；公开仓库提供实现。

Key Innovation

把专家监督从静态 warm-start 改为可衰减、可回滚的控制机制，并显式处理 RL 崩塌。

Experiments

数学与通用 benchmark，对比 GRPO、TRAPO 等；报告数学/通用平均分与训练稳定性曲线。硬件、端到端 wall-clock 和 rollback 额外成本披露有限。

Editorial Assessment

Why It Matters

后训练系统不仅要最大化 reward，还要能检测和恢复策略退化。MOER 的 rollback 路径可启发更可靠的长周期 RL 控制面。

Limitations

系统资源与吞吐证据不足；多专家轨迹引入额外生成成本。稳定性判据与超参对其他模型的可迁移性待验证。

Editor Note

84/A。公开代码与明确的故障恢复机制加分，但目前更像训练控制算法，系统效率证据弱于本日其他入选项。

Abstract

Original Abstract Summary

NVIDIA Nemotron 3.5 Bolt E4B 4GB is an edge-oriented agentic model post-trained from Gemma-4-E4B-it. It has eight billion total parameters with four billion active, ships in Q4_K_M form for an approximately four-gigabyte footprint, supports 64K input and output contexts, and is paired with a DFlash companion for low time-to-first-token.

中文摘要

该模型面向本地/边缘 Agent：以稀疏 E4B 架构控制每 token 激活量，再用 Q4_K_M 将权重压到约 4 GB；DFlash companion 用于推测/草稿生成以缩短首 token 等待。后训练采用异步 RL 与多环境 GRPO。

Technical Analysis

Problem

边缘 Agent 既要较长上下文、工具调用和记忆能力，又受到 4 GB 级显存/内存与 TTFT 约束。

Method

基于 Gemma-4-E4B-it 继续后训练；异步 RL 解耦训练与推理，多环境 GRPO 覆盖工具/交互任务；量化发布并配套 DFlash。

Architecture

8B total / 4B active E4B，Q4_K_M，64K input/output，OpenMDW 1.1 license；训练栈含 NeMo RL 与 NeMo Gym。

Key Innovation

把稀疏激活、4 GB 量化、长上下文、agentic post-training 与 DFlash TTFT 优化组合为官方可部署包。

Experiments

官方模型卡比较 Gemma-4-E4B-it、Qwen/Nemotron 变体，在 RoleBench、BFCL、When2Call、LongMemEval 等任务报告 BF16/Q4 分数。硬件、真实端侧 tokens/s 与 TTFT 数字未充分披露。

Why It Matters

Frontier lab 的重点信号不是单纯榜单，而是把训练、量化和推测解码作为一个端侧系统交付物；DFlash 也显示小模型 serving 正强调首 token 延迟。

缺少详细端侧硬件、功耗、TTFT/tokens-s 公开表；闭环复现训练成本高。部分 benchmark 并未领先基座，且官方自报结果仍需独立验证。
