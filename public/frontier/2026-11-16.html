Abstract

Original Abstract Summary

Obaleth exposes GPU-initiated communication to the compiler, co-optimizes it with computation, and lowers specialized transport code across NVIDIA and AMD GPUs. The paper reports small-message, collective, and vLLM MoE serving improvements against NCCL GIN, NVSHMEM, and DeepEP.

Faithful English summary of the first-party source; not a verbatim abstract.

中文摘要

通用通信库隐藏了设备端代码与传输决策，阻碍跨计算—通信联合优化。Obaleth 将通信链、完成语义、内存顺序和队列批处理显式化，在不同硬件上生成专用 RDMA/NVLink 路径。

Technical Analysis

Problem

NCCL/NVSHMEM 的通用调用边界会重复支付 reservation、doorbell 与 completion，并让编译器看不到 buffer 生命周期与跨 kernel 依赖。

Method

以通信操作作为 kernel IR 节点；按生命周期规划 completion；合并命令链、裁剪 fence 与同步，并为 GPU doorbell 或 CPU-assisted doorbell 选择分层 lowerings。

Architecture

编译器前端 → 通信 IR → completion/lifetime planner → NVIDIA/AMD transport code；GPU 构造队列与 WQE，按平台由 GPU 或 host thread 敲 doorbell。

Key Innovation

不是再做一个固定 collective，而是让通信像计算 kernel 一样被 specialization、fusion 与跨调用优化。

Experiments

H100：每节点 4 GPU、节点间 200 Gb/s InfiniBand；B200 另测 GPU doorbell。256 GPU all-to-all；vLLM 在 16×B200 服务 Qwen3-235B；MoE dispatch/combine 对比 DeepEP。

Editorial Assessment

Why It Matters

GPU 发起通信真正进入 compiler/runtime 共设计，能针对模型拓扑、消息尺寸和 buffer 生存期生成不同的数据面。

Limitations

H100 仍需 host-forwarded doorbell；结果依赖消息尺寸、拓扑与 compiler specialization。公开代码可复现性尚需社区在更多 NIC/AMD 平台验证。

Editor Note

本日最值得读。贡献不是“更快的 all-to-all”一句话，而是把 transport 选择、同步语义和内存寿命升级为编译对象。

02

共同点：设备侧 one-sided/PGAS；区别：Obaleth 为工作负载生成更小状态与专用 completion；新增量：编译器掌握 buffer 生命周期。

Abstract

Original Abstract Summary

Fuse-All MoE fuses expert computation and communication on TPU7x, retains intermediates on chip, and combines fixed token-slot destinations with load-aware scheduling and placement. It uses EP16 for prefill and symmetric EP8TP2 for decode, reporting kernel and integrated serving gains.

Faithful English summary of the first-party source; not a verbatim abstract.

中文摘要

MoE 在 TPU 上受中间 HBM 流量与 expert skew 双重限制。该工作把 token 收集、专家计算、激活与写回融合，同时保留路由语义，使 placement 与调度可以独立变化。

Technical Analysis

Problem

传统 MegaBlocks/EP 路径产生多次中间 HBM 往返；prefill 的 expert skew 与 decode 的小批量又要求不同负载均衡策略。

Method

Prefill 用 EP16 的 load-aware tile scheduling、expert redistribution 与预置副本；decode 用跨同一芯片两个 TensorCore 的对称 EP8TP2。

Architecture

TPU7x 每芯片 2 TensorCore、192 GiB HBM、约 7.38 TB/s；base kernel 跨 16 devices/8 chips，intermediate 留在 VMEM，固定目标槽维持完成语义。

Key Innovation

把 kernel fusion 与系统级 expert placement 放在同一 token-slot contract 下，而不是分别优化。

Experiments

TPU7x 2×2×2 slice；EP16 prefill 与 EP8TP2 decode；32–512 decode tokens；对比 MegaBlocks EP16。论文区分 kernel、whole-layer 与完整 serving。

Editorial Assessment

Why It Matters

MoE serving 的瓶颈正在从单一 GEMM 迁移到 token movement、placement 与上下游并行布局的整体设计。

Limitations

整栈 34.5% 含其他优化；慢芯片尾部、padding、scalar overhead 仍在；代码未披露，硬件限定 TPU7x。

Editor Note

Meta 实验室交叉信号。报告单列为独立论文，但 PART III 只引用，不重复计数。

Abstract

Original Abstract Summary

Superfluid separates local serving from model runtimes, adds QoS-aware scheduling, process isolation, durable session logs, prefix coalescing, and heterogeneous fleet placement. It evaluates interactive latency under agent load and multi-device scaling across Apple, AMD, and NVIDIA systems.

Faithful English summary of the first-party source; not a verbatim abstract.

中文摘要

该系统不切分一个模型，而是在每台可容纳完整模型的设备上复制模型，将整个 session 放置到某一节点，仅传 token id。单机侧用抢占和短 tick 保证交互请求，多机侧按实测速率、KV 占用与前缀亲和性放置。

Technical Analysis

Problem

本地 server 通常绑定单 runtime/单机，无法在后台 agent 并发时保障交互响应，也缺乏跨设备故障恢复和 durable conversation。

Method

四级 QoS、lane 抢占、chunked prefill、shared-prefix hold、KV admission 重试；append-only token log 在输出前 fsync；节点按预计完成时间和 prefix affinity 选择。

Architecture

Rust daemon 管 API/调度/tokenizer/session log；每模型独立 worker 管 weights/KV/sampling；Unix socket + shared-memory ring；fleet 用 TCP+Noise，节点运行 llama.cpp/MLX/BaseRT。

Key Innovation

把本地推理的耐久性、交互优先级与异构 replica placement 放到同一 serving contract，而非只追求单机 tok/s。

Experiments

Qwen3.8-27B 4-bit、Apple M5 Pro 64GB；六台三厂商设备、64 simulated users 一小时；另测 12×M3 Ultra、Qwen3.6-35B-A3B、384 agents。

Editorial Assessment

Why It Matters

Agentic serving 的核心 SLO 从“模型吞吐”扩展到用户抢占、durability 和 session failover。

Limitations

每节点必须容纳完整模型；跨节点迁移要重算 prompt，节点间不传 KV；单个 fleet 实验只用一种 runtime；无 TLS，需要可信网络或反向代理。

Editor Note

开源、实验透明，且明确承认复制式架构边界；适合本地多智能体而非数据中心超大模型切分。

v1 submitted 2026-11-13 17:28:37 UTC；first public listing 2026-11-16

Abstract

Original Abstract Summary

Callo reuses invalidated KV as speculative state while exact prefill rebuilds KV on a disaggregated prefill instance. It schedules and preempts speculation based on decode capacity and confidence, then verifies drafts against exact state before committing output.

Faithful English summary of the first-party source; not a verbatim abstract.

中文摘要

Agent 会话编辑会让 prefix cache miss，但旧 KV 并非毫无价值。Callo 在 decode 节点基于旧 KV 生成 provisional drafts，同时 prefill 节点计算精确 KV；最终仅接受精确验证的 token。

Technical Analysis

Problem

PD serving 中 cache miss 请求在 re-prefill 完成前完全等待，而 decode 资源可能空闲；直接使用旧 KV 又会破坏正确性。

Method

构造 provisional KV；draft 与 exact prefill 重叠；confidence early stop；decode 侧 capacity policy；通过 NIXL 转移并用 exact KV 验证。

Architecture

P-instance 与 D-instance 各一张 H200 NVL，通过 NVLink/NIXL；vLLM 0.29；scratch blocks 隔离 provisional state，验证后原子提交。

Key Innovation

将“失效缓存”从废弃对象变为不可信但可验证的 speculative state。

Experiments

2×H200 NVL 141GB；Llama-3.3-70B FP8、Gemma-4-31B/Mistral-Small-3.2-24B BF16；100 个 SWE-bench Verified session，20 个校准，L5/L10 context management；另做 8–192 GPU trace simulation。

Editorial Assessment

Why It Matters

Stateful serving 不应只问“缓存是否命中”，还应区分 exact、invalidated-but-useful 与 disposable 三类状态。

Limitations

收益依赖 session affinity、cache miss 频率、suffix 长度和空闲 decode 容量；P:D 偏斜时某些组合接近无收益或退化；代码未披露。

Editor Note

不能把 1.32× miss-request 峰值写成普遍服务加速；主结论保留 all-request 与负载条件。

Abstract

Original Abstract Summary

LWS co-schedules prediction and inference-time learning on shared accelerator resources. Per-layer weight versioning, resumable reductions, and specialized softmax-gradient units allow learning to use fragmented idle capacity while protecting prediction latency.

Faithful English summary of the first-party source; not a verbatim abstract.

中文摘要

长上下文通过推理时学习把历史写入权重，但引入 backward 与 update。LWS 不增加第二套 MAC，而是利用 attention 非矩阵阶段留下的矩阵空闲，并允许不同层以不同延迟发布更新。

Technical Analysis

Problem

推理加速器假定权重静态，训练加速器又针对完整 step；ITL 同时具有低延迟 prediction 和可延迟 learning，现有设计都不匹配。

Method

按层 weight versioning；可中断/恢复 reduction block；learning kernel 可让位给 prediction；专用 dS/dZ 单元缓解 vector/softmax gradient 竞争。

Architecture

建模 datacenter/edge NPU，32MB/4MB SRAM；MAC array 共享；版本控制发布更新；scheduler 在空闲周期切片 learning。

Key Innovation

把 mutable weights 与更新可见性做成硬件一等语义，并以 per-layer lag 形成质量—吞吐控制面。

Experiments

TTT-E2E 3B、128K；9 个模型；96 组 1B/3B/8B、2–8 mutable layers、512–4096 chunk、SGD/AdamW；RTL 16nm synthesis。

Editorial Assessment

Why It Matters

若 ITL 成为长上下文替代路径，服务系统将需要同时调度 token 与 parameter mutation。

Limitations

没有实硅和生产 serving 验证；质量以特定 ITL/模型衡量；硬件收益依赖 learning 能落入 prediction idle capacity。

Editor Note

架构新颖度高，但 Evidence/Reproducibility 因 modeling-only 下调。

Abstract

Original Abstract Summary

SGLang adds a single-launch hierarchical ring all-reduce for gfx1250 partition pairs. Each partition runs a cross-accelerator ring while pair links exchange split shares in the same kernel, with guarded dispatch and bit-exact tests.

Faithful English summary of the first-party source; not a verbatim abstract.

中文摘要

gfx1250 的两个逻辑 GPU partition 共享外部链路但拥有独立 pair link。新 kernel 同时运行两条跨 accelerator ring，并在同核内交换 pair share，以减少外链流量和并发争用。

Technical Analysis

Problem

两个跨 accelerator ring 并发会争用共享链路；flat ring 即使把 partition 放相邻仍发送过多跨 accelerator 数据。

Method

每 chunk 分半，partition h 在对应 ring 传输；三个 FIFO（cross/pair-in/pair-out）以 64-bit counters 同步；8 warp 中 3 个搬 pair 数据、5 个跑 cross step。

Architecture

单 kernel、每 CU 一 channel；HierRingPlane 提供 3×2×512KB slices/channel symmetric buffer；heuristic 仅在成对 partition 且消息够大时启用。

Key Innovation

显式利用“共享外链 + 独立内链”的 partition-pair 拓扑，而不是把逻辑 GPU 当等价 rank。

Experiments

8-GPU gfx1250 node（每 accelerator 两 partition）、BF16、8 次 all-reduce/CUDA graph、10 replays、median of 3、max rank；TP4/6/8；bit-exact 对 RCCL。

Editorial Assessment

Why It Matters

逻辑 GPU 分区会改变 collective 最优拓扑，通信 runtime 需要理解物理共享资源。

Limitations

只覆盖 gfx1250 partition pairs 和较大消息；部分额外 CI/ROCm job 红灯；真实 serving workload 未展示端到端收益。
