Abstract

Original Abstract Summary

Delta Tokenizer reuses the prior token sequence of a session and re-encodes only appended text plus the short tail whose segmentation may change. For a stateless long prompt, it derives tokenizer-safe cuts, encodes segments across CPU cores, and concatenates them into an output identical to the reference tokenizer. A shared pool interleaves incremental updates with chunks from long jobs.

中文摘要

该工作把分词器从“每次从头计算”的无状态前端，改造成能理解 session delta 的有状态组件。关键约束不是近似加速，而是在安全拼接边界上保持与参考 tokenizer 完全一致；同时把长请求拆成可调度的小块，避免拖住短更新。

Technical Analysis

Problem

KV prefix cache 已避免重复 prefill，但 serving frontend 仍会对每轮完整对话重新分词；长上下文和 agent 多轮交互会把 CPU tokenization 推到 TTFT 与吞吐关键路径。

Method

保存前一轮 token IDs；只重编码 append 和短尾窗口；根据 pre-tokenizer 转移寻找稳定拼接点。对无 session 状态的长输入使用 segment-parallel encode，并在共享 CPU pool 中以 chunk 粒度调度。

Architecture

Session state / request text → delta detector → stable-boundary incremental encoder；冷请求 → safe-cut planner → multicore chunks；两条路径进入共享 tail-aware CPU pool，再把 reference-identical token IDs 交给 SGLang。

Key Innovation

把“完全一致的增量分词”“超长输入的多核并行”和“短增量不被长任务阻塞的调度”统一到 serving frontend，而不是只优化单次 tokenizer microbenchmark。

Experiments

主 CPU 平台为双路 AMD EPYC 9115 中固定 16 核，扩展实验用双路 64 核 EPYC 7763；SGLang v0.5.19 运行在 RTX PRO 6000 96GB 或 RTX 5090 32GB。覆盖 Qwen3、Llama-3.1、gpt-oss、DeepSeek-V3 tokenizer、SWE-smith agent traces，并核验 418 亿文档的输出一致性。

Editorial Assessment

Why It Matters

prefix caching 生效后，tokenization 会成为新的 fleet bottleneck。该工作直接对准用户正在关注的 agentic/stateful serving，并已经给出 SGLang 端到端 TTFT 结果。

Limitations

目前公开代码包含 incremental path 和 fast encoder；chunk-parallel path、CPU pool scheduler 与 SGLang adapter 尚标注为后续开放。返回 Python integer IDs 仍有拷贝开销，且收益集中在长上下文/高复用 session。

Editor Note

本期 Must Read。最有价值的不是 40× 单点数字，而是证明 tokenizer 需要像 KV cache 一样维护 session state，并被纳入 serving scheduler。

Abstract

Original Abstract Summary

JointServe manages model-weight shards and KV blocks under one HBM budget. It reads the target expert from the caller model’s streamed tool call, prefetches missing layer groups during generation and tool gaps, retains a partial resident prefix of each model, and reserves transfer bandwidth for restoring live-session KV. An adaptive carve-out changes the weight/KV split with workload demand.

中文摘要

多模型 agent 的能力分散在不同权重中，有限显存既要容纳即将调用的模型，又要保存会话 KV。JointServe 不再把“换模型”和“保 KV”视作两个问题，而是在统一预算里选择权重层组与 KV，并借助明确的下一专家信号提前搬运。

Technical Analysis

Problem

整模型换入会把 PCIe 传输串行放到 TTFT 关键路径；为腾权重空间丢掉 KV 后，返回原模型又需昂贵 re-prefill。异构专家也不能假设共享 base weights。

Method

统一 residency value/cost 模型、动态 weight/KV carve-out、tool-call intent prefetch、partial k* layer residency、preemptive transfer bandwidth floor、host-backed KV restoration。

Architecture

Planner streaming output → target-model signal → residency selector；HBM 内联合存放 weight layer groups + KV blocks；host RAM 保存可恢复 KV；chunk scheduler 在 weight prefetch 与 live KV restore 间分配带宽。

Key Innovation

利用 agent 调用图中可直接读取的目标模型，把模型切换从“请求到达后预测”改为“调用者生成期间预取”，并在单实例内联合管理权重和 KV。

Experiments

A800-SXM4-80GB、PCIe 4.0、1TB host RAM、实测 H2D 24.3 GB/s；五个 7B 级专家以及 14B/32B tier；synthetic、TraceLab 665K turns、SWE-bench、τ-bench、OSWorld。基于 SGLang 实现。

Editorial Assessment

Why It Matters

模型即工具的 agent workload 会把 serving working set 从一个模型扩展为权重池+长生命周期 KV；该工作直面私有部署/共享 GPU 的容量墙。

Limitations

单作者、单 GPU 原型，未公开代码；未覆盖多节点路由、权重版本更新或多租户隔离。模型意图必须能从 tool-call stream 中提前确定；与 Talaria 等跨实例策略的联合不在实验内。

Editor Note

研究切口独特且端到端结果完整，但代码与更大规模复现缺失，因此压在 A+。特别值得关注其 weight/KV 统一 residency 抽象。

Abstract

Original Abstract Summary

CacheSmith addresses the accuracy loss caused when independently cached RAG chunks omit cross-chunk attention. It exposes a configurable WarmUp–Probe–Patch recomputation pipeline, profiles cost–accuracy bands, forms interference-aware layer-by-layer prefill batches, and uses a solver-free planner to select per-batch recomputation under quality and latency budgets.

中文摘要

RAG context cache 能跳过 prefill，却会缺失拼接后产生的跨 chunk attention。CacheSmith 不使用固定重算比例，而是根据请求、任务信号、到达负载和当前 SLO，动态决定哪些层/阶段需要补算。

Technical Analysis

Problem

完全复用 chunk KV 快但可能降低答案质量；full prefill 准确但慢。静态 selective recomputation 无法应对请求异质性和动态排队预算。

Method

WarmUp/Probe/Patch 三阶段重计算；profiled cost–accuracy bands；solver-free budget planner；SLO-aware batching，减少 layer-by-layer prefill 的跨请求干扰。

Architecture

Offline cached chunks（host/NVMe）→ transfer engine → partial KV allocation → layer-wise prefill；online scheduler 形成 batch，planner 按质量门槛和剩余 TTFT budget 配置三阶段。

Key Innovation

用“质量通过且在 SLO 内”的联合指标驱动 KV reuse，而非只追求 token latency 或固定近似精度。

Experiments

RTX PRO 6000 96GB、AMD EPYC 9554、Samsung 9100 PRO Gen5×4；Llama-3.1-8B 单卡、Qwen3-32B 双卡；LongBench/RULER 四任务，共 600 请求；0.2–0.4 req/s Poisson 与 CV 2–3 Gamma burst。

Editorial Assessment

Why It Matters

KV reuse 的真正上线条件不是平均更快，而是在负载变化时同时保持答案质量与 tail SLO；这是将近似缓存从 kernel 技巧变为 serving policy 的关键。

Limitations

应用 workload 是 RAG，泛化到一般 agent prompt 或非检索 chunk 未验证；自定义 Triton attention-weight kernel 未调优，代码未确认；最高 27.5% 不能外推到所有负载。

Editor Note

虽然用户要求过滤普通 RAG 应用，但本工作贡献是通用 KV reuse/runtime/scheduler，而不是应用层 RAG，因此进入主体。

Abstract

Original Abstract Summary

This pre-release advances TensorRT-LLM’s C++ runtime and serving stack with sparse-KV configuration and tier-aware offload, a Mooncake-backed store pool, stronger V2 scheduling, model startup observability, MoE routing optimizations, speculative-decoding accounting, and expanded support for GLM-5.3, Kimi K3, MiniMax-M3 and Nemotron models.

中文摘要

该版本不是单一算法论文，而是将 KV 分层、外部存储池、抢占、投机解码预算、MoE 小 batch 优化以及多种新模型的状态语义整合进生产 runtime。重点应看接口覆盖和 correctness 修复，而不是不存在的统一加速倍数。

Technical Analysis

Problem

新模型不断引入 sparse attention、KDA/MLA、MTP 与不同 KV 语义；分布式 serving 同时需要 offload、抢占、KV transfer 生命周期和可观测性保持一致。

Method

C++ KVCacheManagerV2、tier-aware sparse KV/offload、Mooncake store pool、V2 scheduler budgeting/preemption、per-request speculative acceptance 与 spend-aware draft KV budget。

Architecture

OpenAI server / serving extensions → scheduler V2 → C++ model runner & KVCacheManagerV2 → sparse/tiered KV + Mooncake store → CUDA/FlashInfer/CUTLASS kernels；disaggregated KV transfer 维护 ownership/retirement。

Key Innovation

把多项论文式能力落到统一 runtime contract，并通过 KV transfer、scheduler 和 model runner 的结构调整减少“模型专用补丁”外溢。

Experiments

release notes 给出 VR200 4-GPU serving performance cases已加入测试，但没有公开统一结果；已披露若干 H100、SM120/121 的 known issues。不能把 feature list 等同于性能提升。

Editorial Assessment

Why It Matters

TensorRT-LLM 是 NVIDIA 生产推理路径的重要参考。该 RC 将 sparse KV、外部 store 与新模型支持同时推入主线，对后续 vLLM/SGLang connector 设计有直接参考价值。

Limitations

预发布版本；已知 TP2/H100 worker-pool hang、SM120/121 DeepSeek MLA CUDA Graph illegal memory access 等问题。缺少统一 benchmark，部分功能仍标注 part 1 或准备阶段。

Abstract

Primus Projection combines measured GPU microbenchmarks with analytical reconstruction of collectives, FSDP overlap and pipeline schedules at a target cluster size. A CPU-only simulation mode supports pre-silicon planning. The Primus Tuning Agent uses the projection as a seconds-per-candidate oracle, combining deterministic axis sweeps, an LLM investigation loop and an analytical memory feasibility filter.

中文摘要

配置大模型训练需要同时决定多维并行、micro-batch、重计算、sharding 与 overlap。Primus 不要求为每个候选启动完整多机作业，而是测量能低成本测量的部分，再对目标规模恢复不可直接测量的通信和流水线行为。

Technical Analysis

Problem

训练 recipe 空间组合爆炸；一次错误配置可能直接 OOM，靠多节点试错既昂贵又无法覆盖 pre-silicon/新硬件规划。

Method

单卡/子节点 microbenchmark + 解析模型；downscale–measure–upscale；memory legality pre-filter；deterministic seed planner 与 LLM cross-axis search。

Architecture

Model/hardware YAML + microbenchmarks → hybrid projection engine → throughput/memory oracle；seed planner/LLM investigator 生成候选 → pre-filter → 小预算真实验证 → 更新搜索。

Key Innovation

不是纯分析模型或黑盒 trial，而是在真实 kernel/library 漂移与多维并行解析之间建立可扩展中间层，使 agent search 获得低成本、高保真的评分器。

Experiments

Llama-3.1 dense、Mixtral 8×22B MoE；MI325X/MI355X；生产规模验证到 DeepSeek V3 1,024 GPUs 与 Qwen3-235B 256 GPUs。论文明确未在 NVIDIA/TPU 实证，ZeRO-2 不覆盖，网络拥塞未建模。

Editorial Assessment

Why It Matters

这正对应 Megatron/FSDP/TorchTitan 用户最现实的难题：不是缺少并行策略，而是不知道在新模型、新 GPU 和新软件栈上选哪套组合。

Limitations

只在 AMD Instinct/ROCm 实证；尚未验证 NVIDIA/TPU。网络拥塞可能在跨节点 EP 中放大误差；FP8 recipe 仍需收敛验证；代码开放状态未核实。

Editor Note

本期训练侧 Must Read。价值在“测量锚点+解析投影”的工程可信度，而不是 LLM agent 本身；若开放工具链，复现价值会进一步提升。

Related Work

01
Calculon

共同点：解析估算并行训练性能。区别：Calculon 主要依赖硬件规格。新增量：Primus 用真实 microbenchmark 捕获 fused kernel、clock 与库版本效应。

02
Galvatron

共同点：搜索 TP/PP/DP 配置。区别：Galvatron 主要 profile 单层并建模通信。新增量：恢复 FSDP overlap、完整 pipeline 和 MoE grouped-GEMM。

03
FlexFlow / Alpa

共同点：profile/搜索执行策略。区别：常需要目标集群算子或 stage profiling。新增量：子节点测量外推到 1,024 GPUs。

04
ATTUNE

共同点：自动寻找训练 recipe。区别：ATTUNE 通过真实 runs 和 correctness gates 调优；Primus 以快速投影 oracle 为核心。新增量：秒级候选评分与 pre-silicon 模式。
