Abstract

Original Abstract Summary

The release consolidates 927 commits across model support, speculative decoding, CUDA graphs, context parallelism, KV transfer/offload, MoE and hardware-specific kernels. Its benchmark claims are tied to individual pull requests and configurations rather than one aggregate speedup.

中文摘要

本版本的重点不是单个模型接入，而是把 DFlash/DSpark、FLy、DCP、Mooncake/NIXL、专家并行与 NVIDIA/AMD 专用 kernel 同时推进到生产接口；默认 wheel 转向 CUDA 13 和 PyTorch 2.14。

Technical Analysis

Problem

高速模型迭代使 serving runtime 同时承受模型结构、通信、内存层次和硬件后端变化。

Method

把多个独立 PR 的 kernel、调度、传输与 API 改进纳入统一 release，并提供 CUDA/ROCm/CPU/XPU artifact。

Architecture

vLLM engine core + Model Runner V2 + KV connector/offload + distributed context/expert parallel backends；EFA 镜像内置 Mooncake transfer engine。

Key Innovation

投机解码不再只是 drafter 接口：token budget、prefix-cache 尾块、量化 draft head、verification policy 与 CUDA Graph 都被协同优化。

Experiments

官方 release 汇总的条件化结果包括：DeepSeek-V4.1-Flash+DSpark/GB300 1373→3390 output tok/s；FLy 在 MI355X/B300 为 1.04–1.31×；FlashInfer DCP prefill 在 8×B200、100k input 下 mean TTFT 降 39–48%。

Editorial Assessment

Why It Matters

它同时改变默认依赖、KV 数据面与高端 GPU execution path，是当日最直接影响部署者的工程发布。

Limitations

CUDA 12.9 artifact 被移除；大量结果来自 PR 自报且硬件/模型各异；tag 名为 v0.33.0rc3、页面标题与 artifact 为 v0.33.0，需注意版本标识差异。

Editor Note

生产升级应先验证 CUDA 13、NIXL 1.5 和已移除 Medusa/旧 Ray graph executor 等 breaking changes。

Abstract

Original Abstract Summary

HiState targets hybrid full-attention/recurrent models in long agent sessions. It stores historical recurrent checkpoints on SSD, combines them with fast KV reuse, adapts checkpoint intervals and coordinates eviction across state types.

中文摘要

混合模型既需要 KV，也需要周期性 recurrent state；HiState 将历史 checkpoint 放到 SSD，以自适应间隔控制恢复代价，并以统一 eviction 管理两类状态。

Technical Analysis

Problem

长 Agent trace 的状态大且异构，现有 KV-only cache 无法高效恢复 recurrent layers。

Method

历史 recurrent checkpoint、快速 KV cache、自适应 checkpoint interval、统一状态驱逐。

Architecture

vLLM 扩展：HBM/主存/SSD 层次保存 KV 与 recurrent checkpoint，恢复时选择最近状态并重放后缀。

Key Innovation

首次把 hybrid-state agent serving 的两个状态空间作为共同资源管理，而非分别补丁。

Experiments

两条 coding-agent trace；对比 vLLM-Marconi 与 SGLang-HiCache。摘要未披露 GPU/SSD 型号。

Editorial Assessment

Why It Matters

Hybrid recurrent architecture 正进入 Agent serving，状态管理会成为 KV cache 之后的新数据面。

Limitations

硬件、模型规模与代码开放状态未在摘要披露；结果集中于两条 coding trace。

Editor Note

最值得复现的是 checkpoint interval 与 eviction 在域外 trace 上的稳定性。

Abstract

Original Abstract Summary

Flide introduces exact state forking for decision inference. ForkAttention maps flattened tree branches to GPU indices for both standard attention and Gated DeltaNet, while prerecorded execution graphs and checkpoint resume reduce control overhead.

中文摘要

决策推理需要从同一前缀探索大量分支。Flide 将树展平成单一 token 流，ForkAttention 在 GPU 上复用共同前缀状态，并对 full-attention 与 recurrent state 保持精确语义。

Technical Analysis

Problem

逐分支重复 prefill 浪费算力，近似状态复用又会改变分支概率。

Method

tree flattening、ForkAttention 索引、预录 execution graph、checkpoint resume。

Architecture

GPU-resident branch map 为每个 token 指向正确的 KV/recurrent state；执行图覆盖分叉、推进和恢复。

Key Innovation

把 exact state forking 从 full attention 推广到 Gated DeltaNet hybrid state，同时保持数值忠实度。

Experiments

多种 decision workloads，对比 vLLM 与 SGLang；摘要未披露具体 GPU、模型和全部对照设置。

Editorial Assessment

Why It Matters

stateful/decision API 正从文本生成的边角用例变成独立 runtime primitive。

Limitations

代码状态与完整硬件条件未核实；峰值加速依赖树形分支结构。

Editor Note

若实现能进入主流 runtime，状态分叉可能成为 search/agent serving 的通用接口。

Abstract

Original Abstract Summary

ARK observes that ECMP collisions among long KV-transfer flows inflate prefill-decode handoff latency. It reserves distinct spine paths by choosing sender source ports, requiring neither switch modification nor packet reordering.

中文摘要

PD 解耦的 KV 流持续时间长，ECMP hash 碰撞会形成热点。ARK 在发送端选择 source port，使并发流映射到不同 spine，并保持标准网络设备兼容。

Technical Analysis

Problem

ECMP 对长 RDMA KV 流的随机碰撞放大 FCT 与 TTFT。

Method

collision-aware path reservation and sender-side source-port selection。

Architecture

集中式 path allocator 追踪 spine 使用；sender 选择对应 5-tuple，网络仍运行普通 ECMP/RDMA。

Key Innovation

以最小部署改动把 PD 数据面从随机 ECMP 变成可控 path allocation。

Experiments

packet-level RDMA simulation；未披露真实集群部署。

Editorial Assessment

Why It Matters

当 KV transfer 成为主要网络流量时，端侧可控路由比单纯增加带宽更便宜。

Limitations

核心证据来自仿真；真实交换机 hash、背景流和故障恢复仍待验证。

Editor Note

SIGCOMM 接收增强可信度，但生产价值取决于能否接入现有 P/D scheduler。

Abstract

Original Abstract Summary

LEAP reuses the serving model's prefill hidden state with a linear readout and adapts it online using recursive least squares on CPU, overlapping updates asynchronously with inference.

中文摘要

输出长度可帮助 SJF/SRPT 式调度，但另跑预测模型太贵。LEAP 复用主模型隐藏状态，只训练线性头，并用递归最小二乘应对 domain shift。

Technical Analysis

Problem

输出长度未知导致 batching 和抢占策略低效；强预测器本身又增加延迟。

Method

prefill feature extraction、linear readout、CPU RLS online adaptation。

Architecture

GPU prefill 产生 feature；CPU 异步更新小型 predictor，scheduler 使用估计长度。

Key Innovation

把预测器参数和运行成本降到几乎可忽略，同时保持对域漂移的自适应。

Experiments

多域调度 workload；摘要未披露具体 GPU 和模型。

Editorial Assessment

Why It Matters

长度感知调度长期受 predictor overhead 限制，LEAP 把它变成可部署组件。

Limitations

相关性改善不等于绝对误差一致；极端长尾与对抗 prompt 未核实。

Editor Note

吞吐增益较小但尾/平均延迟改善明显，适合 SLO 优先而非纯吞吐场景。

Related Work

Abstract

Original Abstract Summary

The study separates per-call efficiency from task-level energy. On A100 GPUs, 4-bit weights with 16-bit activations reduce energy for a fixed number of calls, yet live agents can consume more per verified completion because quantization changes reliability and retry behavior.

中文摘要

量化常按每 token 或每次调用评估。本文在 coding/data agent 中以“验证通过的完成任务”为分母，发现重试会逆转局部节能。

Technical Analysis

Problem

局部推理能效无法代表 Agent 完成任务的总能耗。

Method

固定调用与 live-run 双重实验、verified-completion accounting、cache-cap sensitivity。

Architecture

两种 agent model 在 A100 40/80GB 上运行 coding/data workflows，并记录调用、重试、缓存和完成验证。

Key Innovation

将模型可靠性和控制循环纳入量化能耗边界。

Experiments

A100 40GB/80GB，两种 Agent 模型、coding/data 任务；对比 4-bit/8-bit 权重与 16-bit activation。

Editorial Assessment

Why It Matters

它提醒系统论文必须用任务完成而非 token 作为 Agent 成本单位。

Limitations

模型/任务样本有限，量化 kernel 和软件栈细节决定外推性。

Editor Note

结果不是“量化无效”，而是量化与可靠性、cache policy 必须联合优化。

Abstract

Original Abstract Summary

MemX extends auto-parallel search to cross-vendor heterogeneous GPU clusters. It jointly models iteration time, memory and balance, supports recomputation, and uses sparse profiling plus interpolation, dual-output XGBoost and prediction caching.

中文摘要

异构集群中同一 DP/TP/PP/recompute 配置会在不同 GPU 上产生不同时间与显存压力。MemX 用联合代价模型筛选可行且平衡的 Megatron-LM 方案。

Technical Analysis

Problem

现有 auto-parallel 工具多假设同构 GPU，且 profiling 搜索成本过高。

Method

weighted product objective、minimal profiler、interpolation augmentation、dual-output XGBoost、cache。

Architecture

Megatron-LM 执行层上方的 search/planning layer，输入各 GPU 性能和内存特征，输出混合并行与 recompute 策略。

Key Innovation

把 memory feasibility 与 cross-vendor balance 共同纳入大规模搜索。

Experiments

两个异构集群、四个基线；40/60 GPU 部分结果由测得的 20 GPU 数据仿真外推。

Editorial Assessment

Why It Matters

异构 GPU 采购与闲置资源越来越常见，自动规划能直接影响训练 TCO。

Limitations

40/60 GPU 结果不是实机；预测误差和跨软件版本迁移需评估；代码状态未核实。

Editor Note

可迁移性比单次 Top-1 更关键，应关注模型在新 kernel/模型架构下是否要重做 profiler。

Abstract

Original Abstract Summary

Fair Cast identifies a deployment-facing numerical bias: with tiny online updates, deterministic BF16 export leaves most served weights unchanged for many steps. An unbiased casting rule removes the lag with a one-line change and small export cost.

中文摘要

Qwen3-1.7B 在线训练中每步只有 0.4–0.5% 的 serving 权重变化，导致 rollout policy 落后 50–150 步。无偏舍入让小更新以正确概率反映到 BF16。

Technical Analysis

Problem

FP32 optimizer state 到 BF16 serving weight 的量化会吞掉小更新，形成隐蔽 policy lag。

Method

unbiased stochastic-style cast at export, matched-seed evaluation。

Architecture

训练保留 FP32 master；每次同步时用无偏规则生成 BF16 serving 权重，不改 optimizer 或 rollout runtime。

Key Innovation

把数值舍入本身识别为 online RL 的策略陈旧来源。

Experiments

25 组 matched seeds，0.6B–4B，AdamW/Muon；Qwen3-1.7B export 22–38ms。

Editorial Assessment

Why It Matters

这是极低实现成本、可能高回报的训练—推理同步修复。

Limitations

效果集中在小更新/频繁导出的 online setting；随机性与确定性复现需要工程约定。

Editor Note

应优先验证与 vLLM/NCCL 分片权重传输、FP8 serving weight 的组合行为。

Related Work

01
Stochastic rounding

同为无偏舍入；Fair Cast聚焦 serving weight export。

02
Mixed-precision master weights

保留 FP32 更新；Fair Cast修复导出到 BF16 的最后一步。

03
Async RL policy lag

通常归因 sampler 延迟；本文显示数值量化也是 lag。

Abstract

Original Abstract Summary

DLC decomposes training-inference mismatch into numerical discrepancy and policy lag. It centers the former, clips lag-induced ratios, and triggers resynchronization when effective sample size falls below one half.

中文摘要

异步 RL 中 rollout 和 learner 的 log-prob 差异既来自 kernel/精度，也来自真实旧策略。DLC 区分两者，避免用同一个 importance ratio 粗暴修正。

Technical Analysis

Problem

把所有 log-prob mismatch 当 policy lag 会过度校正数值噪声并导致训练崩溃。

Method

discrepancy centering、lag-ratio clipping、ESS-triggered resync。

Architecture

actor/learner 异步管线中增加轻量统计与同步控制，不改变基础 policy optimizer。

Key Innovation

用可解释分解连接数值系统误差与统计 off-policy correction。

Experiments

Qwen3-0.6B/1.7B，在 stale sampler 条件下对比独立 on-policy 训练。

Editorial Assessment

Why It Matters

训练系统的数值一致性和 sampling freshness 需要联合设计。

Limitations

规模仅到 1.7B；更大 MoE、多机 kernel heterogeneity 未验证。

Editor Note

与 Fair Cast 同日出现，说明 online RL 的“系统误差”正在成为独立研究层。

Related Work

01
PPO importance sampling

用 ratio 修正 off-policy；DLC先分离数值偏差。

02
GRPO

常用于 LLM RL；DLC提供异步/陈旧 rollout 稳定化。

03
IMPALA / V-trace

处理 actor lag；DLC额外建模推理数值差异。

04
verl async RL

提供系统管线；DLC是可嵌入的校正策略。

Abstract

Original Abstract Summary

The LLMFineTuningBench study analyzes 30,920 experiments across four GPU types and 1–32 GPUs, quantifying failure behavior, interconnect scaling and the relative value of system versus model-specific optimizations.

中文摘要

大规模 serverless 微调的性能并非只由 FLOPS 决定。该数据集显示 batch 增大显著提高失败率，RoCE 拓扑决定多机效率，而系统级优化可超过单一 MoE 优化。

Technical Analysis

Problem

缺少覆盖真实 failure、网络和多 GPU 伸缩的微调系统基准。

Method

Architecture

Experiments

为调度器、容量规划和容错研究提供比成功运行均值更真实的基线。

Limitations

Abstract

Original Abstract Summary

UpLoop trains a shallower model first, copies layers into a looped architecture, and spends the saved early-stage compute on repeated applications of shared blocks while matching a dense baseline in final parameters, tokens and FLOPs.

中文摘要

模型增长通常改变计算预算，难以公平比较。UpLoop 通过浅层起步节省计算，再把预算投入循环共享层，使最终参数、token 和 FLOPs 与 dense 基线严格对齐。

Technical Analysis

Problem

如何在不增加总训练预算下 upcycle 到更强的 looped architecture。

Method

shallow pretraining、layer copy、shared-block looping、compute accounting。

Architecture

1.3B 最终模型；训练早期层数更少，后期形成共享循环 block。

Key Innovation

把 architectural upcycling 变成 compute-neutral 的预算重分配。

Experiments

1.3B，22 个下游任务；与同参数/token/FLOPs dense baseline 对比。

Editorial Assessment

Why It Matters

为受固定训练预算约束的架构探索提供清晰可比方案。

Limitations

规模较小；loop inference latency 与 serving compatibility 未在摘要中展开。

Editor Note

训练收益明确，但部署端重复 block 的 KV/graph 行为需要另行评估。

Related Work

Abstract

Original Abstract Summary

Li²SAO presents a lightweight asynchronous online-RL method. It bootstraps with group-relative actor-critic estimates and then uses single-rollout generalized advantage estimation, reducing sampling requirements while retaining asynchronous throughput.

中文摘要

在线 RL 的 group sampling 成本高，异步又引入 policy lag。Li²SAO 用轻量 SAO 管线，在早期通过 group-relative 信号稳定价值估计，随后转向单 rollout GAE。

Technical Analysis

Problem

如何同时降低 rollout 数量并保持异步 RL 稳定性。

Method

group-relative bootstrap + single-rollout GAE + asynchronous actor-learner。

Architecture

actor、learner 和 rollout worker 解耦；代码已公开。

Key Innovation

把 group-based 相对估计作为过渡，而非永久承担多样本成本。

Experiments

来源报告称在多个 reasoning/agent tasks 上达到或超过 GRPO；摘要未披露可复核的统一硬件与精确 headline 数字。

Editorial Assessment

Why It Matters

rollout 常是 RL 系统最大成本，单样本路径可能直接提高 GPU 利用率。

Limitations

摘要证据数字不足；actor-learner lag 与 reward variance 的上限需正文验证。

Editor Note

代码公开提高复现性，但应重点审计与 GRPO 等算力基线是否严格等价。
