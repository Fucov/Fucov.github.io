Publish Date

v1 submitted 2026-11-10 19:37 UTC；first public listing 2026-11-13

Venue

arXiv:2611.14681；Together AI production research

Abstract

Original Abstract Summary

Together Compiler is presented as a continual agent loop for optimizing changing inference workloads. A tiered persistent engine separates engine startup from candidate forward-pass evaluation, while a cost model seeds parallelism configurations. The system reports higher experiment throughput and throughput gains across hand-written megakernels, frontier-model engine configurations, and production traffic.

Faithful English summary; not a verbatim abstract.

中文摘要

该系统让优化 agent 在不反复重启完整推理引擎的情况下热替换候选 forward pass，并用从少层快速引擎到多层高保真引擎的分层评测过滤候选；并行度成本模型同时考虑硬件、微基准、实测 forward 与真实流量分布。

Technical Analysis

Problem

新模型、流量分布和硬件持续变化，逐部署人工调 kernel 与并行策略不可扩展；只测独立 kernel 缺少数据相关性，重启端到端引擎又使实验吞吐过低。

Method

多 agent 通过共享消息板生成候选；Tiered Persistent Engine 热加载 forward pass；快速层级负责高吞吐搜索，慢速层级验证真实数据分布；成本模型为 TP、EP、DCP 等配置提供搜索起点。

Architecture

Traffic/model/hardware profile → cost-model seed → parallel agent proposals → hot-reload persistent engines → tiered fidelity measurements → production promotion；引擎进程、权重与 KV sizing 保持常驻，候选只替换执行路径。

Key Innovation

把“编译器搜索”与“生产引擎测量”合成在线持续闭环，并显式解决实验吞吐与测量保真度冲突，而非只生成单个离线 kernel。

Experiments

官方博客披露：完整引擎基线启动约 467 s，TKCC 路径约 9.0 s；评测覆盖 H100/B200、Llama 1B megakernel，以及 Kimi K3、GLM 5.3、MiniMax M3.1-Flash、DeepSeek v4.1-Flash 等 InferenceX/AgentX 配置。

Editorial Assessment

Why It Matters

真实推理平台的最优 kernel 与并行策略是流量分布函数。TKCC 把重新优化从季度工程项目缩短为持续系统过程，并已服务生产 token。

Limitations

核心生产系统与完整代码未公开；部分结果基于 InferenceX/AgentX 特定配置，Trainium2 使用合成多轮数据；无法独立复现实验吞吐与生产推广准则。

Editor Note

S 级。方法与生产影响突出，证据覆盖多模型多硬件；Reproducibility 因闭源实现明显扣分。

Related Work

02

共同点是用 agent 提议代码；TKCC 的新增量是分层测量、并行度成本模型与生产推广闭环。

03

这些是被优化的通用引擎；TKCC 不替代 serving control plane，而是持续重编其 forward path。

arXiv:2611.14904

Abstract

Original Abstract Summary

The work introduces an intra-GPU spatial execution model for memory-bound LLM decode. It partitions an operator graph into contiguous segments, assigns them to disjoint SM pools, and streams microbatches through the stages. A shared-resource simulator searches graph cuts, stage bindings, SM allocations and microbatch sizes, followed by a silicon feasibility experiment.

Faithful English summary; not a verbatim abstract.

中文摘要

论文把 decode 图切成连续段，每段绑定到独立 SM 池，并让微批次在段之间像流水线一样流动；搜索器联合决定切分点、阶段映射、SM 数量和微批次大小，同时建模共享内存带宽与缓存竞争。

Technical Analysis

Problem

短 decode kernel 对 SM 和 DRAM 带宽的占用呈突发性，纯时间复用会留下资源空洞；但错误的空间切分会引入争用和阶段不平衡。

Method

用分析型 shared-resource simulator 映射吞吐 Pareto frontier，再选定两阶段方案用 CUDA Green Contexts 和 TensorRT-LLM kernel 在实卡验证。

Architecture

Operator graph → contiguous segments → disjoint Green-Context SM pools → spatial stages → streamed microbatches；搜索器联合优化 graph cut、stage binding、SM allocation 与 batch。

Key Innovation

不同于多租户并发或单 kernel persistent fusion，本作在单请求的 operator graph 内建立可搜索的 GPU 内空间流水线。

Experiments

GPT-OSS 120B、32×B200 部署设定；模拟器搜索 Pareto frontier。实硅实验用 1×B200 模拟该部署，global batch 2,048、36-layer decoder、两阶段配置。

Editorial Assessment

Why It Matters

空间流水让内存受限与计算受限片段互补，提供比“整 GPU 串行跑 operator”更细的资源调度维度。

Limitations

大部分 Pareto 结果来自模拟；实卡仅验证一个两阶段点，且用单 B200 模拟 32 GPU 部署。代码与自动搜索器未披露。

Editor Note

S 级。概念清晰且有实硅闭环，但跨模型、跨 batch 和端到端在线 serving 证据仍有限。

Related Work

01
CUDA MPS/Green Contexts

共同点是空间划分 SM；本作把划分用于单 LLM 图的阶段化流水，而非一般并发隔离。

02
Pipeline parallelism

共同点是阶段流水；本作在单 GPU 内切 operator graph，通信和资源竞争模型完全不同。

03
Megakernel/persistent decode

共同点是减少调度空洞；megakernel 通过融合，本作保留多 kernel 并做空间重叠。

Abstract

Original Abstract Summary

The paper rebuilds a persistent expert-parallel MoE decode operator for SM120 consumer Blackwell GPUs. It uses warp-level block-scaled MMA, compact FP4 weights, adaptive token tiling, expert-granular streaming dispatch, batched pulls, deduplication and resident relay copiers to overlap token exchange and expert computation over PCIe.

Faithful English summary; not a verbatim abstract.

中文摘要

该工作不是简单移植 Hopper kernel，而是围绕 SM120 的 warp-level block-scaled MMA 重新安排 A/B 操作数、scale 选择、token tile、远端 expert 拉取缓存与返回通道，并把共享专家折入常驻计算角色。

Technical Analysis

Problem

低并发 EP decode 每层串行经历 dispatch、grouped GEMM、combine；消费级 Blackwell 经 PCIe 互连且缺少 SM100 的关键硬件机制。

Method

FP4 权重置于寄存器 A、FP8 activation 作为 B；专家粒度 streaming dispatch、批量 bulk-pull 与 64-bit 去重缓存减少 PCIe 往返，resident relay copier 排空 BF16 返回。

Architecture

Green-Context partitioned persistent CUDA Graph：network pull/dispatch role ↔ warp-level FP8×FP4 compute role ↔ resident return relay；position-major arena 管理全宽 BF16 结果。

Key Innovation

把面向 NVLink/数据中心 Blackwell 的 GC-MoE 重新构造成 PCIe/SM120 可用的端到端 persistent operator，而非只优化 GEMM。

Experiments

8×RTX PRO 5000、PCIe、18 个 decode 点；对比 FlashInfer CuTe DSL W4A8 MegaMoE 与 Cake MegaMoE；另含 shared-expert 融合，94 个数值案例、752 个逐 rank 检查。

Editorial Assessment

Why It Matters

展示消费级 PCIe 集群也能通过通信—计算协同获得 EP MoE decode 的系统级收益，并扩大 FP4 部署范围。

Limitations

只覆盖 SM120 与特定 8 卡 PCIe 拓扑；端到端服务层 SLO、功耗、故障恢复和代码开放状态未披露。

Editor Note

S 级。硬件约束驱动的重构扎实、数值验证完整；生态可复现性仍待代码。

共同点是 Green-Context persistent graph；本作新增 SM120 warp-MMA、PCIe pull 与消费级约束。

02
FlashInfer MegaMoE

共同点是低精度 grouped MoE；本作将 dispatch/compute/combine 融合为常驻图并实测更快。

03
DeepEP/Cake

共同点是 EP 通信；本作以专家流式拉取和返回 relay 针对低 token/rank。

Abstract

Original Abstract Summary

Parallel Prompting packs many questions about one document into a single request and decodes them as independent streams. A stream-ID attention mask inside the attention kernel prevents cross-answer leakage, while fixed decode shapes permit CUDA Graph capture. The implementation is a small overlay on two SGLang versions and includes code and raw results.

Faithful English summary; not a verbatim abstract.

中文摘要

方法把 P 个问题并排置于同一序列，在每步为每个问题生成一个 token；attention kernel 内的 stream-id mask 保证答案只看到文档与自身问题，从而把“每问题一次文档 KV 读取”变成“所有问题共享一次读取”。

Technical Analysis

Problem

prefix cache 只消除重复 prefill；多问题 decode 仍逐请求扫描同一长文档 KV，内存带宽随问题数线性增加。

Method

单请求多 stream 布局、无密集 mask 的 Triton attention 修改、固定形状 CUDA Graph；另提供可补充完成请求的 continuous engine。

Architecture

Document prefill once → question streams packed after document → per-step matrix-matrix decode → stream-ID masked attention → independent token outputs；SGLang overlay 修改约 80 行、三个现有文件。

Key Innovation

在 attention 访问级别共享文档 KV，而不是只复用前缀对象；保持答案条件独立且无需构造 O(n²) 密集 mask。

Experiments

CodeLlama-7B-Instruct，8k–16k 文档、64–256 问题、128 输出 token；A100-80GB 与 RTX A6000；SGLang 0.4.2/0.5.22，比较 stock FlashInfer/Triton+CUDA graphs，144 个配对运行。

Editorial Assessment

Why It Matters

共享长文档、多独立问答是评测、数据标注和 RL judge 常见形态；该方法直接降低最昂贵的 KV 带宽重复。

Limitations

当前是离线 engine，绕过 SGLang scheduler/server；仅 Triton backend、page size 1、单 GPU、greedy decoding；长答案会扫描 sibling answer token，收益收缩。

Editor Note

A+。开放代码、原始结果和等价性检查带来高可复现性，范围限制也披露充分。

Related Work

02
Batch prompting

共同点是文档只输入一次；区别是串行生成且后续答案可能看到前序答案。

03

Abstract

Original Abstract Summary

SlipStream is a software-hardware co-designed prefetcher for high-bandwidth flash memory. Software profiles repeatable weight-page demand and inserts a staging warp; hardware tracks 4 KB pages and retires staging entries only when demand consumes them, bounding producer lead and decoupling buffer size from outstanding traffic.

Faithful English summary; not a verbatim abstract.

中文摘要

软件侧记录数据无关 LLM kernel 的权重页访问顺序，由 staging warp 发出非阻塞 STAGE；硬件侧让工作 warp 的首次 demand 消费决定条目退休，从而避免超长 flash 延迟要求成比例扩大在途状态与缓冲。

Technical Analysis

Problem

HBF 容量和带宽接近 HBM，但近 20 μs 读延迟会让按需访问慢至 12.8×；cache-line prefetch 或按虚拟地址 tensor streaming 需要过多状态和缓冲。

Method

需求顺序 profiling、staging warp producer、work warp consumer、4 KB page tracking、返回后才分配 buffer slot，以及 demand-paced retirement。

Architecture

Profiled page stream → STAGE queue → HBF request tracking → small return buffer → demand-side consume/retire；producer lead 被真实 kernel 需求自然限制。

Key Innovation

将预取窗口从“时间/返回驱动”改为“消费驱动”，使缓冲规模不随 HBF 延迟和 workload 线性增长。

Experiments

7 个 dense 模型、16–800 GB 权重；HBF latency 约 HBM 的 20×；比较理想 HBF 与 H3；同时评测 MoE。主要结果来自体系结构模拟，硬件实现未披露。

Editorial Assessment

Why It Matters

若 HBF 成为 GPU 容量层，是否能以可接受 SRAM 成本掩盖 flash 延迟决定其能否实际承载大模型权重。

Limitations

结果依赖模拟和可重复、数据无关的权重访问；动态稀疏访问与真实 HBF silicon 行为尚待验证；代码未披露。

Editor Note

A+。体系结构洞察强、基准覆盖广，但实硅与开放实现不足。

共同点是从 HBF 流式读取权重；H3 按虚拟地址推进，本作按真实 demand 顺序与消费节拍推进。

02
Conventional cache-line prefetch

共同点是隐藏内存延迟；本作以 4 KB 页和 staging warp 降低 20×在途状态。

03

共同点是层次化权重存储；这些多依赖 host/SSD 调度，本作面向与 HBM 同带宽的封装级 HBF。

Abstract

Original Abstract Summary

Starscream studies LLM sharding on partitioned chiplet GPUs. It adds an intra-GPU sharding dimension orthogonal to inter-GPU sharding, guided by preserving kernel shapes, removing redundant memory, and minimizing flat collective overhead. Tensor parallelism is used as a case study on AMD MI300X and MI355X.

Faithful English summary; not a verbatim abstract.

中文摘要

现代多 die GPU 暴露 NUMA 内存域和逻辑分区，但传统框架把分区当作更多同质 GPU，导致权重冗余、算术强度下降和 collective 变长。Starscream 在 GPU 内与 GPU 间采用正交分片，并保持适合 kernel 的矩阵形状。

Technical Analysis

Problem

chiplet GPU 的内存和互连并非均匀；flat TP 在 partition 数增加时会复制数据、缩小 GEMM、增加通信。

Method

以 kernel shape preservation、redundancy elimination、communication minimization 三原则扩展 sharding；用 TP 案例展示 intra/inter GPU 两级结构。

Architecture

Physical Instinct GPU → NUMA-aware logical partitions → intra-GPU shard groups；multiple GPUs → inter-GPU groups；hierarchical collectives 代替单层 flat collective。

Key Innovation

把 GPU partition 从部署隔离手段提升为并行策略的一等轴，并把 kernel 算术强度与 NUMA locality 纳入分片设计。

Experiments

AMD MI300X 与 MI355X；attention 与 fused GEMM micro/ operator evaluation；对照为 chiplet-oblivious partitioned sharding。模型、batch 和端到端服务条件未在摘要披露。

Editorial Assessment

Why It Matters

随着单卡 die 数增加，框架必须区分“卡内分区”和“卡间 rank”；Starscream 提供可迁移的分层并行原则。

Limitations

摘要缺少端到端 TPS/TPOT、模型和规模细节；代码未披露；结论主要以 TP 案例验证。

Editor Note

A+。面向未来 GPU 拓扑的重要设计信号，但端到端证据与复现材料不足。

Abstract

Original Abstract Summary

The paper studies host-memory KV restoration on a commercial static-graph NPU stack where copy operations share an engine thread with prefill and decode. It implements a synchronous host tier using public runtime APIs and builds a scheduler-aware event model frozen before each cohort, then evaluates chain, fork, mixed and bursty agent workflows.

Faithful English summary; not a verbatim abstract.

中文摘要

论文指出“从 host 恢复 KV”不是天然更快：copy 会与 prefill/decode 争用同一 engine thread。作者在 Rebellions ATOM+ 上实现主机 DRAM 层，并用调度事件模型预测容量收益和尾延迟代价。

Technical Analysis

Problem

设备 KV 预算固定，agent 共享前缀在压力下被逐出并反复重算；host restore 节省算力但会占用引擎线程。

Method

公共 KV copy API 实现同步 spill/restore；scheduler-aware event model 在测试 cohort 前冻结，用于选择恢复/重算策略并预测 P50/P99。

Architecture

Qwen3-8B planner on 2 cards + Qwen3-0.6B executor on 1 card；device KV ↔ host DRAM tier；copy、prefill、decode 串行进入静态图 runtime engine。

Key Innovation

把 restore 决策建模为调度/传输/容量联合问题，并用预先冻结的事件模型避免事后拟合。

Experiments

Rebellions ATOM+，vllm-rbln 0.10.2；planner 两卡、executor 一卡；chain/fork/mixed/bursty workload，多 seed 与 common-load 条件。

Editorial Assessment

Why It Matters

为非 GPU 静态图加速器提供了可操作的 host KV 判断边界，也说明容量层必须与 scheduler 建模协同。

Limitations

仅一个商业 NPU stack；同步 copy 与单 engine thread 限制强；mixed/bursty 对 seed 敏感，fork P99 增加 16–18%。代码未披露。

Editor Note

A+。测量纪律和负面结果很有价值，外部通用性仍需更多 runtime。

Abstract

Original Abstract Summary

The report coordinates inference and environment execution for batched agent tasks used in evaluation, synthetic data and RL rollouts. A workload model allocates memory between KV cache and recurrent state, trajectory-aware routing improves reuse and load balance, and Chain-Advancing Action Scheduling prioritizes long chains under constrained environment capacity.

中文摘要

作者不只优化模型 server，而是把 agent trajectory 在推理 worker 与外部环境之间的交替过程作为同一 makespan 问题：先估计混合模型状态占用，再路由轨迹以保留 cache，最后按已观察进度推进长链。

Technical Analysis

Problem

agent batch 的完成时间由最慢 trajectory 决定；推理和环境交替造成 GPU 空洞、cache 丢失和受限环境队列尾部。

Method

workload-based KV/recurrent-state allocation、reference concurrency、trajectory-aware routing 与 scheduling；环境侧解耦 sample admission，用 CAAS 优先推进长链；controlled replay 做因果消融。

Architecture

Batch admission → trajectory router → hybrid-model workers (KV + recurrent state) ↔ bounded environment executors → CAAS progress queue → completed batch；replay 注入真实推理与记录环境时延。

Key Innovation

把 hybrid LLM 状态内存、cache affinity 和环境资源调度联合到批次 makespan 目标，而非只看 server token throughput。

Experiments

Ling-3.0-Flash 与 Ling-3.1-Flash；BFCL、SWE-bench Multilingual、WideSearch、MCP-Atlas；live evaluation 加 controlled replay，结果用于 Ling-3.x 训练与评测流程。硬件规模未在摘要披露。

Editorial Assessment

Why It Matters

RL rollout、合成数据和 agent benchmark 都以整批完成时间决定迭代速度；环境调度常是现有 serving 论文忽略的尾部来源。

Limitations

硬件、并发、各优化单项贡献与代码未在摘要完整披露；针对 Ling hybrid 模型的状态模型未证明可直接迁移至 dense Transformer。

Abstract

Original Abstract Summary

The paper directly measures expert transfers for OLMoE-1B-7B in a real CPU-to-GPU copy harness. Policies that freeze routing reduce copies but raise next-token loss. A farthest-next-use eviction rule preserves every routing decision, copies fewer experts than LRU, and approaches the offline minimum; a limited future window recovers most of the gain.

中文摘要

作者把“路由切换次数”与“真实专家复制次数”分开测量。所有比 LRU 更快的固定 expert-set 路由策略都带来至少 0.067 nat loss；相反，Belady 式最远未来淘汰只改变 cache policy，不改变模型路由。

Technical Analysis

Problem

CPU offload 的瓶颈是专家 H2D 复制；现有方法训练路由保持稳定，但可能以质量换传输。

Method

在真实 copy harness 中比较 LRU、固定 expert-set 和 oracle farthest-next-use；再限制未来 token 窗口，评估可预测性要求。

Architecture

Router emits unchanged expert demand → GPU expert cache → eviction policy chooses victim → missing expert copied from CPU → OLMoE decode；质量与复制时间分别计量。

Key Innovation

把性能优化放在 eviction 而非 routing，明确实现“零质量变化”的传输减少，并量化未来需求窗口价值。

Experiments

OLMoE-1B-7B、NVIDIA L40S、真实 CPU→GPU copies；比较 LRU、固定路由策略、offline minimum 与不同未来窗口。代码和 traces 开放。

Editorial Assessment

Why It Matters

为 MoE offload 提供质量不变的明确上界，也提示 speculative routing/未来 token 预测可直接转化为 cache 收益。

Limitations

oracle 需要未来请求；16-token 未来窗口如何在线获得未解决；只评测一个模型和 L40S，端到端多用户 serving 未披露。

A+。问题小而清晰，开放材料和负面结果提高可信度；系统规模有限。

Abstract

Original Abstract Summary

SS-HSDP separates runtime parameters used by training kernels from update parameters used by optimizers. Shared views and hierarchical sharding organize the two representations independently without redundant movement, supporting matrix optimizers and zero-copy execution. Evaluations cover video and language models with MXFP8 and compare FSDP2, veScale-FSDP and Megatron-FSDP.

Faithful English summary; not a verbatim abstract.

中文摘要

传统 FSDP 让训练 kernel 的 packed layout 与优化器的矩阵/参数单元相互绑定。SS-HSDP 维护共享底层数据的运行时视图和更新视图，并用层次分片管理二者所有权，从而避免为了优化器重排而破坏高效 kernel。

Technical Analysis

Problem

高效 kernel 偏好 packed/quantized layout，而 Muon 等优化器要求特定矩阵单元；同一参数表示同时满足两者会带来拷贝或限制优化器。

Method

runtime/update parameter decoupling、shared data views、hierarchical sharding 与 fully zero-copy execution；优化器在自身 unit 上更新，runtime 读取适合 kernel 的布局。

Architecture

Global parameter storage → hierarchical shard ownership → runtime view (packed MXFP8 kernels) + update view (optimizer units) → synchronized shared backing；通信按层级聚合。

Key Innovation

把参数“执行表示”和“更新语义”变成正交抽象，在同一 sharded DP 框架内支持高效低精度 kernel 与矩阵优化器。

Experiments

视频与语言模型，MXFP8 training；对比 PyTorch FSDP2、veScale-FSDP、Megatron-FSDP；最高 128 GPUs。具体 GPU 型号、模型规模和完整配置未在摘要披露。

Editorial Assessment

Why It Matters

低精度训练和矩阵优化器正在同时普及；若框架把 layout 与 optimizer unit 绑死，任何一端的创新都会引入重排成本。

Limitations

摘要未披露代码、硬件型号与各模型分项；需要验证 shared views 的一致性、checkpoint 格式和故障恢复。

Editor Note

A+。抽象对未来 FSDP/DTensor 生态重要，性能证据有规模；可复现性和正确性细节待补。
