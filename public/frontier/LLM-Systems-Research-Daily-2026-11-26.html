arXiv:2611.33542v1 · cs.DC / cs.AI / cs.LG

One-line Summary

按 prefill 的最大 token 负载和 decode 的最大活跃专家数分别优化 EP rank，在不复制专家的情况下缓解最慢 rank 同步瓶颈。

Abstract

ORIGINAL ABSTRACT SUMMARY · EN

RankCast treats MoE imbalance as two different rank-level optimization problems. Prefill steers flexible lower-ranked expert assignments with per-rank prices, while decode closes low-cost experts on the busiest ranks. Protected top experts and bounded candidate sets limit quality loss, and the implementation overlaps routing prediction and metadata exchange with SGLang/DeepEP execution.

中文摘要

MoE 服务的 prefill 与 decode 具有不同瓶颈：前者偏计算，取决于最忙 rank 的 token 数；后者在中等 batch 下偏内存，取决于每个 rank 激活的专家数。RankCast 保留每个 token 的高置信专家，仅在 Top-L 候选中调整其余选择，并复用 DeepEP 通信通道传输紧凑元数据。

Technical Analysis

PROBLEM

EP 层必须等待最慢 rank；静态 placement、replication 与 prefetch 需要额外 HBM 或专家权重搬运，且无法跟踪瞬时负载。

METHOD

跨层预测下一层路由。Prefill 通过分布式直方图形成 rank price；decode 在满足 protected-prefix 与候选约束下关闭拥挤 rank 的低成本专家。

ARCHITECTURE

SGLang serving path + DeepEP dispatch/low-latency path；side stream 预测 gate score；prefill price solver 与 decode expert-shedding solver；元数据搭载在现有 token-count 消息中，不增加独立 collective。

KEY INNOVATION

把 MoE serving 的负载均衡从统一 token-count 目标拆成 phase-aware 的两个物理 rank 目标，并把质量约束显式写入 rerouting。

EXPERIMENTS

Qwen3-235B-A22B（EP=8）与 Qwen3.5-397B-A17B（EP=16），在 SGLang 与 DeepEP 上端到端测试；论文披露模型、EP 规模与框架，完整 GPU 型号/集群拓扑未在摘要中披露。

KEY RESULTS · SOURCE-REPORTED

来源报告：最忙 rank 的 excess prefill load 降低超过 75%；prefill input throughput 最高提升 19%；decode TPOT 最高降低 10%；质量代价低于 1 个百分点。不同模型/阶段的最大值不可合并为单一加速。

Editorial Assessment

WHY IT MATTERS

它直指大规模 MoE 服务的同步尾部：避免以复制专家挤占 KV cache，也避免在热路径搬运专家权重。

LIMITATIONS

需要预测下一层路由并允许低排名专家重路由；质量界依赖候选集与模型；硬件拓扑、跨节点网络和更高并发下的完整结果仍需验证。

EDITOR NOTE · ANALYSIS

含金量高。对生产 MoE serving 而言，核心价值不是一个新 router，而是把 prefill/decode 的成本模型分开并落到现有 SGLang+DeepEP 数据路径。

Related Work

01

DeepSeek EPLB

共同点：都处理 MoE 专家负载失衡。

核心区别：EPLB 调整专家 placement/replication；RankCast 在 serving 热路径调整低排名路由。

新增量：用候选约束换取瞬时 rank balance，减少副本 HBM。

02

DeepEP

共同点：都使用 EP dispatch/combine 通信。

核心区别：DeepEP 是通信库；RankCast 复用其通道传递 balancing metadata。

新增量：在不新增 collective 的前提下加入 phase-aware solver。

03

SGLang

共同点：都面向高吞吐 LLM serving。

核心区别：SGLang 提供 runtime；RankCast 是其 MoE 路由平衡扩展。

新增量：将 rank price 与 expert shedding 接入现有执行流。

arXiv:2611.34615v1 · cs.DC / cs.PF

One-line Summary

用“宽 token batch、浅 layer slice、独立 row-group transport”打破 chunk size 同时控制计算、抢占延迟和网络包大小的耦合。

Abstract

ORIGINAL ABSTRACT SUMMARY · EN

PipeAxes serves long-context models over PCIe and heterogeneous clusters by running wide prefill batches through only a few layers at a time. A fused Triton Hadamard-INT4 codec and independently sized row groups reduce activation traffic, while a slack-aware scheduler selects batch width, slice depth and transport granularity independently.

中文摘要

传统 chunked prefill 用一个 chunk size 同时决定 GPU batch 宽度、decode 可插入间隔与跨 stage 传输大小，导致小 chunk 重复加载权重、大 chunk 阻塞交互请求。PipeAxes 将 token 宽度、layer slice 深度和通信 row group 三轴拆开，再依据 latency slack 动态选择。

Technical Analysis

PROBLEM

在 PCIe 或弱网络上的 PP serving 中，prefill chunk 太小造成权重重复加载，太大又使 decode 和短请求长期等待。

METHOD

宽 batch 仅运行少量层后让出 GPU；融合残差与 hidden state 后做 Walsh–Hadamard INT4 压缩；通过并行 TCP socket 以独立 row group 发送；scheduler 依据 SLO slack 调参。

ARCHITECTURE

vLLM 0.23.0 V2 engine；layer-sliced prefill、独立 decode CUDA Graph、terminal inline sampling；Triton H-INT4 codec；row-group priority transport；deadline admission control。

KEY INNOVATION

将计算粒度、GPU 让出粒度和网络传输粒度从单一 token chunk 中解耦，使每一轴都能按硬件与 SLO 优化。

EXPERIMENTS

97 次配对 replay、5,016 个请求；Qwen3-8B/30B-A3B/32B；双 PCIe A800 80GB，以及 RTX 4090→RTX 3090 跨节点；网络 100–1000 Mbps、最高 30 ms RTT；长上下文至 64K。

KEY RESULTS · SOURCE-REPORTED

来源报告：四 stage MoE pipeline 的 SLO goodput 为 calibrated Revisit-PP 的 23.3×、Fixed-4096+Express 的 4.44×；混合 64K workload 中短请求 p95 TTFT 从 native vLLM 的 129.8 s 降至 512 ms。INT4 相对 BF16：MMLU +0.06pp、GSM8K -0.46pp。

Editorial Assessment

WHY IT MATTERS

它把低带宽、异构 GPU 环境的 serving 问题从“调一个 chunk size”提升为三轴资源调度，结果同时覆盖 latency、goodput 与质量。

LIMITATIONS

依赖 PP 划分和 TCP transport；结果集中在 Qwen3 与特定 SLO；INT4 质量和 codec 收益可能随模型、hidden size 与网络变化。代码链接未在 arXiv 页面确认。

EDITOR NOTE · ANALYSIS

系统证据完整，尤其是 97 个 replay 和明确 SLO。23.3× 是特定四阶段 MoE/WAN 对照，不应外推为通用 vLLM 加速。

Sarathi-Serve

核心区别：Sarathi 主要调 token chunk；PipeAxes 解耦 layer slice 与 transport row group。

新增量：在异构 PP/WAN 下独立优化三种粒度。

02

Revisit-PP

共同点：都面向 pipeline serving 的交互延迟。

核心区别：Revisit-PP 预测 token chunk；PipeAxes 保持宽 batch 并切 layer。

新增量：减少重复权重加载，同时保留 decode 插入点。

03

vLLM

共同点：都使用 continuous batching、chunked prefill 与 CUDA Graph。

核心区别：vLLM 是 baseline runtime；PipeAxes 改写 PP prefill/transport 调度。

新增量：加入 H-INT4 与 slack-aware multi-axis control。

One-line Summary

不再给 draft 与 target 相同 prompt，而给 draft 任务相关示例，使其从“求解”转为“模仿”，在保持 exact sampling 的同时提高接受率。

Abstract

ORIGINAL ABSTRACT SUMMARY · EN

AsymSpec attributes low speculative-decoding acceptance on hard tasks to forcing a small draft model to solve the same problem as the target. It gives the draft model auxiliary solved examples while keeping the target prompt unchanged, amplifying the alignment that normally emerges from verified tokens. The paper proves exact sampling and exponential convergence.

中文摘要

论文观察到生成越往后 acceptance 越高，并以受控上下文实验把这一现象归因于 draft 模型从已验证 token 中进行上下文学习。AsymSpec 通过非对称 prompt 将 draft 的目标从推理改为模拟 target 的解题轨迹，无需训练新 drafter。

Technical Analysis

PROBLEM

标准 speculative decoding 的 draft/target 接收相同任务；小 draft 在推理任务上能力不足，拒绝率高，理论并行收益无法兑现。

METHOD

为 draft 加入检索到的示例解答或多视角自前缀，target 保持原始 prompt；验证与 rejection sampling 不变，并给出分布精确性证明。

ARCHITECTURE

双 prompt、双 KV cache；draft 生成候选，target 并行验证；可配合 prefix caching 缓解公共示例的 prefill 成本。

KEY INNOVATION

把 speculative decoding 的能力差距转化为 prompt/objective asymmetry，并显式利用 draft 的 in-context alignment，而不是训练额外 head。

EXPERIMENTS

nano-vLLM/PageAttention 实现；RTX 4090 与 RTX A6000；MATH-500、AIME 2025、HumanEval、CNN/DailyMail、MT-Bench；覆盖 Qwen3-8B 到 Llama-3.1-70B，并与标准 speculative、SSD、EAGLE-3 比较。

KEY RESULTS · SOURCE-REPORTED

来源报告：相对 autoregressive decoding，Qwen3-8B 平均 2.29×、Llama-3.1-70B 最高 4.95×；覆盖 reasoning、code、summarization。最大值对应不同模型/任务，不代表统一配置。

Editorial Assessment

WHY IT MATTERS

它无需训练即可改善高难任务的 draft acceptance，并保留精确采样，适合已有大小模型组合快速试验。

LIMITATIONS

draft 增加辅助输入并维护独立 KV cache，内存相对标准 speculative decoding 近似翻倍；长示例会反噬带宽与 prefill；完整代码尚承诺“upon publication”，当前未核实公开。

EDITOR NOTE · ANALYSIS

观点新颖，但生产价值取决于 exemplar 选择、缓存命中和双 KV 的内存账单。首先应复现实例长度—接受率—吞吐的三方曲线。

核心区别：经典方法给两者相同任务；AsymSpec 给 draft 辅助示例。

新增量：把 prompt asymmetry 作为新的 acceptance 杠杆。

02

EAGLE-3

核心区别：EAGLE-3 训练 target-aware drafter；AsymSpec 无训练、靠 ICL。

新增量：用现成小模型即可部署，但付出额外 KV。

03

共同点：都并行提出多 token。

核心区别：Medusa 增加并训练 decoding heads；AsymSpec 保持独立 draft model。

新增量：无需修改 target 权重或增加 head。

FlyingStart：循环深度语言模型固定点解码的跨 token 学习式热启动 · Recurrent Depth / Fixed-point Decoding / Warm Start / Self-speculation

AUTHORS

Runguo Li, Dezhen Lu, Zixiang Ni

INSTITUTIONS / LABS

University of Illinois Urbana-Champaign；University of Tübingen；Xi’an Jiaotong University

PUBLISH DATE

v1 submitted 2026-11-25 14:51:50 UTC；first public arXiv new-list: 2026-11-26

VENUE

arXiv:2611.34492v1 · cs.CL / cs.LG

One-line Summary

用上一 token 的收敛状态和当前 prelude 输出预测更好的初始状态，在不改变停止准则与精度目标的情况下少跑循环层。

Abstract

ORIGINAL ABSTRACT SUMMARY · EN

FlyingStart fits a closed-form linear map on a frozen recurrent-depth model to initialize each token from the previous token’s converged state and the current prelude output. The original iteration and stopping rule remain unchanged, so savings come from starting closer to the fixed point rather than weakening convergence criteria.

中文摘要

循环深度模型通常让每个 token 从随机噪声开始迭代至固定点。FlyingStart 发现相邻 token 的固定点在坐标变换后可预测，以闭式线性映射构造热启动；映射成本低于一次 loop 的 5%，且可与 self-speculative decoding 叠加。

Technical Analysis

PROBLEM

动态深度方法只决定何时停止，却忽略每个 token 从哪里开始；随机初始化重复支付收敛成本。

METHOD

在冻结模型上用 480 条 Wikipedia 与 160 条 GSM8K-train 序列拟合线性映射，将前一 token exit state 与当前 prelude output 映射为初始 state。

ARCHITECTURE

prelude → learned linear warm start → shared recurrent block 迭代 →原有 state-change exit；每个 token 只保留一个 KV entry；可接 WaveFront self-speculation。

KEY INNOVATION

把 fixed-point decoding 的初值作为独立系统杠杆，并以 contraction analysis 预测可节省的 loop 数。

EXPERIMENTS

Huginn-0125 及四个模型；RTX 3090/H100/RTX 6000 Ada/RTX A4500；四项数学任务、GSM8K、BBH、IFEval、Spec-Bench；自研 engine 与 CDB engine。

KEY RESULTS · SOURCE-REPORTED

来源报告：Huginn 在相同精度下少 14–19% decoding layers；两套 serving engine 的 batched throughput 提升 16–18%；叠加 WaveFront 再提升 10–14%。映射开销为 Huginn 一次 loop 的 3.6%（另一 Llama 模型 4.6%）。

Editorial Assessment

WHY IT MATTERS

对 recurrent-depth 模型，它提供一个训练后、低风险的推理优化，并保持原有收敛证书与 stopping rule。

LIMITATIONS

收益随模型收敛速度而变，快速收敛模型空间较小；线性映射增加参数与校准流程；结论主要围绕 Huginn，常规 Transformer 不适用。代码公开状态未在 arXiv 页面确认。

EDITOR NOTE · ANALYSIS

这是架构特定但干净的优化：没有放宽停止条件。应关注 calibration domain shift 与 map 在多会话/长上下文上的稳定性。

核心区别：Huginn 定义模型；FlyingStart 优化其 token 初始状态。

新增量：无需重训 backbone 即可少跑 loop。

共同点：都按 token/层动态减少计算。

核心区别：Early exit 放宽或选择停止点；FlyingStart 保持停止规则、改变起点。

新增量：固定点距离证书保持不变。

03

WaveFront

共同点：都加速 recurrent-depth decoding。

核心区别：WaveFront 使用 self-speculation；FlyingStart 提供 warm start。

新增量：两者可叠加，论文报告额外 10–14%。

One-line Summary

用 HSM 暴露多步 MTP 状态混合、用 HSGD 随机阻断隐藏状态梯度，在不增加推理成本的情况下缩小 drafter 的训练—推理错配。

Abstract

ORIGINAL ABSTRACT SUMMARY · EN

The paper targets the mismatch between training tail-augmented drafters on backbone or one-step MTP states and using them autoregressively on recurrently generated MTP tails. Hidden State Mixing samples aligned backbone/MTP states across steps; Hidden State Gradient Detach regularizes state and embedding paths while leaving the forward pass unchanged.

中文摘要

MTP/EAGLE 类 drafter 在推理时会看到越来越长的自生成隐藏状态尾部，但训练时通常只看到 backbone 或单步 MTP 状态。HSM 以对齐同一预测目标的多来源状态进行混合，HSGD 随机停止隐藏状态与 embedding 路径的梯度；两者都是仅训练时方法。

Technical Analysis

PROBLEM

自回归 drafter 的 rollout 状态分布与训练输入不一致，导致后续 draft 位置接受率下降；显式 TTT 又增加显存与特殊 mask。

METHOD

HSM 在 backbone 和不同 MTP step 的对齐隐藏状态中采样；HSGD 随机 detach 状态/embedding 梯度但保留 forward；覆盖联合预训练+SFT与冻结 backbone 的 MTP boosting。

ARCHITECTURE

Backbone hidden states → shared-parameter MTP module；HSM state sampler 或 HSGD gradient gates；SFT/boosting；推理仍用原 MTP/EAGLE drafter，无额外 runtime operator。

KEY INNOVATION

用简单的状态分布扰动/梯度正则替代显式模拟完整推理尾部，并揭示 HSGD 偏早期位置、HSM 偏长 draft tail 的互补性。

EXPERIMENTS

四个 Nemotron 模型、DeepSeek-V4-Pro、Qwen3-8B EAGLE-3；SPEED-Bench qualitative split。预训练最长 128K context、global batch 128（约 16.78M tokens/update）、8-way context parallel；具体 GPU 型号未披露。

KEY RESULTS · SOURCE-REPORTED

来源报告：冻结 backbone 的 HSM MTP boosting 相对共训 MTP，mean acceptance length 最高 +52.2%；Qwen3-8B 四步 EAGLE-3 对比中，HSM 与 TTT 接受率相当，peak reserved training memory 低 48%。不同实验条件的最大值不合并。

Editorial Assessment

WHY IT MATTERS

直接作用于 speculative decoding 的训练瓶颈，并已在 Megatron-LM 与 NVIDIA Model Optimizer 提供实现，复现与落地路径清晰。

LIMITATIONS

硬件与完整训练成本未披露；52.2% 来自特定模型/boosting 条件；acceptance 增益不等价于端到端吞吐；对非 tail-augmented drafter 不适用。

EDITOR NOTE · ANALYSIS

含金量高，尤其是“训练改动、零推理开销”。HSM/HSGD 的最佳选择取决于生产使用的 draft length 与 verification 成本。

One-line Summary

以匹配参数、FLOPs 与 KV cache 的非重复访问对照，发现 looped MoE 的大部分收益来自网络形状、优化器和额外计算，而非参数 revisit 本身。

Abstract

ORIGINAL ABSTRACT SUMMARY · EN

LoopTitan isolates parameter revisiting from the shape, expert layout and residual scaling changes that accompany looped MoE recipes. Matched non-revisit controls retain the reported gains, while Muon removes the residual-scaling advantage seen under AdamW. The project releases code, 17 models and an auditable run record.

中文摘要

Looped MoE 常把“重复访问参数”与更深更窄的网络、专家布局和 residual scale 一起改变。LoopTitan 用逐项构造与匹配预算的非 revisit 对照拆解这些因素：revisit 本身几乎无增益，网络形状贡献最大；residual scale 在 AdamW 下像降低有效学习率，在 Muon 下优势消失。

Technical Analysis

PROBLEM

此前 looped MoE 对照没有隔离 network shape、residual scale 与 optimizer，难以判断参数复用是否真是收益来源。

METHOD

在参数、训练 FLOPs、KV cache ±5% 范围内建立 non-revisit twin；按 recipe 逐项加入 shape/layout/scale/revisit；在 AdamW 与 Muon、不同模型规模和 token 预算下重复。

ARCHITECTURE

统一 LoopedLM 配置模型；38 种配置、九类已发表 looped recipe；TorchTitan native FSDP；AdamW/Muon；预算 checker、Qwen3-MoE conformance、exact resume、HF export。

KEY INNOVATION

不是再提出一个 looped 结构，而是用严谨控制实验推翻“revisit 是主要增益”的归因，并提供可审计基础设施与更强 LoopTitan-Base。

EXPERIMENTS

1.3B–3.0B stored parameters，5B–24B training tokens；主要 Phase-1 表格为 1.3B、5B tokens、三 seed；DCLM；17 个预训练模型、482 runs/12 studies；训练 GPU 型号未在已核实页面披露。

KEY RESULTS · SOURCE-REPORTED

来源报告：matched budget 下 non-revisit control 保留全部 gain；Muon 下 residual scale 收益消失；额外一次 visit 的收益中，等参数等计算的更深标准 MoE 获得 90.2%；LoopTitan-Base 在 Muon 下与最强 looped recipe 相差 0.2 mBPB。

Editorial Assessment

WHY IT MATTERS

它改变了 looped MoE 的研究基线：未来工作必须与 matched non-revisit control 和强 optimizer 对比，而不是把 shape/scale 收益归因于循环。

LIMITATIONS

规模仍远小于前沿超大 MoE；结论针对所测 recipe/optimizer；训练 GPU 与系统吞吐未披露；Phase 1 仍需更大规模与下游能力验证。

EDITOR NOTE · ANALYSIS

本期 Must Read。技术价值来自因果拆解、公开对照与可复现协议，而不只是模型分数；也提醒 scaling-law 结论必须先校正架构自由度和 optimizer。
