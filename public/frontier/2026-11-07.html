Abstract

Original Abstract Summary

This prerelease integrates a broad set of serving-runtime changes: foundations for a unified KV manager and host-backed pools; Helix and attention-data-parallel KV movement; percentile-aware admission; native sparse MLA; dynamic expert-load balancing; new speculative-decoding paths; and production-facing OpenEngine and API updates. The release also lists unresolved correctness and warm-up risks for selected model, KV-format, CUDA-graph, and worker-reuse combinations.

中文摘要

这一版本的主线不是单个 kernel，而是让 KV 状态、解耦传输、调度、稀疏 attention、MoE 与推测解码在同一服务运行时中继续合流。统一 KV 管理器加入 sparse-attention arena 与 host-backed pool；Helix 与 attention DP 增加按 view 的 KV head 传输和 owner-only 写入；调度器增加 TTFT 分位准入。由于仍是 rc3，已知问题必须与功能清单一起阅读。

Technical Analysis

Problem

大模型服务在 KV 生命周期、PD/Helix 传输、稀疏 attention、MoE 负载与 frontend 扩展上存在多套局部路径；当这些路径叠加时，容量、调度、通信所有权与可观测性容易脱节。

Method

统一 KV 管理基础；sparse arena 与 host pool；attention-DP connector、per-view KV-head transfer 与 owner-only MLA write；TTFT-percentile admission；原生 sparse MLA/DSA；DynamicEPLB；vocabulary-parallel selection 与 DSpark verification。

Architecture

TensorRT-LLM PyTorch runtime / Modeling V2 / OpenEngine；面向 Blackwell 等 NVIDIA GPU；覆盖 context–generation disaggregation、Helix、attention DP、expert parallelism、CUDA graphs、FlashInfer 互操作和多 frontend 服务。

Key Innovation

新增量在于把跨层状态管理与通信语义沉入一个版本化运行时：KV 分配、传输 ownership、准入、稀疏计算与 MoE 平衡不再只是彼此独立的可选 patch。

Experiments

Release notes 没有披露统一实验矩阵。部分变更指向 GB300/SM100/SM103/SM107、Kimi K3、DeepSeek-V4、GLM、MiniMax 与 Qwen，但硬件规模、请求分布、对照与统计条件分散在 PR 中；本报告不据此给出综合加速。

Editorial Assessment

Why It Matters

这类整合版本决定研究型 KV、稀疏 attention、MoE 与 speculative decoding 能否进入生产服务主干。尤其值得关注 TTFT-aware admission 与 Helix ownership，它们把性能优化与 SLO/正确性约束直接相连。

Limitations

仍是 prerelease；官方列出 NVFP4 KV correctness、Kimi K3 + CUDA graph warm-up hang、DeepSeek-V4-Pro OOM 与 MPI worker reuse hang 等已知问题。缺少统一基准，且多项能力仅适用于特定模型或 GPU 架构。

Editor Note

含金量来自系统整合与开放代码，而非一组漂亮的峰值数字。A+ 而非 S：代码和变更证据强，但 rc 状态、已知问题与缺少统一实验口径显著降低证据与复现评分。

Related Work

01
vLLM

共同点：Paged KV、continuous batching、speculative decoding 与广泛模型支持。区别：TensorRT-LLM 更深绑定 NVIDIA kernel/quantization/runtime 路径；本次新增统一 KV/Helix ownership 与 OpenEngine 集成。

02
SGLang

共同点：prefix/KV reuse、结构化执行与高性能服务。区别：SGLang 以语言/runtime 与 RadixAttention 为中心；本次版本聚焦 NVIDIA 设备级 KV、稀疏 attention 和 Modeling V2。

03
LMCache

共同点：跨层 KV 管理与 host tier。区别：LMCache 是可插拔 KV 存储/传输层；本次新增量是把 host pool、Helix/attention-DP 传输和 scheduler 直接纳入 TensorRT-LLM 引擎。

04
DistServe / Splitwise

共同点：context–generation 解耦。区别：早期工作强调资源池与阶段隔离；本次版本增加 Helix 聚合 KV、owner-only 写入、per-view head transfer 与失败联动取消。
