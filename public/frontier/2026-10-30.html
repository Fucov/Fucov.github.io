Abstract

Original Abstract Summary

The paper introduces Conflux Parallelism, which co-executes prefill and decode while assigning different sequence/tensor parallel layouts at operator granularity, and builds an SLO-aware scheduler around it.

中文摘要

ConfluxServe 观察到 prefill 偏计算、decode 偏带宽，但二者的最优并行度并不相同；它只在适合的线性算子上合批，在 attention 处保持阶段化执行，并以 TTFT/TBT 约束最大化 goodput。

Technical Analysis

Problem

传统 co-batching 要求统一并行配置，阶段分离又浪费互补资源。

Method

XP 在算子级组合不同 SP/TP，调度器联合 admission、prefill chunk 与 decode placement。

Architecture

基于 vLLM 0.15.1，复用 PagedAttention/CUDA Graph/Ulysses-SP；线性层 co-batch，attention 分相位，KV aliasing 与 layer-wise transfer 处理切换。

Key Innovation

并行配置不再绑定 serving instance 或 batch，而成为 operator-level execution path。

Experiments

4×H100 SXM5 80GB（Llama-8B/Qwen-14B）与 8×H100（Qwen-32B），Mooncake/Qwen traces；对比 Chunked Prefill、DistServe、LoongServe、MuxWise，统一 TTFT/TBT SLO 与 GPU 数。

Editorial Assessment

Why It Matters

对 TP8/B300 生产 serving 很直接：prefill/decode 异构并行不必等价于物理 PD 拆分。

Limitations

仅单 XP instance；全局 routing 未实际运行；代码未确认公开。

Editor Note

值得关注其与现有 PD disaggregation、DCP/EP 混合部署的集成复杂度。

Related Work

Abstract

Original Abstract Summary

FlatCake argues that production KV reuse is bimodal and defeats DRAM-as-cache assumptions. It directly places immutable KV blocks on their target medium and streams sequential SSD reads through bounded GPU windows.

中文摘要

FlatCake 利用 KV block 写一次、不可变、按 session 共同复用的性质，取消 DRAM staging/migration；数据按 session-contiguous、layer-major 排列，通过 GDS 直接流入有限 GPU window。

Technical Analysis

Problem

DRAM staging 争用和 eviction-order SSD 布局导致 prefetch abort、读放大和碎片化。

Method

统一 64-bit 地址空间、creation-time placement、媒体独立队列、合并顺序 SSD 读取。

Architecture

SGLang 集成；GPU HBM 为一级，DRAM/NVMe 为 peer backend，GDS 将 SSD 数据直接送入 GPU window。

Key Innovation

不再把 DRAM 当 NVMe 的中间缓存，而把 KV 生命周期和 session 空间局部性直接编码到布局。

Experiments

生产 Claude Code trace + DeepSeek-V4-Flash/多卡 B200；另用 Llama-3.1-70B/A100 覆盖 8K–128K context，对比 Mooncake、Mooncake-GDS、recompute。

Editorial Assessment

Why It Matters

它重新定义了 KV tiering 的基本抽象，尤其贴合长会话 Agent 与代码助手。

Limitations

生产 trace 和硬件组合仍有限；代码未确认公开；SSD endurance/多租户隔离未成为主要评估。

Editor Note

相较单纯“多一层缓存”，FlatCake 的价值在于删除 staging invariant。

Related Work

同样做分布式 KV 数据面；FlatCake 用 flat peer media 避免 DRAM staging。

02

03

Abstract

Original Abstract Summary

中文摘要

Technical Analysis

Problem

显存不足时多数专家驻留 CPU；同一加载策略无法同时服务 compute-bound prefill 和 I/O-bound decode。

Method

Architecture

Abstract

Original Abstract Summary

PhOSv1 observes that sleeping model engines retain largely duplicated GPU contexts. It centralizes context allocation and deduplicates driver state and kernel binaries while preserving rapid wake-up.

中文摘要

vLLM/SGLang sleep 能快速扩容，但每个休眠进程仍占 GPU context。PhOSv1 把 context 分配委托给中心服务，配合 LFU 控制缓存模型集合。

Technical Analysis

Problem

大量休眠模型的 context 显存线性增长，挤压在线 KV cache 并降低吞吐。

Method

CUDA API remoting、context service、kernel binary/context 去重、LFU eviction。

Architecture

Rust 10,825 LOC；中心 daemon 持有共享 GPU context，vLLM engine 通过 remoting 访问。

Key Innovation

将 model sleeping 的共享对象从权重扩展到 GPU driver context 和 kernel binaries。

Experiments

单台 8×A800 80GB 服务器，测量使用单 GPU；Xeon 8350C、1TB DRAM、CUDA 12.9、vLLM 0.19.1；10–16 个 Qwen/Qwen-VL 模型。

Editorial Assessment

Why It Matters

多模型服务中“睡眠态也吃显存”是容易被忽略的容量税。

Limitations

当前评估以单 GPU 为主；context 共享的隔离、安全与 driver 兼容面需要长期验证。

Editor Note

对常驻多模型池有价值，但生产接入风险高于普通 scheduler patch。

Abstract

Original Abstract Summary

Problem

Abstract

Original Abstract Summary

Raincheck defers unselected multimodal tokens instead of discarding them, progressively prefilling them while controlling attention visibility and updating recurrent/full-attention states.

中文摘要

与 hard pruning 永久丢弃信息不同，Raincheck 保留未选 token，并按源顺序在 decode 空隙补算；visibility control 与 affine state mapping 允许生成开始后继续扩展上下文。

Technical Analysis

Problem

多轮 MLLM 首轮长视觉 prefill 慢，而 query-aware pruning 会损害后续问题。

Method

deferred prefill、gap scheduling、attention visibility、state mapping、prefill-decode fusion。

Architecture

Key Innovation

把被剪掉的输入从“永久删除”变成“可延迟完成的背景工作”。

Experiments

Qwen3-VL-8B、Qwen3.5-9B，30% 初始保留，4 种 pruning method，MultiVerse/ConvBench。

Editorial Assessment

Why It Matters

对视频/图像多轮 Agent，利用 decode bubble 补上下文比单纯 pruning 更稳健。

Limitations

依赖可用 decode/gap 容量；复杂 workload 下后台 prefill 可能干扰其他请求。

Editor Note

可与 PD disaggregation 的 prefill pool 和请求优先级调度结合。

Problem

Method
