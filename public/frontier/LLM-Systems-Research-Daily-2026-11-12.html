KVCache.AI / Mooncake；个人机构未披露

Publish Date

commit merged 2026-11-12 08:13 UTC（16:13 Asia/Shanghai）

Venue

Mooncake main branch · core code

Abstract

Original Abstract Summary

This core-code update adds automatic owner-side pipelined gathering for ranged reads made of many small source fragments that map to one contiguous registered destination. It preserves the public API and per-fragment results, discovers owner services through an expiring RPC directory, and safely falls back to scatter when geometry or transport requirements are not met.

No paper abstract was published; this is a faithful English summary of the official commit description, not a verbatim abstract.

中文摘要

该改动把“许多小源片段 → 一个连续目标缓冲区”的读取模式识别放入 Store：owner 端先打包片段，再以既有 Transfer Engine 的 RDMA WRITE 流水写入读取端，避免逐片段 scatter 的控制与传输开销。

Technical Analysis

Problem

分散 KV/对象片段的 ranged read 会形成大量小传输；逐片段 scatter 的控制路径、连接与 WR 数量可能支配成本。

Method

按 owner 与目标连续区间构造 GatherReadPlan；通过 heartbeat 刷新的短时 RPC 目录发现 owner 服务；用注册内存分块、流水 RDMA WRITE 和会话 fencing 完成传输。

Architecture

Reader policy/geometry check → owner capability discovery → gather session → owner CPU pack → pipelined Transfer Engine WRITEs → contiguous registered destination。TCP、TENT、gap、混合协议或不支持端点均走既有 scatter。

Key Innovation

不是新建外部数据面，而是在 Store 内做可回退、可围栏的 gather/scatter 选择，同时保持 descriptor、allocator、snapshot 与逐片段语义不变。

Experiments

官方提交披露 28 个聚焦测试，覆盖 mlx5_0 RDMA、TCP fallback、HTTP metadata、session capacity recovery；性能 harness 与报告明确不在仓库内，因此吞吐/延迟增益未核实。

Editorial Assessment

Why It Matters

长上下文与分层 KV 存储经常把逻辑连续读取映射为许多物理小片段；把 gather 推到 owner 可减少读取端的小 IO 风暴。

Limitations

仅支持经典 RDMA owner 与 CPU-memory replica；TCP 因失败后无法安全 fence 未启用；owner 丢失自动恢复未提供；缺端到端性能数字。

Editor Note

A 级。架构新增量与代码开放度高，但缺少可归因性能实验，Evidence 因此保守计分。

Abstract

Original Abstract Summary

The change extends Mooncake's worker-pool HugeTLB population path from RDMA to EFA. It avoids MAP_POPULATE-driven single-thread page faulting and zeroing before transfer-engine registration while preserving reservation behavior and early failure when the huge-page pool is insufficient.

No paper abstract was published; this is a faithful English summary of the official commit description, not a verbatim abstract.

中文摘要

EFA + HugeTLB 原先仍通过 MAP_POPULATE 单线程触页，导致大 Store 段初始化极慢。本改动让 EFA 也在注册前由 worker pool 并行触页，保持 mmap 时的容量预留与失败语义。

Technical Analysis

Problem

1 TiB 级 host-memory Store 在 EFA 路径上被单线程 page fault/zeroing 阻塞，启动时间远大于传输引擎本身。

Method

将 parallel_hugetlb_population 条件由仅 RDMA 扩展为 RDMA 或 EFA；复用现有 worker pool 与注册前触页流程。

Architecture

HugeTLB mmap（MAP_PRIVATE、无 MAP_NORESERVE）→ worker-pool population → EFA Transfer Engine registration → Store ready。

Key Innovation

改动很小，但修复了协议分支导致的大容量内存初始化非对称，使 EFA 获得与 RDMA 相同的并行物理页建立路径。

Experiments

AWS p6-b200.48xlarge，x86，8 EFA NICs；1 TiB segment；1 GiB HugeTLB pages；对照原 EFA MAP_POPULATE 与 2 MiB THP。未披露重复次数、方差与应用级 TTFT。

Editorial Assessment

Why It Matters

层次 KV/权重存储的可用性不仅由稳态带宽决定，TB 级 host tier 的初始化时间直接影响扩缩容与故障恢复。

Limitations

单平台、单容量点；不代表 steady-state KV 传输吞吐；核心 diff 仅一行条件扩展，方法新颖度有限。

Editor Note

B 级。结果清晰且可复现，但属于关键工程修复而非新系统架构。

PyTorch / TorchTitan；个人机构未披露

Publish Date

commit merged 2026-11-12 07:55 UTC（15:55 Asia/Shanghai）

Venue

TorchTitan main branch · core code

Abstract

Original Abstract Summary

This core-code contribution enables HybridEP for Muse Spark training. It masks unwritten capacity rows around the model's per-expert postprocessing, compiles the masks into RMSNorm kernels, and preserves CUDA Graph capture. The official change report includes performance, numerical comparisons, and multi-configuration tests.

No paper abstract was published; this is a faithful English summary of the official commit description, not a verbatim abstract.

中文摘要

Muse Spark 的 expert 后 RMSNorm 在非阻塞 HybridEP 下会处理未写入的 capacity rows，造成错误梯度或 NaN。本改动在 postprocess 前后以 GPU mask 隔离无效行，并把 mask 编译融合进 RMSNorm，使 Hopper 上可使用无 CPU sync 的 HybridEP 与 CUDA Graph。

Technical Analysis

Problem

AllToAll 每层 CPU sync，无法捕获 CUDA Graph；直接启用 HybridEP 又会让未写入 capacity rows 进入 RMSNorm 和反向，污染参数梯度。

Method

由 offsets_E[-1] 在 GPU 上生成有效行 mask；postprocess 前用 torch.where 去除陈旧/NaN 输入，后再 mask 输出以归零无效行梯度；local_compile 融合 mask。

Architecture

FSDP/TP/CP → HybridEP non-blocking dispatch → grouped GEMM → masked expert RMSNorm postprocess → combine；GPU offsets 驱动 mask，无 CPU 同步，支持 CUDA Graph。

Key Innovation

把 dispatcher 的容量语义与模型专属 expert postprocess 显式连接，并通过局部编译消除双 mask 开销。

Experiments

主性能：8×H100，scaled proxy，FSDP8+EP8，steps 11–30 平均 TPS；数值：4×H100、20 steps，AllToAll/HybridEP loss 接近且 compiled/unfused bitwise 一致。另有 263 CPU tests、HybridEP/DeepEP GPU tests。

Editorial Assessment

Why It Matters

训练端 MoE 通信路径常被模型专属归一化、capacity padding 和图捕获共同约束；该提交展示了可落地的跨层接口修复。

Limitations

capacity factor 1.0 使显存约翻倍；BF16 combine score rounding 与 AllToAll 数值不完全相同；多模态训练仍不支持 CUDA Graph。

Editor Note

S 级。开放代码、完整性能与数值证据、明确 trade-off，属于本日最强系统新增。

PyTorch / TorchTitan；个人机构未披露

Publish Date

commit merged 2026-11-12 08:18 UTC（16:18 Asia/Shanghai）

Venue

TorchTitan main branch · core correctness fix

Abstract

Original Abstract Summary

The change fixes an FSDP state-machine and stream-ordering bug in RL generator weight reloads. It completes a pending grouped forward before resharding so the next unshard and all-gather run on the current stream after shard writes. The official report validates both a 35B MoE LoRA case and a 816B Muse Spark run.

No paper abstract was published; this is a faithful English summary of the official commit description, not a verbatim abstract.

中文摘要

当 norm 位于 CUDA Graph、lm_head 单独执行时，FSDP group 可停留在 FORWARD 状态。若 LoRA adapter-only load 以 device stream 写 shard，prefetch stream 上的 all-gather 可能不等待这些写入，最终聚合未初始化权重。本修复先把 group 置回 IDLE。

Technical Analysis

Problem

RL 训练器向生成器同步权重时，FSDP 状态与 CUDA stream 依赖不完整，导致静默错误 rollout、reward 归零。

Method

_reshard 调用 complete_fsdp_grouped_forward(module, None)，然后 module.reshard；IDLE 状态让 unshard/all-gather 正确落在 current stream。

Architecture

Trainer weight fetch → finish grouped forward → reshard/refill shards → current-stream unshard/all-gather → generator CUDA Graph rollout。

Key Innovation

将错误定位到 FSDP group state 与 stream ownership 的交叉，而不是简单增加全局同步；复用已有 graph-validation helper。

Experiments

Qwen3.5-35B-A3B Geometry3K LoRA（DP2×EP2、Dist-MoE、FULL graphs、10 loads）；Muse Spark 816B（DP4×TP4×EP16、200 steps）；2-rank gloo state test；74 CPU tests。

Editorial Assessment

Why It Matters

在线 RL 的 correctness 依赖训练—生成权重同步；此类 silent divergence 不会表现为 OOM 或 crash，却会直接污染奖励与策略更新。

Limitations

修复针对特定 grouped lm_head/norm 状态；官方说明当前 blocking fetch 尚不触发竞态，风险主要来自 stream-ordered device work；硬件型号未完整披露。

Editor Note

S 级。影响是训练正确性而非局部性能，且有 35B/816B 实例与回归测试支持。

TorchTitan main branch · RL core code

Abstract

Original Abstract Summary

The update changes TorchTitan's MoE RL default so that the learned router gate remains trainable while the moving expert-bias update and auxiliary load-balancing loss are disabled. The accompanying ablations separate the gate from load-balancing state and report trainer-generator log-prob gaps without claiming reward gains.

No paper abstract was published; this is a faithful English summary of the official commit description, not a verbatim abstract.

中文摘要

此前 RL transform 同时冻结 expert bias、移除 aux loss、冻结 gate；这会阻止策略学习 routing。本改动重命名并收窄 transform：只关闭动态负载均衡状态和损失，gate 仍由 RL 梯度更新。

Technical Analysis

Problem

移动 expert bias 会放大训练器与生成器的 top-k 路由不一致，但连 gate 一起冻结又切断了 MoE 策略的可学习部分。

Method

FreezeMoERoutingTransform 改为 DisableMoELoadBalancingTransform；冻结 expert_bias_E、aux_loss=None，不再设置 router.freeze_gate。

Architecture

RL trainer FSDP2/EP → trainable gate → fixed expert bias / no aux loss → full state dict sync → vLLM generator；两端保持相同 routing 参数。

Key Innovation

将“路由参数学习”与“负载均衡控制状态”拆开，避免用粗粒度冻结解决 policy mismatch。

Experiments

2×H100；4-layer cuts of Qwen3.5-35B-A3B 和 Qwen3-30B-A3B；每步 8 prompts×8 samples×200 tokens，AdamW 5e-6；Qwen3.5 60 steps、Qwen3 20 steps。另 504 RL CPU tests。

Editorial Assessment

Why It Matters

MoE 后训练不仅要同步权重，还要定义哪些 routing state 属于策略；该提交把这一算法—系统边界显式化。

Limitations

没有 reward A/B；frozen run 方差较大；未测 gpt-oss、非零 expert bias 的 Muse Spark 816B；旧 checkpoint 可能缺 gate optimizer state。

Editor Note

A+。系统语义重要且证据诚实，但尚缺奖励与大规模稳定性结论。

Abstract

Original Abstract Summary

This Transformer Engine update reduces redundant NVFP4 work in fused GroupedMLP activation recomputation. The forward keeps only the row-wise representation needed for FC2 and saves the exact amax values; the backward reuses them when rebuilding the bit-identical FC2 input, eliminating repeated quantization passes and Hadamard-amax kernels.

No paper abstract was published; this is a faithful English summary of the official commit description, not a verbatim abstract.

中文摘要

激活重算时，反向会重建 fc2_x 并重新做 column-wise 量化。旧路径前向仍生成随后丢弃的 column-wise copy，反向又重新扫描 amax。本改动以 saved tensors 保存前向 amax，并在 bit-identical 重建后复用。

Technical Analysis

Problem

NVFP4 fused MoE MLP 在 activation recompute 下重复量化和 amax 扫描，浪费内存带宽与 kernel launch。

Method

提前决定 recompute_fc2_x；前向只请求 row-wise 数据；保存 pre/post-RHT amax；反向使用 nvfp4_group_quantize_with_amax；条件满足时采用 Hadamard-fused fc1 kernel。

Architecture

Fused FC1 + activation + RHT/amax → row-wise NVFP4 FC2 input → FC2；backward dSReLU rebuild → reuse saved amax → column-wise quantize for wgrad。

Key Innovation

利用“重算张量与前向 bit-identical”这一正确性条件，把量化统计从可丢弃中间值提升为可复用训练状态。

Experiments

GB300；8 experts；NVFP4+RHT；130B hybrid MoE proxy；tanh-SReLU、plain SReLU、SwiGLU；recompute on/off；检查 output、dgrad、dprob、weight gradients 与 kernel launches。

Editorial Assessment

Why It Matters

FP4 训练收益常被 scale/amax 处理抵消；把重算与量化状态联合设计可直接减少数据扫描。

Limitations

主数字是单 fused-call kernel 时间，不是端到端训练吞吐；依赖匹配 cuDNN frontend 与 SM100/GB300 路径；130B proxy 的完整模型配置未披露。

Editor Note

A+。NVIDIA 第一方核心实现与位级正确性证据强；端到端收益未披露使 Evidence 留有折扣。
