Abstract

Original Abstract Summary

The study measures Ouro and Huginn serving and grades every optimization from bitwise-identical to accuracy-checked. It finds thousands of small kernels, graph-cache misses, prefix reuse, and disaggregated transfer commit tails to be the decisive costs.

中文摘要

工作没有把“更快”当成单一数字，而是把逐位一致、经验等价和需要精度检查的改动分层；这使性能收益与语义风险可以一起审计。

Technical Analysis

Problem

循环模型每个 token 多次执行共享 block，究竟是循环提交、微型 kernel、KV 还是 PD 传输限制服务速度？

Method

端到端测量、rounding-fence kernel fusion、prefix/page reuse、CUDA Graph cache 扩容和 PD transfer-budget 调整。

Architecture

开源 looped-model engine；Ouro 与 Huginn；单机及 prefill–decode disaggregation。

Key Innovation

把每项系统优化按输出精确性分级，并证明直觉上的“合并循环提交”并非主要收益。

Experiments

Ouro/Huginn；1014+1319 条精确性/准确率检查；摘要未披露 GPU 型号。各加速来自不同配置，不合并。

Editorial Assessment

Why It Matters

新模型结构需要新的服务 cost model；本工作同时给出性能和正确性边界。

Limitations

模型族较窄；部分近似优化依赖一分规则；代码入口未在摘要页披露。

Editor Note

当天最完整的 serving 测量论文，价值在于排除错误直觉并保留可审计语义。

Abstract

Original Abstract Summary

Bevy observes that expert prefetching becomes less accurate as the GPU expert cache improves. It interleaves requests by expert readiness, then dynamically batches ready requests per layer while prioritizing laggards.

中文摘要

专家缓存越有效，剩余 miss 越难预测，错误预取反而浪费链路和显存。Bevy 用可执行请求本身确定下一步需求，避免猜测。

Technical Analysis

Problem

本地 MoE expert offload 中，GPU 等待传输，而预取会因选择不准伤害性能。

Method

runahead inference、expert-ready scheduling、动态分层 batching 与落后请求优先。

Architecture

GPU expert cache + 主机权重存储 + 并发请求 scheduler。

Key Innovation

把预取问题改写为请求交错问题，在不预测 expert routing 的情况下隐藏搬运。

Experiments

两个 local platforms；对 llama.cpp 和最快 prefetch baseline；摘要未披露模型/硬件明细。

Editorial Assessment

Why It Matters

消费级单卡运行大 MoE 的关键不是只扩大缓存，而是让请求在 miss 间隙继续前进。

Limitations

重复读取共享权重增加计算；尾延迟、公平性和高并发扩展未在摘要披露。

Editor Note

核心洞察清晰：有缓存时，调度可以比专家预测更可靠。

Abstract

Original Abstract Summary

LeanSparse streams one layer of prefill history through reusable buffers and uses compact coarse indexes during decode, retrieving original indexer keys only for candidate refinement. Separate indexer and KV caches reuse data across generation steps.

中文摘要

稀疏 attention 只少读 KV，并不会自动减少服务所需的完整索引历史。LeanSparse 将“候选发现”和“精确评分”分层，避免全量 indexer keys 常驻 GPU。

Technical Analysis

Problem

native sparse attention 的索引元数据仍挤占 GPU，prefill 临时峰值又阻塞请求准入。

Method

layer streaming、双 buffer 重叠、coarse-to-fine indexing、indexer/KV cache 分离。

Architecture

SGLang + DeepSeek-V4-Flash；GPU/host 历史流与候选 refinement。

Key Innovation

针对稀疏 attention 的索引侧内存，而不是只做 KV offload。

Experiments

950K context；对 HiSparse/ECHO；多轮 Open-SWE traces。摘要未披露 GPU 型号。

Editorial Assessment

Why It Matters

百万 token agent serving 的并发可能被 indexer 而非 KV 本体限制。

Abstract

Original Abstract Summary

GC-MoE partitions SMs into communication and compute domains, launches their kernels as concurrent CUDA Graph roots, and uses token-ring handshakes plus double-buffered counters. It supports Hopper FP8/decoded FP4 and Blackwell block-scaled MMA.

传统 fused MoE 让通信 warp 与 MMA 在每个 SM 上争抢寄存器、共享内存和 issue slots。物理划分 SM 后，两类 kernel 可独立配置和同步。

Technical Analysis

Problem

低 token decode 下 dispatch 延迟和权重流量主导，单 kernel 内重叠产生资源干扰。

Method

Green Context SM partition、并发 graph roots、token ring、双缓冲 counters、融合 SwiGLU/requantization。

Architecture

8×H20 / 8×B300；FP8/FP4 expert parallel kernels；20/148 B300 SMs 用于 dispatch。

Key Innovation

用硬件隔离而非同 CTA 共享资源实现 MoE communication–compute overlap。

Experiments

Why It Matters

MoE decode 的瓶颈是极小 batch 下通信与 GEMM 的互相干扰，Green Context 提供新的隔离维度。

Limitations

仅 NVIDIA Hopper/Blackwell；收益相对温和且依赖 SM partition 调参。

Editor Note

开放实现、硬件完整、对照严格，是当天 kernel/runtime 最强项之一。

Abstract

Original Abstract Summary

TapeSAC automates selective activation checkpointing without model-code edits. Dispatcher-level recording enables demand-driven replay, and a cost-aware planner selects tensors under a peak-memory constraint.

传统 checkpoint 往往整块重算，甚至重算 backward 不会读取的中间值。TapeSAC 以 producer 依赖和实测成本构建内存—时间 Pareto frontier。

Technical Analysis

Problem

Method
