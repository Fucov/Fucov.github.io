Abstract

Original Abstract Summary

UlaCache presents a KV-cache management system for sparse-attention LLM serving. A stable logical address space spans GPU pools and optional CPU memory, allowing allocation and sparse access to remain independent of physical placement. Distributed local buffers retain selected KV across decoding steps, while PB-LRU manages a shared GPU cache and parallelizes recency and eviction bookkeeping.

中文摘要

稀疏注意力减少每步读取量，却仍需保留完整历史 KV。UlaCache 把 GPU 与 CPU 容量合并成逻辑地址空间：推理引擎只操作稳定地址，系统负责解析位置、跨设备搬运和映射提交；TP 下各 rank 聚合容量并缓存本地副本，CPU 扩展时由 PB-LRU 并行决定晋升与驱逐。

Technical Analysis

Problem

稀疏注意力只降低读取，不降低必须保留的历史规模；现有 CPU 后备或固定请求缓存会复制 KV、限制并发，TP 下 MLA 还可能跨 rank 复制。

Method

统一逻辑寻址将 token KV 与物理槽位解耦；DP 使用 rank 本地池，TP 聚合多 GPU 池。缺失 KV 按需传输，本地 buffer 保留重复选择，PB-LRU 以 recency bucket 和分层 bitmap 并行处理命中、驱逐与映射。

Architecture

SGLang 集成层向 UlaCache 分配逻辑槽并提交 sparse selection；GPU/CPU storage pools 构成地址空间；TP computing rank 有 selected-KV local buffer；distributed indexer 对本地 key 打分后 all-gather TopK；独立 CUDA stream 预取并以 event 协调传输、attention 与槽位复用。

Key Innovation

把“稀疏访问”与“完整历史保留”放到同一地址抽象中，并让 GPU 空间既能存独立历史又能作热点副本；相较固定 per-request quota，更充分利用低并发时的闲置容量。

Experiments

GLM-5.3，FP8 权重/KV、BF16 activation；8×H200 与 8×B300；SGLang 与 HiSparse 基线；DP/TP、启用/禁用两步 MTP；Multi-LexSum 64K–128K 输入，最多 578 请求、每请求生成 2,048 token。报告 TPOT、output tokens/s 与可容纳并发。

Editorial Assessment

Why It Matters

长上下文 sparse attention 正从 kernel 问题转向全生命周期内存系统问题。逻辑地址让上层调度无需绑定位置，也为分层内存、跨 GPU 容量聚合和未来迁移策略提供统一接口。

Limitations

结果集中于 GLM-5.3、两类 NVIDIA GPU 与单一长文本 workload；TP distributed indexer 的低并发同步开销仍存在。论文未提供独立代码仓库，SGLang 实现的公开状态未核实。

Editor Note

91/S。系统抽象、实现与完整硬件实验形成闭环，是本日 Must Read；但复现入口与跨模型泛化尚不足以进入 S+。吞吐峰值只能在其匹配预算、特定 batch sweep 与 workload 条件下解读。

Related Work

共同点：CPU 后备的 sparse-KV serving。区别：固定 per-request GPU buffer 且 GPU/CPU 保存副本。新增量：统一地址与共享 PB-LRU 提升唯一历史容量。

共同点：分层 KV 存储。区别：主要服务 prefix reuse，执行时仍恢复到 GPU 槽。新增量：UlaCache 直接托管活跃解码历史并支持 sparse access。

Abstract

Original Abstract Summary

HAWK explores phase-disaggregated inference that assigns prefill to GPUs and decode to NPUs. It creates a common RDMA path across device memories and places layout-aware buffers on the NPU so that tensor-layout conversion is partly embedded in transfer. The received KV can be consumed directly, avoiding host staging and post-transfer rearrangement.

中文摘要

HAWK 针对 GPU 与 NPU 软件栈、通信接口和 KV 布局都不一致的问题，在两侧驱动间接入统一 Linux RDMA 路径；GPU 先做 transfer-aware transformation，NPU 按目标布局分配多个可 RDMA 缓冲区，使数据在传输过程中自然落到可直接解码的位置。

Technical Analysis

Problem

PD 分离跨同构 GPU 已有成熟 RDMA，但 GPU–NPU 既缺直接互操作，又存在 tensor layout 差异；host staging 和落地后重排会把 KV 搬运推到关键路径。

Method

扩展 NPU 驱动的 peer-memory 支持，使 NIC 可直访两类设备内存；将连续 GPU buffer 与多块 layout-aware NPU buffer 配对，并通过传输前的局部重排放大连续 RDMA chunk。

Architecture

prefill node：4×A100 PCIe；decode node：4×Tenstorrent p150a；节点间 200 Gbps HDR InfiniBand/ConnectX-6。vLLM + Tenstorrent plugin，Mooncake Transfer Engine 上实现 user-space transfer，TP=4 服务 Llama 3.1 70B。

Key Innovation

不要求两端采用统一 tensor layout，也不把完整 layout conversion 留到收包后，而是将布局约束编码进 RDMA buffer allocation 与传输映射。

Experiments

与 GPU–GPU host staging、GPU–NPU host staging、GPU–GPU direct RDMA 比较；ShareGPT chatbot 和 LongBench summarization，Poisson 到达。测量 10–1,280 MB 传输、TTFT、TPOT、90% SLO attainment、throughput、ASIC power 与按设备价格估算的成本效率。

Editorial Assessment

Why It Matters

异构 PD 的关键不只是调度哪种芯片，而是能否让 KV 数据面跨厂商栈工作。HAWK 给出从驱动、RDMA、buffer layout 到在线 serving 的端到端证据。

Limitations

原型依赖 Tenstorrent 开放栈且只测 Llama 3.1 70B、单 prefill/decode instance；NPU 平台外推性有限。功耗使用 ASIC 估计，成本依赖价格假设；代码仅“计划开源”。

Editor Note

89/A+。这是把异构 PD 从概念推进到真实 vLLM/RDMA 系统的强证据，但代码未公开且平台面窄，暂不进 S。

Abstract

Original Abstract Summary

RISK-KV reduces the historical state needed for request migration and interruption recovery. Exact KV anchors surrounding a target layer are used to predict the missing layer input through ridge regression; folding the model’s frozen KV projections into the predictor reduces storage. A measured NLL-risk gate selects reconstructible layer groups.

中文摘要

在迁移或恢复时，RISK-KV 不搬完整 KV，也不从 token 全量重放，而是保留部分精确层作为 anchor，用轻量跨层回归预测缺失层的 attention-projection 输入，再沿原模型 KV projection 生成缓存。系统按实际重建引起的 NLL 变化搜索可省略层组。

Technical Analysis

Problem

完整 KV 迁移受带宽限制，丢弃 KV 后 token replay 又增加恢复时延；无质量约束的近似重建可能破坏预测。

Method

两侧精确 anchor + ridge regression；将预测器与冻结 KV projection 折叠；独立 calibration/test 上测 reconstruction risk，以 quality gate 搜索省存储且满足质量阈值的 topology。

Architecture

离线拟合跨层 predictor；迁移时只传 exact anchors 与不可重建层；目标侧以 folded FP16/FP32 predictor 生成缺失 KV、执行 RoPE 并组装 cache；恢复路径在下一 token 前完成。

Key Innovation

把重建误差从张量距离提升为对模型 NLL 的功能风险，并把层选择、存储节省和恢复时延放入一个可门控方案。

Experiments

3 个 0.5B–1.5B 模型，WikiText-2，512 历史 + 512 teacher-forcing 窗口；3 seeds、每 seed 8 请求；独立 train/validation/test。硬件与网络迁移环境未披露，本地延迟实验仅 8 validation 请求/模型。

Editorial Assessment

Why It Matters

状态迁移与抢占恢复是弹性 serving 的隐性成本。若能按风险选择重建，调度器可在质量、带宽和恢复时间之间做更细粒度权衡。

Limitations

仅小模型、短 512-token 历史和本地恢复；真实网络迁移、长上下文、并发与端到端生产调度未验证。单作者且无代码链接，复现性受限。

Editor Note

82/A。方向新且质量门控合理，但系统证据仍偏原型；3.31× 不应外推到长上下文或远程迁移。

Abstract

Original Abstract Summary

BIRD-RL targets agentic reinforcement learning in stateful data-centric environments where isolating every rollout with its own database container is spatially and operationally expensive. A trajectory-scoped persistent execution layer safely reuses replicas while preserving isolation, supporting a four-stage curriculum that combines supervised reasoning and on-policy exploration.

中文摘要

有状态数据库任务要求 rollout 之间既隔离，又能保留单条轨迹内不断变化的环境状态。BIRD-RL 通过预先物化数据库副本池、按轨迹绑定副本并只重置发生写操作的实例，避免每条 rollout 重建容器；其上运行两阶段 SFT 与两阶段 GRPO，训练统一的 SQL 生成/调试模型。

Technical Analysis

Problem

工具型 RL 框架通常假定环境轻量且无状态。对 SQL 调试，每 rollout 独占容器会产生巨大 I/O；直接复用数据库又造成轨迹污染和错误奖励。

Method

四阶段 curriculum（单轮 SFT、多轮工具 SFT、单轮 reasoning RL、多轮 agentic RL）+ trajectory-scoped replica pool；按轨迹分配实例、追踪状态，结束时只对写入过的副本复位。

Architecture

verl v0.7.0.dev0 + vLLM v0.11.0；8×H100 80GB；数据库池预留 B×R/2 副本/数据库；async vLLM rollout 最多 5 个 assistant turn。基础设施作为通用 verl rollout pipeline 的 patch。

Key Innovation

把 RL rollout 隔离从“一轨迹一容器”改为“轨迹作用域状态 + 可复用持久副本”，让环境生命周期 I/O 随修改比例而不是总轨迹数增长。

Experiments

Qwen2.5-Coder 7B/14B，8×H100；SFT 后两阶段 GRPO；BIRD-CRITIC-SQLite 与 BIRD dev。B=16、R=16 时对比 per-rollout container，在线 I/O 2.94 TiB vs 236 GiB；只有 9.25% 轨迹触发写后 reset。

Editorial Assessment

Why It Matters

Agentic RL 的扩展瓶颈不仅是 actor/learner GPU，而是环境状态。该工作把数据库隔离、复位和 I/O 明确提升为训练系统的一等资源。

Limitations

证据集中在 SQLite/SQL；12.8× 是生命周期 I/O 比率，不是端到端训练吞吐。69 GiB 离线池成本被排除，其他数据库、容器运行时和高写入率下收益未知。

Editor Note

88/A+。训练基础设施增量明确、代码开放、实验条件透明；但应用域较窄，需进一步证明对浏览器、代码执行和企业服务等重状态环境的通用性。

Abstract

Original Abstract Summary

The paper models DPO as a computation graph and stochastically prunes three independent axes before their operations execute: response positions for vocabulary scoring, prefixes for sequence execution, and preference branches for backpropagation. Inverse-probability weighting gives a conditionally unbiased single-branch gradient estimator for the sampled objective.

中文摘要

该方法不把“少算 loss token”误当成节省计算，而是在操作发生前决定是否执行：位置裁剪减少输出头计算，序列裁剪缩短 backbone 前缀，分支裁剪只保留 chosen/rejected 一侧反向图。论文同时分析不同裁剪对目标函数的偏差与梯度方差。

Technical Analysis

Problem

DPO 同时为 chosen/rejected 计算 policy/reference 分数并保留两条反向路径，词表 logits、长序列执行与 activation 造成显存和时间开销；单纯删监督位置未必省下算子。

Method

三轴独立 stochastic pruning；position/head selective execution、prefix truncation、single-branch backward；用 inverse-probability weighting 校正被采样分支的梯度。

Architecture

训练时在 forward 前生成 mask；policy/reference 使用匹配的 prefix/position，reference 不建图；仅被选 policy branch 保留 autograd。可与 LoRA、FlashAttention-2、gradient checkpointing、AdamW 组合。

Key Innovation

把 DPO 资源优化表述成完整计算图上的可执行裁剪，并通过 matched controls 区分“实现避免 materialization”与“删除监督”各自贡献。

Experiments

Qwen3-4B/8B、Mistral-7B，HelpSteer3-Preference 与 UltraFeedback；LoRA rank 64；8×Ascend 910B 32GB，global batch 64。测 step time、峰值 HBM、训练时间和 10 个 accuracy/open-ended benchmark。

Editorial Assessment

Why It Matters

DPO/偏好训练常被输出头和双分支反向拖累。该分解能帮助框架开发者在 kernel、显存和目标偏差之间进行可解释选择。

Limitations

默认裁剪有小幅平均 accuracy 下降，开放式评分不一致；大部分输出显存节省来自 selective-head 实现而非随机删监督。无代码链接，硬件仅 Ascend 910B，迁移到 GPU 栈需验证。

Editor Note

84/A。论文对资源归因很诚实，避免把监督稀疏直接包装成计算节省；但代码缺失、质量折损与单一硬件限制其即时影响。
