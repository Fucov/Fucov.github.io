Abstract

Original Abstract Summary

KVStream treats hierarchical KV storage as a parallel bandwidth pool rather than a fixed cache hierarchy. Reads are dynamically claimed in chunks by independent tiers, while writes are replicated and deferred. Integrated as an LMCache backend, it approaches the aggregate-bandwidth bound and improves throughput and TTFT on long-context, reuse-heavy workloads, while also quantifying regimes where replication overhead outweighs retrieval gains.

中文摘要

KVStream 将层次 KV 存储从“命中最快副本”改为“多层并行供数”：本地 NVMe 和共享存储根据完成速度动态领取读取块，新 KV 则异步复制。论文既给出高复用长上下文下的收益，也报告低复用、长输出或写带宽不足时的退化。

Technical Analysis

Problem

现有 offload 往往每次只从一个层级读 KV，使本地盘与共享存储不能叠加带宽；固定静态分片也难以适应节点和 PFS 的瞬时拥塞。

Method

请求级批量读取、completion-driven chunk claiming、自适应跨层路由、异步 deferred writes 与全层复制；调度无需预先估计每层吞吐。

Architecture

作为 LMCache backend 接入 vLLM；每个 TP rank 将 KV block 分块，local NVMe 与 PFS worker 并发领取；慢层自然领取更少。节点之间无需中心协调，扩展实验到 128 GPUs。

Key Innovation

用在线工作领取实现 aggregate bandwidth，而不是把层次存储仅作为容量后备；同时通过复制确保任一层都能独立服务后续读。

Experiments

TP=4，H100-80GB，约 320GB host memory；14B/32B/70B/110B，LooGLE、NarrativeQA、CUAD、Qwen-Coder、Chutes、SWE-bench agentic；对比 CPU-only、LMCache、Mooncake Store、SGLang HiCache。

Editorial Assessment

Why It Matters

长代理会话的 KV 远超单机内存，真正决定恢复延迟的是所有可用存储路径的总带宽。该工作把 KV tiering 提升为可调度的数据平面。

Limitations

优势依赖 prefix reuse 与短输出；4% reuse 时慢于 LMCache。复制写入必须跟上生成速度；共享 PFS 容量/副本去重与云对象存储效果仍未解决。论文实现基于 LMCache，但独立代码发布状态未明确。

Editor Note

结论可信，因为论文不仅给峰值，还给了低 reuse 退化边界。工程上最重要的检查点是写路径和多租户 PFS 干扰，而不是读取峰值本身。

LMCache

共同点：vLLM 外部 KV 层；区别：LMCache 基线按单层读，KVStream 并行聚合多层带宽；新增量：完成驱动路由与跨层复制。

02
Mooncake Store

共同点：分离式 KV 存储与高速传输；区别：论文中的 Mooncake connector 只用单一 offload tier；新增量：本地盘+PFS 并行读取。

03
SGLang HiCache

共同点：GPU/CPU/NVMe 层次缓存；区别：HiCache 偏层级命中，KVStream 偏并行供数；新增量：aggregate-bandwidth 上界与失败区间分析。

04
uGDS

共同点：把 GPU 与 NVMe/PFS 路径纳入统一 KV 数据面；区别：uGDS 强调 GPU-initiated direct storage，KVStream 强调跨层调度；新增量：两者可互补。

Abstract

Original Abstract Summary

InferSlice is a reference architecture for SLO-driven LLM inference across heterogeneous telco infrastructure. It combines network slicing, GPU partitioning, elastic serving, and observability, and evaluates service tiers, scale-out, client-edge bottlenecks, placement, parallelism, and prefill/decode disaggregation on the UK JOINER wide-area network.

中文摘要

InferSlice 讨论的不是数据中心内推理，而是在运营商 WAN 上如何按 SLO 分配网络与 GPU 资源。其最有价值的结果是给出架构边界：复制和 PP 尚能跨站点工作，TP 与 PD 解耦对广域延迟/带宽极其敏感。

Technical Analysis

Problem

主流 serving runtime 假设低时延、紧耦合集群；主权、合规与本地性要求却迫使推理跨地理站点部署，网络成为显式调度资源。

Method

定义 SLO tier，组合 network slicing、MIG/GPU partition、elastic scale-out、weight streaming 与端到端 observability，并逐种测试 DP/PP/TP/PD。

Architecture

控制面以 SLO 驱动服务 placement 与扩缩；数据面在 JOINER WAN 上连接 client/edge/core 站点。论文把网络切片和 GPU 生命周期放入同一参考架构。

Key Innovation

不是把 WAN 当作透明互联，而是实测模型并行与 PD disaggregation 的“可达半径”，给部署拓扑提供否定性证据。

Experiments

BT、Bristol 与 NVIDIA 在 JOINER national-scale WAN 上评估 service differentiation、scale-out、client-edge bandwidth、DP/PP/TP 和 PD。摘要未披露全部 GPU 型号与精确 RTT/带宽数字，相关结论按定性结果引用。

Editorial Assessment

Why It Matters

它提醒系统设计者：数据中心内有效的 disaggregation 不能直接外推到 telco edge；SLO 调度必须把 subnet/hop 和模型并行耦合起来。

Limitations

公开摘要缺少完整硬件、网络参数和逐项数值；参考实现/代码状态未披露。结论来自一张特定国家级网络，对其他运营商拓扑的外推仍需验证。

Editor Note

将其视为架构约束报告，而非吞吐冠军。最重要的工程结论是：WAN 部署优先考虑副本与粗粒度 PP，谨慎使用 TP 与跨站 PD。

03

共同点：跨设备切分模型；区别：InferSlice把站点 hop 纳入可行性；新增量：PP 相较 TP 在 WAN 上更有容忍度。

04

共同点：靠副本贴近请求；区别：论文指出副本 placement 不敏感但受 GPU memory 约束；新增量：与 scale-out/weight streaming 共同评估。

Abstract

Original Abstract Summary

HyScale is an end-to-end training system for learned sparse-attention models. It eliminates the dense score-table bottleneck with exact on-the-fly top-k selection, replays selections across recomputation, overlaps context-parallel communication, and exploits locality in sparse kernels. The paper evaluates full-model and layer-level training across 256K–1M contexts on H20 and H800 clusters.

中文摘要

论文针对可学习稀疏注意力在超长上下文训练中的选择开销、重算浪费、CP 通信和稀疏访存问题，提出端到端系统 HyScale。其核心不是单一 kernel，而是把精确 top-k、选择回放、通信重叠与局部性内核组合成完整训练路径。

Technical Analysis

Problem

在 1M token 训练中，索引器选择会形成巨型分数表，重算阶段重复执行选择；CP gather 与稀疏 kernel 的不规则访存又进一步拉低利用率。

Method

HyTopK 使用乐观阈值在线保留候选，不落盘完整 score table；selection replay 保存并复用选择结果；通信与选择/注意力计算解耦重叠。

Architecture

基于 Megatron Core 0.19.2，实现约 3.4K 行 Python 与 14.7K 行 CUDA/Triton/CuTe kernel；包括 CP layout/sequence-boundary cache、elementwise fusion、permutation-free KV gather 和 locality-aware sparse attention。

Key Innovation

把“精确选择”从 O(context) 分数表改写为流式候选维护，并将其与重算、CP 和 GPU kernel 共同设计；不是以近似精度换取速度。

Experiments

完整 GLM-5.1：512×H20-96GB、8×400Gb/s RoCE/节点、BF16、256K/512K/1M context；另在 32×H800-80GB 上复现 DeepSeek CSA 与 Qwen QSA 层。基线为同版本 Megatron-LM + cuDNN DSA。

Editorial Assessment

Why It Matters

长上下文稀疏注意力是否真正可训练，取决于选择器是否能扩展；该工作给出了从算法到 Megatron 运行时、再到 kernel 的完整证据链。

Limitations

代码仓库未在论文页明确披露；完整模型结果只覆盖 GLM-5.1，其他架构是单层复现。结果依赖高带宽 RoCE 集群，跨网络/其他加速器可迁移性未核实。

Editor Note

优先级最高。尤其值得关注 HyTopK 的“无完整 score table”与 selection replay，它们把稀疏注意力的系统瓶颈从 FLOPs 重新定位到选择状态与重算语义。

Related Work

01
Megatron-LM / cuDNN DSA

共同点：大规模并行训练；区别：基线需要受内存约束的 dense selection；新增量：HyTopK 与 replay 消除选择的内存—时间权衡。

02
Native Sparse Attention

共同点：硬件友好的可学习稀疏注意力；区别：NSA 侧重架构与模式，HyScale 侧重训练系统关键路径；新增量：完整 1M-token 训练实证。

03
LiteTopK / HISA

共同点：加速 sparse-attention 索引或 top-k；区别：HyScale 还覆盖重算、CP 与后续 sparse kernels；新增量：端到端系统协同。

04
TileLang / FlashAttention 类内核

共同点：通过 tiled kernel 提升数据复用；区别：HyScale 利用相邻 query 的选择重叠并减少原子操作；新增量：与 exact selector 和 CP 组合。

Abstract

Original Abstract Summary

KnitTrans coordinates admission control, topology-aware trajectory storage and delivery, and multimodal encoding reuse for disaggregated LLM reinforcement learning. It admits constraint-preserving mini-batches early, materializes data according to TP/CP and encoder consumption order, and encodes repeated multimodal inputs once while accumulating gradients from all consumers. Evaluations cover system efficiency, staleness, and learning quality.

中文摘要

该系统认为 rollout→training 不是简单传输：过晚准入造成策略陈旧，过早流式准入又可能破坏 batch 配额；数据还要匹配 TP/CP 与多模态 encoder 的消费拓扑。KnitTrans 通过受约束 mini-batch 准入、原子化存储和编码复用同时处理三者。

Technical Analysis

Problem

分离式 RL 中，trajectory 到达顺序不等于训练消费顺序；sample-level storage 产生冗余读，TP/CP 重分布增加通信，多模态输入在同一 mini-batch 被重复编码。

Method

带 feasibility guards 的 mini-batch admission；按字段/拓扑拆分 atomic units；按消费者顺序预取与物化；mini-batch 范围唯一编码并反向聚合梯度。

Architecture

基于 VeRL，SGLang rollout + Megatron training；扩展 partial rollout 与 slime-style disaggregation；控制/数据面基于 TransferQueue，使用 Ray actor/Plasma 共享物化结果并支持跨节点 TP。

Key Innovation

把“学习约束是否被满足”纳入数据传输调度，而不是只优化 RDMA/存储吞吐；多模态 encoder graph 生命周期也与 backbone micro-batch 解耦。

Experiments

32 节点、每节点 8×NVIDIA Hopper、NVLink+RDMA；GRPO、每 prompt 16 rollouts；对比 VeRL、slime、StreamRL、AsyncFlow、TransferQueue、Miles/Mooncake、改造的 MegaScale-Data。

Editorial Assessment

Why It Matters

在线 RL 基础设施的瓶颈已从 rollout 算力转向数据生命周期与策略陈旧度。该工作把系统吞吐指标与最终学习质量连接起来。

Limitations

论文实现依赖多套现有系统，完整补丁/仓库未在论文页明确给出；最高 5.8× 只适用于 transfer/encoding 占比较高的 workload，全注意力 backbone 主导时收益有限。

Editor Note

比单纯“更快传输”更重要的是它证明了准入策略会改变训练质量。落地时应重点复核不同 RL 算法的 batch-global 约束是否能被同一 guard 表达。

Related Work

01
VeRL / slime

共同点：rollout 与训练编排；区别：KnitTrans在 disaggregation 上加入 mini-batch 级约束准入与拓扑化存储；新增量：系统效率与学习质量联动。

02
StreamRL / AsyncFlow

共同点：流式降低 staleness；区别：直接按完成顺序准入可能破坏 batch quota；新增量：feasibility guards 保留流式收益与最终约束。

03
Miles / Mooncake

共同点：RL 轨迹的高效存储与 RDMA；区别：Miles 仍是 sample-level 单位；新增量：按训练拓扑拆分 atomic units 和消费驱动交付。

04

Abstract

Original Abstract Summary

This report surveys the obstacles to geo-distributed LLM training and presents a unified system spanning a cloud parameter server, outbound-only gRPC clients, compression, fault tolerance, and multiple pretraining and fine-tuning paradigms. Preliminary deployments train GPT-2 Medium and Llama3-1B across university sites and motivate open problems in elastic membership, adaptive compression, alignment, and incentives.

中文摘要

这是一篇“系统+路线图”式技术报告。它把异构 GPU、WAN 波动、防火墙/NAT、抢占和机构边界作为默认条件，提出统一 PS 架构与训练 meta-algorithm，并以跨校 GPT-2 Medium/Llama3-1B 预训练展示可行性。

Technical Analysis

Problem

闲置边缘 GPU 分散在不同机构，算力、网络和数据均异构；传统同步集群依赖入站连接与稳定成员，容易被慢节点、NAT 与抢占拖垮。

Method

云端 PS 汇聚模型更新，客户端仅建立出站 gRPC；支持多 PS、可调同步 cadence、量化+Huffman 压缩、断点与 rejoin，并统一预训练/LoRA/ZO/split learning。

Architecture

Level-1 是 PS、client、通信压缩和容错基础层；Level-2 以 meta-algorithm 参数化 federated pretraining 与多种 fine-tuning。真实站点通过公网接入 AWS 协调节点。

Key Innovation

把预训练和多种微调置于同一 geo-distributed runtime，并明确把“只能出站连接”作为架构约束；贡献兼具实现原型与研究议程。

Experiments

GPT-2 Medium/OpenWebText：OSU 1 worker 2×H100，UW–Madison 2 workers 各 2×RTX3090，AWS EC2 t2.xlarge PS，每 10 分钟同步；对比 FedAvg、DiLoCo、FedNova。另报告 Llama3-1B 初步实验，但完整规模数字未全部披露。

Editorial Assessment

Why It Matters

它扩展了“大规模训练”的资源假设：除了同构数据中心，还可利用机构间闲置算力。对容错、压缩和异构优化器的联合设计有直接研究价值。

Limitations

许多章节仍是路线图，模型规模离 frontier training 很远；没有公开代码链接和端到端成本/吞吐倍率。跨机构隐私、安全、激励与 RL alignment 尚未实现。

Editor Note

达到门槛但低于前三。应把它读作可运行原型加问题定义，而不是已经证明边缘资源可替代数据中心训练。

03

04

共同点：跨机构微调；区别：本文把它们放进同一基础栈；新增量：从预训练到微调的统一 meta-algorithm。
