Abstract

Original Abstract Summary

ResServe represents an activation with an FP4 base plus an FP4-quantized residue, computes both contributions in narrow decode operations, and folds the outputs on chip. It applies compensation to linear layers and decode attention, while selectively limiting compensation during prefill.

中文摘要

论文将量化误差保留为独立 FP4 残差，在解码阶段用额外但低成本的矩阵计算恢复其贡献；线性层采用 M-Ext 输出折叠，注意力采用 ResAttn，prefill 则按选择性策略控制额外工作。

Technical Analysis

Problem

W4A4/FP4 能显著降低推理成本，但激活量化会伤害代码与推理质量；改用 W4A8 又会牺牲解码阶段最关键的延迟优势。

Method

将激活分解为 FP4 base 与 FP4 residue；在 tensor core 中分别乘加，并在片上折叠结果。线性层与 decode attention 都有专用路径，prefill 使用选择性补偿。

Architecture

在线运行时基于 vLLM 0.26.0；线性路径建立在 FlashInfer 上并新增 residue 布局、shape tactic tuning 与 output fold；ResAttn 保留原 KV 布局，只替换 decode attention 计算，基线通过 FlashInfer 调用 TensorRT-LLM kernel。

Key Innovation

不是用更高位宽直接覆盖误差，而是把“丢失信息”压成另一个 FP4 tensor，并利用窄矩阵低利用率窗口恢复，从而把精度恢复变成可调的系统资源。

Experiments

主要硬件为 NVIDIA B200，附加 RTX 5090 kernel 实验；覆盖 Qwen3-4B/8B/32B、Qwen3.8-27B 与 Swift-27B，比较同格式 plain FP4、FlashInfer 与 TensorRT-LLM W4A8 路径；任务包括代码生成、推理与检索。

Editorial Assessment

Why It Matters

它把低比特精度恢复从离线校准推进到 kernel/runtime 共设计，并直接触及 B200 上 FP4 serving 的质量—延迟边界。

Limitations

主要结果集中于 B200、列出的五个模型和特定 vLLM/FlashInfer 版本；额外 checkpoint 存储、不同 workload 的补偿比以及更大并发下的收益仍依赖部署条件。

Editor Note

代码开放、实验条件清楚，证据强；但仍是 v1 预印本，模型与硬件外推需谨慎，因此评为 A+。

Abstract

Original Abstract Summary

ISER-MoE dynamically assigns hot experts to GPU groups and multicasts their weights through the NVLink switch so each byte leaves the owner once. A GPU scheduler and multi-port broadcast are overlapped with shared-expert work to mitigate per-layer expert imbalance.

中文摘要

系统先由 HALO-Q 根据当前路由选择热专家及复制组，再利用 NVLink switch multicast 与 SAMI 多端口广播注入权重，最后把复制和 shared expert 计算重叠；实现构建在 TensorRT-LLM/MegaMoE 上。

Technical Analysis

Problem

MoE expert parallel 层由最繁忙 rank 决定时延，热专家随 layer 与 workload 漂移；逐层点到点复制会压垮 owner，传统 broadcast 又有延迟或带宽开销。

Method

HALO-Q 同时优化 rank balance 与 locality；对齐 GPU group 后，用 TMA weight replication 和对称 multicast 使 owner 每字节只发一次，并通过多端口广播摊平注入。

Architecture

TensorRT-LLM + MegaMoE NVFP4 backend；单 NVLink multicast domain，Dynamic Expert Parallelism，GPU scheduler；当前支持偶数 EP degree（至 EP32）、E≤384 且可整除，CUDA 13.1+，eager mode。

Key Innovation

把专家复制的数据面推入 NVLink switch multicast，并让每层热专家调度与网络 group topology 联合优化，而不是只在 token routing 或静态 placement 层平衡。

Experiments

trace replay 使用 DeepSeek-V4-Pro、8192 tokens/rank；硬件参考与 kernel/serving 测试使用 GB200，覆盖 EP4–8 硬件点、EP4–24 replay，并在数学与 agentic prompt 上评估 prefill。

Editorial Assessment

Why It Matters

热专家复制常被网络广播成本抵消；ISER-MoE 证明 switch-assisted multicast 可以把复制真正放进单层关键路径预算。

Limitations

尚未在 GB200 上测量带真实 shared expert 的完整 layer 或完整 end-to-end throughput，也没有与静态计划的硬件对照；仅验证 prefill、单 NVLink domain、无 CUDA graph，generation 未测试。

Editor Note

方向很强且由 NVIDIA/TensorRT-LLM 团队实现，但硬件实证仍不完整、代码未披露，证据与复现分数受限。

Abstract

Original Abstract Summary

DARIC observes stable patterns in KV-cache deviations and uses them to select a workload-dependent subset of tokens for recomputation. Its lightweight architecture separates cache generation and recomputation while preserving standard inference-engine scheduling and optimized kernels.

中文摘要

DARIC 不在请求时昂贵地逐 token 计算 deviation，也不使用固定重算比例；它从模型/数据上的偏差分布构建先验，按 chunk 结构分配重算预算，并通过输入处理器、调度器和 worker 轻量接入 vLLM。

Technical Analysis

Problem

位置无关 chunk KV 复用提高命中率，却破坏跨 chunk 交互；现有 CacheBlend 类方法要么在线选 token 成本高，要么依赖固定先验，且侵入 engine execution flow。

Method

分布感知 token selection 根据独立 chunk 数量与经验 deviation pattern 自适应决定重算集合；系统独立生成/装配 KV，并在保持原调度语义的情况下触发 partial recomputation。

Architecture

构建于 vLLM；包含 input processor、scheduler、worker 三层；支持非连续命中的 chunk 复用，保留 CUDA graph 与优化 attention kernel 的标准执行路径。

Key Innovation

把“重算多少 token”从固定比例转成由 deviation 分布和 chunk 结构驱动的预算，并用低侵入架构避免 cache reuse 破坏成熟 serving engine。

Experiments

覆盖多种 LLM、RAG、function calling 与 agentic coding 数据；以 CacheBlend 等位置无关复用方法为对照，同时报告同步与异步请求、hit rate、selection overhead、TTFT 和质量。具体硬件与所有模型组合见论文表格。

Editorial Assessment

Why It Matters

PIC 的落地障碍往往不是缓存本身，而是重算策略和 engine 集成；DARIC 同时处理两者，并已接受 SIGMOD 2027。

Limitations

质量“可忽略”的阈值随任务而异；偏差分布先验可能随模型版本、prompt 分布和 RoPE 方案变化，需重新校准。公开代码存在，但未核实所有实验脚本与模型资产是否齐全。

Editor Note

系统—算法共设计完整、代码开放、venue 证据强；但跨配置结果区间较大，复现完整性仍待核验。

Abstract

Original Abstract Summary

Nebula manages position-independent cache segments across a serving cluster. It combines optimistic accounting with event-driven updates, tunes shared capacity between prefix and position-independent caches using ghost hits, and schedules prefill using queueing, compute, and transfer costs.

中文摘要

Nebula 维护细粒度 PIC segment 的“及时且可信”集群视图，用 ghost-hit 反馈自动分配 prefix/PIC 容量，并将排队、计算与 KV 传输成本统一进 prefill 完成时间模型，支持远程 PIC 与并行 prefill。

Technical Analysis

Problem

单 worker PIC 虽提高复用率，却无法在集群中全局定位/转移 segment；细粒度状态异步变化又让 router 视图过时，导致重复计算、无效命中与长尾 TTFT。

Method

optimistic accounting 先预留未来状态，event-driven update 修正实际完成/淘汰；ghost-hit 调整 PC/PIC 容量；基于完成时间模型选择弹性并行度和计算位置。

Architecture

worker 基于 SGLang 的 radix tree 与 tiered storage，router 扩展 NVIDIA Dynamo cluster directory，NIXL 执行跨 worker/storage tier 传输；约 19K 行实现，7P1D、每 worker 单 GPU。

Key Innovation

首次把 distributed PIC 的 segment 状态、cache policy 与 prefill placement 放在同一控制面中，而不是把 PIC worker 放在只懂 prefix cache 的 router 后面。

Experiments

两台服务器，每台 4×NVIDIA H20-3e、2×48-core Xeon 8575C、1 TiB host memory、4×200 Gbps RDMA Ethernet；四模型与 ChatRAG-QuAC、RAGPulse、τ-bench-Retail、ChatDev 四类 workload。

Editorial Assessment

Why It Matters

agentic/RAG prompt 的可复用单元越来越碎，prefix cache 不足；Nebula 把 PIC 从单机技巧推进到真正的分布式 serving primitive。

Limitations

仅两节点 H20 集群、7P1D 配置；控制面在更大规模和更高 segment fan-out 下的开销尚未证明。论文未提供明确代码仓库 URL，复现性受限。

Editor Note

问题重要、系统实现和实验口径完整；缺少公开代码和大规模验证，使其停留在 A+ 下沿。

Abstract

Original Abstract Summary

AutoParallel formulates distributed training as graph-wide selection of valid DTensor placements under a hardware-aware cost model. It emits an ordinary PyTorch module, composes with manually parallelized dynamic regions, and makes plans inspectable and replayable.

中文摘要

系统通过 TorchDynamo/AOTAutograd 捕获前后向联合图，为每个算子枚举合法 DTensor placement，以含 NCCL/topology 的成本模型和 seeded MRF solver 求解，再物化为可由 Inductor 编译的普通 PyTorch module。

Technical Analysis

Problem

生产训练要组合 DP/FSDP/TP/SP/CP/EP 等维度，手写 recipe 成本高且容易沿用次优模式；既有自动并行常依赖专用 runtime、计划不透明、难与 PyTorch production stack 组合。

Method

图级 placement 搜索；DTensor propagation 保证候选语义合法；成本模型覆盖 compute 与 redistribution collective；split-dimension seed + Hamming-ball MRF 缩小高维搜索。

Architecture

TorchDynamo + AOTAutograd 捕获 joint graph，DTensor/DeviceMesh 表示 placement，local_map 固定用户控制区域，TorchTitan GraphTrainer/Inductor 执行并重叠通信；输出支持 eager/compile、mixed precision、activation/distributed checkpoint。

Key Innovation

把 named parallelism 降解为 per-operator placement 的涌现结果，同时保留动态 MoE/CP 区域的显式控制边界；自动计划不引入第二套 runtime。

Experiments

dense、hybrid、MoE 与 long-context workload；最多 4D mesh、128×NVIDIA H100；与匹配 mesh 和 runtime optimization 的专家 TorchTitan recipe 比较，并测试 replanning、solver scalability 与 cost-model ranking。

Editorial Assessment

Why It Matters

自动并行长期难进生产，核心原因是与主框架割裂；AutoParallel 的价值在于 PyTorch-native、可检查、可回放并已进入 TorchTitan GraphTrainer。

Limitations

pipeline parallel 仍正交处理；动态 MoE/CP 区域依赖用户提供 local_map；论文代码仓库开放但其 README 表明部分能力仍处于演进，复现全部 Meta 集群结果需 H100 规模。

Editor Note

这是当日最值得读的系统工作：问题、抽象、实现和生产集成完整。复现成本与动态区域仍需人工控制，故为 S 而非 S+。

Abstract

Original Abstract Summary

ASP predicts response lengths, constructs balanced minibatches, and orders groups to smooth a multi-instance rollout stream. It runs within a decoupled generation–training architecture that keeps policy lag observable and bounded.

中文摘要

ASP 将 prompt 输出长度预测、动态规划 minibatch 构造与 batch-group 排序组合起来；多个 generation unit 承载 vLLM actor，control unit 调度并把完成样本送入 training queue，training unit 执行 reward、logprob 与更新。

Technical Analysis

Problem

RL rollout 的长度异质性造成 padding bubble、long-tail skew 和 length-sorted dispatch 引发的 queue occupancy 波动；单实例推理又很快遇到扩展平台。

Method

对固定 prompt 集离线预测长度并构造均衡 minibatch；按训练队列状态调整 group ordering；通过 generation/training 解耦提高资源利用，同时监控并限制 policy staleness。

Architecture

Training Unit、多个 Generation Unit、Control Unit、受控 Training Queue；GU 内运行多 vLLM actors；原型基于 MindSpeed-RL/Ascend 910B3。

Key Innovation

不是只做 length sorting，而是把三类 bubble 纳入同一调度管线，并把 arrival smoothing 与 bounded-lag 异步训练连接起来。

Experiments

最多 128×Ascend 910B3；Deepscaler 约 41K 数学题用于吞吐/扩展，Maze-Reasoning-GRPO-v0.1 超 180K 用于收敛；模型含 Qwen3-30B-A3B/32B/8B；对比 MindSpeed-RL 与 verl。

Editorial Assessment

Why It Matters

rollout 已成为 reasoning RL 的主要成本中心，ASP 给出了可操作的多实例调度和异步流水线分解。

Limitations

原型限 Ascend 生态；未直接比较 StreamRL、AsyncFlow、AReaL、Laminar；最多 128 NPU；离线 scheduler 假设 prompt 集预先已知，不适合完全在线数据生成。

Editor Note

实验与局限披露充分，但跨硬件和在线场景泛化尚未证明，代码状态未披露，评为 A。

Abstract

Original Abstract Summary

RPEG represents an RL training pipeline as a data-centric graph whose structure and execution plan are optimized together. It exposes sharing and staleness choices, lowers the graph into scheduled operations, and models compute, communication, memory, and hierarchy.

中文摘要

RPEG 把 RL pipeline 的跨 step 状态、模型角色与 stage dependency 表成可展开的 execution graph，在结构层搜索异步程度和 actor/critic 共享，在执行层搜索 stage fusion、placement、微批和多维并行，并用分层硬件模型评分。

Technical Analysis

Problem

推理模型 RL 每步耦合多模型、异构阶段、跨步状态和异步依赖；现有系统通常只优化 rollout、colocation 或某个调度层，难以联合权衡吞吐、显存与 staleness。

Method

构建 RLM Pipeline Execution Graph；unroll 跨 step dependency，lower 到 runtime graph；局部搜索结构与 execution plan，性能模型覆盖 GEMM、非 GEMM、collective、reshard、KV/activation/optimizer memory。

Architecture

data-centric graph IR + distributed runtime；支持 actor/critic sharing、bounded asynchrony、stage fusion、fine-grained scheduling、DP/TP/PP 等并行；按 rack/node/GPU 分层建模通信。

Key Innovation

把 RL 算法结构选择与系统执行计划放进同一个可计算图和同一个搜索目标，而不是先固定 pipeline 再局部优化。

Experiments

最多 256×NVIDIA GH200；对比 ReaL 和 verl，覆盖不同模型/集群层级与结构配置；报告 step latency、throughput、hardware utilization、model accuracy 与性能模型校准。

Editorial Assessment

Why It Matters

reasoning RL infra 的真正难点是跨模型/跨 step 的组合爆炸；RPEG 提供了可分析、可搜索的统一中间表示。

Limitations

搜索与性能模型依赖硬件校准，未证明对所有 RL 算法和非 NVIDIA 集群都准确；代码开放但完整复现实验需要大规模 GH200。论文未设置独立 limitations 节，本报告把这些作为分析推断。

Editor Note

抽象和性能模型极其完整，规模也强；但模型驱动搜索的可迁移性与高昂复现门槛使其略低于 S。
