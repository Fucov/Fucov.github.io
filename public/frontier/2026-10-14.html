Abstract

Original Abstract Summary

FastEEP separates reusable execution structures from resources activated by the current expert-parallel configuration. It coordinates reclamation and reconfiguration across worker execution, GPU memory and communication, enabling intra-instance EP resizing without full teardown.

中文摘要

该系统将 EP 配置视为可变化的资源激活集合，保留构建代价高的运行时状态，仅重配与新 EP size 相关部分。

Technical Analysis

Problem

按实例增删无法细粒度改变 MoE EP 宽度，完整重启带来长 scaling pause。

Method

Partial Reuse；将 execution structure 与 active resources 解耦，并协调 worker/memory/communication reconfiguration。

Architecture

Serving instance → reusable runtime state + EP-specific active resources → coordinated resize controller。

Key Innovation

把弹性粒度从实例下推到实例内部的 EP group。

Experiments

多模型、相对 vLLM baseline 的 resize latency；摘要没有端到端流量、绝对秒数和 GPU 细节。

Editorial Assessment

Why It Matters

MoE 服务容量随负载变化时，EP 重配速度直接影响成本与 SLO。

Limitations

证据只给倍数；请求处理是否暂停、KV 保留和故障语义需查全文；代码未确认。

Editor Note

明确的系统切口和较强潜在影响，但证据披露有限，因此为 A。

Abstract

Original Abstract Summary

QBA combines predicted short-first admission with quota-bounded, debt-enforced promotion of aged predicted-long requests. A reduced M/G/n surrogate explains mean trends, while an event simulator models decode-priority batching, chunked prefill, token budgets and KV-safe admission.

中文摘要

QBA 在短作业优先与公平性之间引入可控配额：老化请求只能按预算晋升，未使用的公平份额形成 debt，从而避免两种极端策略。

Technical Analysis

Problem

长度预测可降低平均延迟，但误差和拥塞会使长请求尾延迟恶化。

Method

short-first admission + quota/debt aging + queueing surrogate + event-driven simulator。

Architecture

Arrival classifier → predicted class queues → quota/debt promotion → continuous batching scheduler。

Key Innovation

用配额限制 aging 的影响范围，使公平性机制不完全吞掉预测收益。

Experiments

模拟 synthetic 与 production-derived workload；比较 FCFS、short-first、aggressive aging。无实机结果。

Editorial Assessment

Why It Matters

调度策略无需修改模型或 kernel，部署成本低；对 tail SLO 有直接价值。

Limitations

全为模拟，长度 predictor 和 KV 行为简化；缺少绝对数字与开源实现确认。

Editor Note

有会议接收与合理模型，但实机证据不足，按 B 入选。

Abstract

Original Abstract Summary

The study implements a real Hugging Face continuous-batching testbench and evaluates eight policies over 1,152 GPU-model-scheduler-workload runs. It finds that scheduler choice changes throughput, TTFT, completion latency and tails, and that oracle remaining length alone is insufficient because batching and hardware effects matter.

中文摘要

该工作更像系统化基准而非新 runtime：它通过真实 GPU 执行揭示，同一调度策略无法跨硬件与流量稳胜，长度 oracle 也不能替代对 batching/hardware 的建模。

Technical Analysis

Problem

轻量调度的跨 GPU 稳健性缺少大规模真实执行证据。

Method

Python/PyTorch continuous batching testbench，八策略全因子比较。

Architecture

Arrival workload → policy queue → token-level batch builder → HF model execution on L40S/A100/H100。

Key Innovation

将 policy、GPU、模型与 traffic 交叉评估，避免只在单硬件得出普遍结论。

Experiments

1,152 runs；6 models；3 GPU classes；ShareGPT-derived traffic。数据集已上传 Hugging Face，代码状态未核实。

Editorial Assessment

Why It Matters

为 serving scheduler 选择与自适应策略提供更可靠 baseline。

Limitations

测试床不等同于 vLLM/SGLang production runtime；摘要缺绝对与分项数字。

Abstract

Original Abstract Summary

RankLens emulates one survivor rank on a single GPU while preserving task-dependent distributed semantics. It runs real local computation and replaces collectives at communication boundaries with recorded values and recorded or estimated timing, including asynchronous dependencies.

中文摘要

它不是缩小模型训练，而是保留一个 rank 的真实执行路径，把其他 rank 的通信效果“回放”进来，因此现有 debugger 与 profiler 可以在单卡环境观察目标规模行为。

Technical Analysis

Problem

分布式训练调试和调优常需重复占用完整集群。

Method

single-rank survivor execution + communication result/timing restoration + async dependency preservation。

Architecture

Original training program → survivor rank local compute → communication interception → trace/value/timing replay。

Key Innovation

将分布式语义压缩到一个真实执行 rank，而不是仅做离线 trace simulation。

Experiments

DeepSpeed/Megatron-LM；8–64 GPUs；structure match、timing error、anomaly reproduction。硬件和 trace storage 开销摘要未披露。

Editorial Assessment

Why It Matters

能显著降低性能分析、异常复现与配置调优的集群成本。

Limitations

依赖可用 trace；跨 rank 数据相关 bug 和大规模网络拥塞可能难以单卡重现；代码未确认。

Editor Note

证据清晰且实用，若开源会成为训练可观测性重要工具。

Abstract

Original Abstract Summary

ATTUNE is a coding agent that tunes a working training recipe within a user-set GPU-hour budget. It changes one lever at a time, reuses lessons from prior campaigns, and only ships recipes that pass configuration and convergence checks.

中文摘要

系统的关键不是扩大搜索空间，而是把诊断、一次一变量试验和正确性校验组成闭环，避免自动 tuner 通过改变训练目标获得虚假吞吐。

Technical Analysis

Problem

训练 recipe 高度依赖模型、硬件、框架和数据；传统 tuner 只验证“能跑”，不能保证语义与收敛一致。

Method

coding agent + lesson catalog + one-lever experiments + objective/convergence gates + GPU-hour budget。

Architecture

Baseline recipe → agent diagnosis → controlled patch → cluster run → correctness gate → campaign memory/next action。

Key Innovation

将可执行代码修改与 loss-curve correctness 放在同一个自动调优 loop 中。

Experiments

held-out models，64–128 GPUs；Llama-405B、GLM-4.5、Mixtral、MiniMax-M2；另有最多 256 GPUs/744B 的 benchmark。具体 GPU 类型需查全文。

Editorial Assessment

Why It Matters

训练调优成本高且容易产生不可比较 recipe；ATTUNE 同时优化吞吐、成本和正确性。

Limitations

结果来自作者栈，agent 依赖诊断质量；gate 漏掉 8/24 个微弱 faulty runs；最佳增益不应替代均值。

Editor Note

10 月 14 日 Must Read。最重要的设计是 correctness gate，不是“agent 自动改配置”的表面叙事。

StageBreaker schedules the true dataflow of video RL rather than whole stages. Reward-separable policy training enables overlap with reward evaluation, loss-independent backpropagation merges two trajectory replays, and finer-grained scheduling improves balance.

中文摘要

长视频与带 CoT 的视觉语言奖励模型使 video RL 的 reward 和 training 都变重。StageBreaker 从阶段 barrier 退回到样本/依赖粒度，以释放可并行区间。

Technical Analysis

Problem

阶段式执行导致 policy 等待全部 reward、trajectory 重放两次以及 GPU 负载不均。

Method

reward-separable training、loss-independent backprop、fine-grained dataflow scheduling。

Architecture

Trajectory chunks → reward model and policy branches → dependency scheduler → merged replay/backprop。

Key Innovation

在 video RL 中用数据依赖替代固定阶段边界。

Experiments

最高 1.41×；摘要缺硬件与绝对吞吐，需全文验证不同 reward/policy 比例。

Why It Matters

RL post-training 的并行度越来越受 rollout/reward/training pipeline 而非单一算子限制。

Limitations

面向视频 RL，不一定直接迁移文本 LLM；仅最大值，代码未确认。

Abstract

Original Abstract Summary

Agentic rollout repeatedly interleaves prefills and decodes across multi-turn trajectories. Prorsa forecasts short-horizon demand from each trajectory lifecycle, allocates prefill and decode workers accordingly, and switches rollout-engine roles as workload composition changes.

中文摘要

多轮 agent 会在一次 trajectory 内不断产生新 prompt，导致 rollout 不再是一次 prefill 后长 decode。Prorsa 用轨迹生命周期预测短期负载，让 prefill 与 decode 容量动态匹配。

Technical Analysis

Problem

固定 P/D 配比无法跟随不同任务与时间段的 rollout 结构，colocation 又产生 attention module 干扰。

Method

trajectory lifecycle observation、short-horizon demand forecasting、worker allocation 与 engine role switching。

Architecture

Agent trajectories → demand predictor → P/D allocator → switchable rollout engines → synchronous/asynchronous learner。

Key Innovation

把 PD disaggregation 从在线服务扩展到训练 rollout，并以轨迹级预测闭环调配。

Experiments

同步/异步 agentic RL；1.11–4.05×。摘要未列硬件、模型与 forecast overhead。

Editorial Assessment

Why It Matters

rollout 已成为在线 RL 的主要成本；多轮 agent workload 特别适合动态 P/D。

Limitations

最大加速跨度大且实验条件摘要未披露；预测误差、权重更新与 KV 迁移成本需全文验证。
