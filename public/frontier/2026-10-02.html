Abstract

Original Abstract Summary

This release consolidates 779 pull requests. Its main systems changes include live role switching between prefill and decode instances, a Rust prefix-cache core enabled by default, expanded speculative decoding and expert-parallel support, and targeted optimizations for DeepSeek-V4.1 and Kimi K3.

中文摘要

本次版本不是简单模型兼容更新，而是同时改动调度、缓存、P/D 解耦、投机解码、MoE 与 CUDA Graph 路径。动态 P/D 角色切换无需重启，prefix cache 默认迁移到 Rust core，并扩展多种硬件镜像。

Technical Analysis

Problem

生产 serving 需要在 workload 变化时调整 P/D 配比，同时减少 Python cache/scheduler 开销，并让新模型在长上下文、MoE 和投机路径上达到稳定性能。

Method

运行时切换 P/D role；默认 Rust prefix cache；模型专项 kernel/graph 路径；扩展 EAGLE/MTP/DFlash、DeepEP v2 和量化 KV。

Architecture

Rust scheduler/cache core → dynamic prefill/decode instances → model runner → attention/MoE/speculative backends → CUDA Graph / heterogeneous images。

Key Innovation

把弹性 P/D 角色重配置与低层 cache/runtime 重构合并进主线版本，而非依赖外部 orchestration 重启实例。

Experiments

官方 release notes 汇总 DeepSeek-V4.1、Kimi K3、LFM2-VL、GLM-5.3、H20/B200/SM100 等路径；关键条目附 PR 级 micro/端到端数字。

Editorial Assessment

Why It Matters

SGLang 已是用户重点跟踪的 serving 主线；动态 P/D、Rust cache 和新模型专项优化直接影响集群部署与启动后的稳态效率。

Limitations

发布包含 779 PR，变更面极广；不同优化的 benchmark 条件不统一，部分数字来自单 PR；升级需要完整回归精度、graph capture 与 PD connector。

Editor Note

今日首读。先看 dynamic P/D、Rust cache、DeepSeek/Kimi 和 MoE 四组变更，再根据现有部署模型决定是否升级。

Abstract

Original Abstract Summary

MegaFlux addresses routing skew in persistent MoE megakernels. An on-device planner chooses hot-expert replicas and tile-aligned token assignments, while forward and backward executors pipeline replica-weight movement and replica-gradient reduction with expert computation.

中文摘要

固定专家放置会让热专家所在 GPU 成为瓶颈。MegaFlux 在设备侧决定复制位置和 token tile 分配，副本权重一到即可开始计算；反向阶段再把副本梯度归并与其他专家计算重叠。

Technical Analysis

Problem

Megakernel 消除了 stage boundary，却仍受固定 expert placement 限制；动态复制又引入权重搬运与梯度回传，若串行执行会吞掉收益。

Method

设备侧 replica planner；tile-aligned assignment；forward weight-streaming；backward gradient-reduction overlap；每 GPU replica budget。

Architecture

Router outputs → on-device replication planner → persistent forward/backward MegaMoE kernel → streamed weights / reduced gradients → owner experts。

Key Innovation

第一次把动态专家复制的控制与数据路径嵌入 forward/backward megakernel，并保持 router output 不变。

Experiments

8×NVIDIA B200；Qwen3/OLMoE trace-derived skew；147 configurations/direction；TensorRT-LLM CuTeDSL kernel 与 vLLM DeepSeek-V4-Pro integration。

Editorial Assessment

Why It Matters

它直接连接 MoE scheduling 与 megakernel：仅融合通信/计算不足以解决 routing skew，placement 也必须进入设备侧运行时。

Limitations

单节点 8×B200；代码未公开；planner 与 replica budget 在跨节点、不同 NVLink 拓扑上的收益未知。

Editor Note

今日必读。用户正在关注 megakernel 与 MoE 通信，这篇最值得拆解 planner/executor 边界和 backward overlap。

Abstract

Original Abstract Summary

The paper isolates GPU-initiated RDMA mechanics from library overhead using minimal GPU and CPU-proxy transports. It benchmarks them against NVSHMEM IBGDA, NCCL GIN, DeepEP, UCCL-EP, MSCCL++, and fabric-lib across H100, H200, B200, and GB200.

中文摘要

论文不再只比较库的端到端快慢，而是逐层测量 work request 构造、doorbell、completion scope、queue placement、SM clock 和 NIC connection pressure，并给出可复现实验代码。

Technical Analysis

Problem

MoE fine-grained communication依赖 GPU-initiated path，但库级 benchmark 混入 queue 管理、memory ordering 与 completion scope，难以判断瓶颈究竟来自硬件还是软件。

Method

mini-gda/mini-proxy 对照；单操作 latency；doorbell batching；queue parallelism；bulk traffic isolation；active connection sweep。

Architecture

GPU thread / CPU proxy → work-request queue → doorbell → ConnectX-7 NIC → InfiniBand fabric → completion path。

Key Innovation

首次以机制级最小传输拆分 GPU-initiated 与 CPU-proxy 路径，并量化资源占用和连接规模对 MoE A2A 的反直觉影响。

Experiments

H100/H200/B200/GB200；NVSHMEM 3.4.5/3.7.2、NCCL 2.30.7/2.31.2、DeepEP、UCCL-EP、MSCCL++、fabric-lib。

Editorial Assessment

Why It Matters

对 NVSHMEM/DeepEP 优化尤其直接：GPU 发起并不自动更快，queue isolation、doorbell batch 和 active connection 才决定最终性能。

Limitations

平台集中 NVIDIA + InfiniBand/ConnectX-7；microbenchmark 到完整模型端到端的映射仍需 workload-specific validation。

Editor Note

与用户当前 NVSHMEM/多 stream 工作高度相关。应重点读 queue sharing、SM residency 与 CPU proxy 对照。

Abstract

Original Abstract Summary

MoE-CORE coordinates complete-layer staging during prefill with nonuniform layer-wise cache capacity, domain-informed initialization, routing-history-aware replacement, and cross-layer prefetching during decode. An optional low-score expert substitution mode trades small approximation for latency.

中文摘要

系统观察到 prefill 与 decode 的访存模式不同：prefill 适合双缓冲整层 staging，decode 则需要按层分配不同 cache 容量并根据 routing history 预测下一层专家。

Technical Analysis

Problem

MoE 总权重远超边缘 NPU 内存，朴素按专家临时搬运受 PCIe/host-device transfer 限制，TPOT 会随模型规模急剧恶化。

Method

prefill 双缓冲 layer staging；decode 非均匀 cache；domain hot-expert warm start；history-aware replacement；cross-layer prefetch；可选近似 substitution。

Architecture

Router → layer-aware expert cache → host/NPU transfer scheduler → alternating prefill buffers / decode prefetch → MTP。

Key Innovation

把 phase-specific staging、cache allocation、routing history 与近似 miss handling 放入统一专家驻留系统。

Experiments

DeepSeek-V4-Flash-W4A8、GLM-5.2-W4A8C8；每模型五类 workload；84GB NPU memory cap；对照 vLLM Prefetch。

Editorial Assessment

Why It Matters

说明国产 NPU/紧凑 appliance 也能承载数百 B 到 T 级 MoE，但收益高度依赖 expert residency，而不是单一 quantization。

Limitations

主对照的输出上限不同（MoE-CORE 1K、vLLM Prefetch 128），极端倍数需谨慎；部分最佳结果使用近似 substitution；平台主要 Ascend。

值得读，但必须连同 benchmark asymmetry 一起看。真正可迁移的是 phase-specific residency 设计。

Abstract

Original Abstract Summary

RapidMoE exploits cross-asymmetry between skewed MoE routing and heterogeneous CPU-GPU hardware. It splits expert representation into a critical path and a residual path, aligns routing and computation with device capability, and adapts the critical expert set online.

中文摘要

现有方案要么搬完整专家挤爆 PCIe，要么让 CPU 承担过多计算。RapidMoE 将权重/计算分成关键与残差部分，在 GPU 与 CPU 上并行执行，再用多级重要度仲裁动态调整精度—延迟边界。

Technical Analysis

Problem

超大 MoE 在 CPU-GPU 混合设备上同时受到 PCIe 带宽和 CPU 算力限制，专家级 offloading 粒度过粗。

Method

bit-level residual split；dual-path routing；storage-compute balanced scheduling；Unified Multi-Level Importance Arbitration。

Architecture

Router importance → critical expert/bit path on GPU + residual path on CPU → overlapped execution → merged output。

Key Innovation

把卸载单位从 expert 降到 residual bit representation，并将路由稀疏性与硬件非对称性显式对齐。

Experiments

多种大规模 MoE 与 heterogeneous platform；比较先进 expert offloading systems；分别报告 decode/prefill。

Editorial Assessment

Why It Matters

为单机/边缘大 MoE 提供另一条路线：不强求所有激活专家完整驻留，而是按重要度切分表示与计算。

Limitations

摘要未披露代码；近似/压缩路径的模型质量边界需要逐模型核验；结果跨平台可迁移性未知。

Editor Note

方法新颖且 EuroSys 接收，但建议优先核查 residual split 的质量—性能曲线与 baseline 配置。

Abstract

Original Abstract Summary

ePACT minimizes electricity commitment-deviation cost under request-level service requirements. A global planner updates interval energy targets, while a local controller predicts energy and completion time for capacity/clock actions and falls back to service-first decisions when deadlines are threatened.

中文摘要

数据中心可能需要提前承诺每小时用电量，少用和超用都产生不对称成本。ePACT 不只追求省电，而是动态调节副本容量和 GPU 频率，使实际能耗贴近承诺且不牺牲服务 deadline。

Technical Analysis

Problem

最低能耗并不等于最低电力成本；静态功率上限无法同时应对请求波动、承诺剩余额度与非对称偏差价格。

Method

global hourly target planner；local configuration predictor；asymmetric deviation objective；deadline filter；异步 coarse-to-fine action search。

Architecture

Trace + commitment meter → global target → local capacity/clock controller → serving pool → feedback energy/SLO。

Key Innovation

将 procurement commitment tracking 引入 LLM serving，并把 GPU 数量/clock 两级控制与 request deadline 统一。

Experiments

H20/H200 pool；single-hour comparisons、controller ablation、24-hour trace simulation；vLLM baseline。

Editorial Assessment

Why It Matters

推理基础设施优化开始从 joules/request 走向真实电价合同与集群运营约束，适合大规模在线服务。

Limitations

主要是 trace simulation；未公开代码；依赖能耗/完成时间预测准确性与 GPU clock control 权限。

Editor Note

值得能源/调度团队读，纯 kernel 研究者可略读。关注 objective 如何区别“省电”和“省钱”。

Abstract

Original Abstract Summary

Leto exploits hardware-operable failures where GPUs and nodes remain usable. It retains working model and reusable process state, preinitializes missing state in a shadow trainer, and protects consistency through two-tier erasure coding and chunk-level transactional updates.

中文摘要

传统容错把训练进程失败等同于硬件丢失，因此重新加载 checkpoint、重算进度并重建 CUDA/通信状态。Leto 区分可原地恢复的故障，直接复用存活硬件上的最新状态。

Technical Analysis

Problem

大量故障只杀死 trainer process，硬件仍健康；checkpoint-based recovery 却让全部 GPU 等待加载、重算和初始化。

Method

working-state retention；reusable process-state preservation；shadow trainer；two-tier erasure protection；chunk transactional update；OOM-aware reclaim。

Architecture

Active trainer + retained model state + shadow trainer → failure detector → in-place takeover → crash-consistent state repair。

Key Innovation

把故障类型细分为 hardware-operable failure，并绕过 checkpoint/recompute 主路径实现同机原地接管。

Experiments

6/72×A100；Kimi-MoE 等训练配置；checkpoint baselines；memory pressure/correctness tests；131,072 GPU simulation。

Editorial Assessment

Why It Matters

训练规模越大，恢复时间越可能成为有效利用率瓶颈；Leto 把“存活硬件上的最新状态”变成可复用容错资源。

Abstract

Original Abstract Summary

TACO derives an exact steepest-descent direction under a normalized 1-to-1 operator norm. For each matrix column it selects the sign of the maximum-magnitude gradient entry and stores only a small set of low-precision components, making persistent optimizer state nearly negligible.

中文摘要

与压缩 Adam state 或低秩投影不同，TACO 从更新几何出发，将每列更新压成一个三值单稀疏方向。它仍使用一阶梯度，且针对 AdamW 预训练模型避免 Muon 几何不匹配。

Technical Analysis

Problem

全参数微调的 optimizer state 常比权重/梯度更占显存，使 13B 以上模型必须多卡或 offload；现有降内存方法可能损失精度或 runtime。

Method

dimension-normalized operator norm；column-wise max selection；ternary one-sparse update；低精度 gradient component state。

Architecture

Backward gradients → column max/sign extractor → compact persistent state → sparse update direction → dense parameter update。

Key Innovation

不是压缩 Adam moments，而是选择可精确求解、天然产生单稀疏方向的优化几何。

Experiments

OPT-13B 与 30–32B 多模型/任务；对比 AdamW8bit、Muon、GaLore、APOLLO-Mini 等；代码与 sweep 工具公开。

Editorial Assessment

Why It Matters

若精度可稳定复现，它能把单卡全参微调规模推到 30B 级，直接改变小团队后训练资源门槛。

Limitations

更新几何与 AdamW 不同，跨任务鲁棒性需更广复现；公开仓库较新；分布式 ZeRO/FSDP 下的通信收益未系统报告。

值得复现。优先核对 accuracy parity、state accounting 和不同 learning-rate sweep，而不是只看 174×。
