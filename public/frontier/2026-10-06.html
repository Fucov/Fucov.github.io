Abstract

Original Abstract Summary

MOLT co-locates inference and opportunistic PEFT by allowing inference to reclaim individual saved activations from an in-flight tuning step. The backward pass recomputes reclaimed activations, while asynchronous-aware protection and coordinated tensor-parallel unbacking prevent use-after-release.

中文摘要

传统副本扩缩容无法回收秒级波动的 KV/激活空闲内存；样本级交接又会丢弃训练进度。MOLT 把回收边界细化到激活槽位，并用重算换取安全、连续的服务优先内存让渡。

Technical Analysis

Problem

推理副本内部存在短时空闲 HBM，但训练共置必须在请求超时前交还内存，且不能破坏正在执行的异步 GPU 工作。

Method

activation-slot handover、backward recomputation、CPU–GPU 异步安全保护、TP rank 协同 unback。

Architecture

Trace-driven inference replica → shared activation allocator → protected slots → PEFT forward/backward → on-demand recompute。

Key Innovation

把“服务优先”的内存回收从整样本/整 step 下沉到单激活，并保留训练进度。

Experiments

Mistral-Small-24B 与 Llama-3.1-70B 等四个部署，H100/B200，TP=1/2/4，真实请求 trace；对照 LLMStation、SIRIUS 与 step-level handover。

Editorial Assessment

Why It Matters

直接解决在线服务与后台微调共置时 HBM 无法弹性回收的问题，兼顾 SLO 与训练产出。

Limitations

依赖可控 allocator/recompute；重算开销受模型与序列长度影响；尚缺跨节点和更多训练算法验证。

Editor Note

今日首读。尤其值得复现的是异步保护窗口与 TP 一致 unback 机制。

Abstract

Original Abstract Summary

SyclKittens is a hardware-aware tile programming model for Intel Max GPUs. It exposes XMX-compatible register layouts, cache-prefetch data movement, and topology-aware peer communication while retaining programmable workload policies for engineers and coding agents.

中文摘要

论文把“给智能体什么接口”视为 kernel 性能的核心变量：raw SYCL 暴露能力但不编码最佳实践，SyclKittens 则把矩阵引擎布局、预取路径和节点拓扑固化为可组合原语。

Technical Analysis

Problem

新加速器的硬件能力先于高质量 kernel 生态到来，通用接口让程序员和智能体很难稳定逼近厂商库。

Method

tile abstraction、SIMD16/XMX layout、partial-tile prefetch、peer-memory primitives、agent-in-the-loop refinement。

Architecture

Coding agent/programmer → SyclKittens policies → Intel-specific lowering → XMX/L1/XeLink → LLM kernels。

Key Innovation

用“编码硬件最佳实践的 DSL”缩小 agent 生成 kernel 与厂商库之间的差距，并覆盖单卡到节点级通信。

Experiments

Intel Max 1550；三种 coding model/三类 kernel 的受控实验；27 个 GEMM shape；Llama-3.1-8B 单/多 GPU 推理。

Editorial Assessment

Why It Matters

为非 CUDA GPU 提供可编程、可由 agent 使用的性能路径，直接降低新硬件 kernel 冷启动成本。

Limitations

主要验证 Intel Max；需要为新代 Intel/其他架构重做 lowering；与 oneDNN 对比不等于完整 serving engine 对比。

Editor Note

今日首读。它同时是 kernel DSL、agent interface 与多 GPU runtime 研究。

Abstract

Original Abstract Summary

HiNa-MoE accelerates CPU-side MoE operators without requiring framework allocator or weight-layout changes. It combines AMX microkernels, fused token gathering/stores, page-interleaving-aware NUMA partitioning, and decode-phase matrix-vector to small-matrix conversion.

Technical Analysis

Problem

CPU-GPU MoE offload 中专家权重巨大、每专家 token 少，通用 GEMM 和跨 socket 流量效率低。

Method

AMX microkernel、fused gather/store、page-interleaved NUMA partition、MV-to-MM conversion。

Architecture

Router tokens → NUMA task partition → gather/transform → AMX expert FFN → store/scatter → attention optimization。

Key Innovation

Experiments

Xeon 6430/6448H/Max 9462；Mixtral、DeepSeek-V3、Qwen3-235B 等；对照 IPEX、KTransformers、oneDNN。

Editorial Assessment

Why It Matters

为 GPU HBM 不足场景提供可插拔 CPU 专家执行路径，尤其适合大 MoE 本地/私有部署。

Limitations

主要是 Intel AMX；代码未明确公开；端到端收益取决于 CPU-GPU 传输与专家放置。

Abstract

Original Abstract Summary

HALO combines a feedback-based search for per-layer SM partitions with a stage-unified scheduler. Base and LoRA computations overlap spatially, while request-level slack and an output-token queue reshape traffic across prefill and decode.

中文摘要

Technical Analysis

Problem

资源有限的本地部署需要同时保障不同服务的 TTFT/TBT，而 blind batching 和 LoRA 额外计算放大过载。

Method

feedback partition search、SM spatial multiplexing、request-level slack、stage-unified scheduling、token traffic shaping。

Architecture

Requests → slack scheduler → prefill/decode unified queue → base/LoRA SM partitions → output token queue。

Key Innovation

同时解决 LoRA operator 重叠与多 SLO 时序调度，而不是只优化 kernel 或公平性。

Experiments

医院/服务中心 trace，Llama/Qwen 多尺寸模型，多 GPU 平台；对照 vLLM/SGLang 及 multi-LoRA/SLO baseline。

Editorial Assessment

Why It Matters

将多租户 LoRA 服务从“尽力而为”推进到可审计的异质 SLO 管理。

Limitations

搜索和调度参数需按硬件/LoRA 注入点校准；代码未公开；场景主要是单机本地服务器。

Editor Note

Abstract

Original Abstract Summary

PhaseGate calibrates separate CPU-retrieval concurrency limits for LLM prefill and decode on unified-memory M4 systems. It admits more work during the less sensitive phase and restricts retrieval during bandwidth-sensitive decoding.

中文摘要

统一内存下 CPU 检索与 GPU 推理共享带宽，但两个 LLM 阶段的干扰敏感度差异很大。PhaseGate 用实时阶段而非固定时间表控制 CPU 并发。

Technical Analysis

Problem

端侧 RAG/agent runtime 中 CPU 检索会与 GPU decode 争用 UMA 带宽，固定并发无法兼顾吞吐与尾延迟。

Method

phase observation、per-phase calibrated limits、backlogged admission、held-out validation。

Architecture

Retrieval queue → PhaseGate → CPU workers ↔ unified memory ↔ GPU LLM prefill/decode。

Key Innovation

用 LLM phase 作为跨处理器 admission signal，简单但能显著改善尾延迟-吞吐权衡。

Experiments

两台 Apple M4 系统；4/1 并发配置；7 次 held-out；对照 fixed policy 与 phase-blind TimeGate。

Editorial Assessment

Why It Matters

端侧 unified-memory agent/RAG 不能假设 CPU 任务与 GPU 推理彼此独立。

Limitations

仅 M4 与饱和检索；workshop 论文；未覆盖 NPU、真实多用户和能耗。

Editor Note

值得作为端侧 runtime 的低复杂度控制基线。

Abstract

Original Abstract Summary

RESOLVE first instruments executions to expose nondeterministic races, then uses an agent to rewrite candidate and reference kernels into bitwise-matching reduced-concurrency forms, and finally proves real-number computational equivalence in F*/Pulse.

中文摘要

随机输入加数值容差无法可靠发现 race，也会掩盖错误。RESOLVE 先动态扩大失败可见性，再把并发结构降维，最后用形式化证明绕开容差争议。

Technical Analysis

Problem

AI 生成/优化 kernel 的正确性难靠有限测试和浮点容差保证，尤其是 race 与 megakernel。

Method

binary timing perturbation、agent reduction、bitwise test correspondence、F*/Pulse proof。

Architecture

Candidate/reference → race testing → reduced-concurrency rewrite → equivalence proof → repair loop。

Key Innovation

把动态测试、智能体重写和形式证明组合为跨 CUDA/DSL 的统一验证管线。

Experiments

KernelBench、CUTLASS/Triton/Gluon fused GEMM、megakernel case studies 与修复实验。

Editorial Assessment

Why It Matters

kernel agent 若没有强验证器，性能搜索会把隐蔽错误带入生产；RESOLVE 提供可组合的安全闭环。

Limitations

形式证明依赖成功的并发归约与 F* 模型；自动化覆盖率、证明成本和代码可用性仍需验证。

Editor Note

Microsoft Research 的强信号；可视作 kernel-agent 基础设施而非普通 benchmark。

Abstract

Original Abstract Summary

CommuteProp separates a split-learning iteration into a cross-block forward/backward phase and a concurrent in-block update. Communication and computation overlap, while a Newton–Schulz-style preconditioner mitigates staleness and the paper analyzes asynchronous convergence.

中文摘要

同步 split fine-tuning 让客户端在等待服务端梯度时空转。CommuteProp 将数据依赖较弱的局部更新移出关键路径，使周期从阶段总和趋近于最慢阶段。

Technical Analysis

Problem

隐私 split LLM 微调受制于顺序通信-计算链路和客户端空转。

Method

decoupled concurrent phases、communication overlap、staleness-aware preconditioning、convergence proof。

Architecture

Client block ↔ activation/gradient link ↔ server blocks；cross-block pass 与 local update 双流水并发。

Key Innovation

在保留 split-learning 数据边界的同时重排反向传播和参数更新，显式控制陈旧误差。

Experiments

多网络带宽/模型配置，对照同步 split learning 与异步变体；测吞吐、收敛和 staleness。

Abstract

Original Abstract Summary

SNACK provides a genuinely sparse PyTorch layer whose storage, forward pass, restructuring, and backpropagation remain sparse. Its SNACK-COO CUDA SpMM kernel maps batches to SMs for the small-batch, high-sparsity regime common in training and single-stream inference.

中文摘要

很多“稀疏训练”仍在 dense tensor 上做掩码，理论 FLOP/内存节省没有兑现。SNACK 从数据结构、梯度到 kernel 全链路只处理非零连接。

Technical Analysis

Problem

masked dense sparsity 无法兑现高稀疏率下的计算、显存与能耗收益，通用 SpMM 又不适配小 batch。

Method

sparse layer API、dynamic connectivity、COO SpMM、batch-to-SM mapping、sparse backward。

Architecture

PyTorch sparse layer → connection restructure → SNACK-COO forward/backward → GPU SM scheduling。

Key Innovation

训练与推理全流程保持真正稀疏，并针对 DST/单流场景优化 kernel。

Experiments

90%–99% 稀疏；Dense+Mask、dense、cuSPARSE、Sputnik、FlashSparse；层级、GPT-2 和 graph workloads。

Editorial Assessment

Why It Matters

将动态稀疏从算法承诺转化为可测的 GPU 内存和速度收益。

Limitations

LLM 实验主要为 GPT-2 级别；COO 优势集中在高稀疏/小 batch；现代 Transformer 大规模训练仍待验证。

Editor Note

因有真实系统与 kernel 贡献，纳入训练主线；不把图 workload 的 4.8× 外推到 LLM。
