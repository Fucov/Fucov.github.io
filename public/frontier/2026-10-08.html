Abstract

Original Abstract Summary

CoMoE targets expert-parallel MoE inference on consumer GPUs whose traffic must traverse host memory. It writes each remotely routed token to a shared host buffer once, lets destinations pull it in parallel, and replaces bulk-synchronous combine with token-level host staging and completion-driven aggregation.

中文摘要

消费级 GPU 计算和显存带宽可观，但缺少 NVLink/P2P，使 MoE dispatch/combine 的冗余传输与全局同步成为主瓶颈。CoMoE 以主机为中心重写通信语义，用一次写入的 token multicast 和按 token 完成的异步聚合削减 PCIe 压力。

Technical Analysis

Problem

标准 All-to-All 在无 P2P 的 RTX 多卡上重复发送同一 token，并让所有 GPU 等待最慢 rank；通信可占 prefill 时间 81.6%。

Method

host-backed token multicast、destination pull、host staging、one-sided deposit/drain、pipelined reduction 与 NUMA-aware buffer placement。

Architecture

GPU router → shared host token buffer/metadata → parallel destination pull → expert compute → host stash → per-token completion/reduction。

Key Innovation

顺应主机介导拓扑，把传统上视为缺陷的 host bounce 转化为软件 multicast hub，并把 MoE combine 的同步单位从 batch 降为 token。

Experiments

ShareGPT、多个现代 MoE、8×RTX 5090 与 8×A800，对照 SGLang/DeepEP，测 TTFT、TPOT、throughput、成本与 DeepResearch。

Editorial Assessment

Why It Matters

首次给出面向无 NVLink 消费级多卡的完整 MoE 数据路径，而不是缩小模型或简单 CPU offload。

Limitations

代码尚未公开；单机 PCIe/NUMA 设计难直接扩展跨节点；性能依赖主机内存与 PCIe 读写不对称；成本比较未含能耗/运维。

Editor Note

本期首读。其核心不是“便宜 GPU”，而是重新定义 All-to-All 之下的 token 语义。

Abstract

Original Abstract Summary

vLLM-Omni models heterogeneous generation as multi-stage pipelines controlled by one orchestrator. Specialized engines and stage replicas execute autoregressive, codec, diffusion, world-model and robot stages, while connectors carry large payloads and session-oriented control preserves stateful and duplex interactions.

中文摘要

多模态生成不再是单一 token decode loop：语音、图像/视频扩散、世界模型和机器人控制拥有不同的调度、状态与流式输出语义。该报告把这些差异收敛到统一 pipeline runtime，同时复用上游 vLLM 的 KV、调度与 CUDA Graph 能力。

Technical Analysis

Problem

现有 LLM server 与 diffusion stack 各自优化单一架构，生产系统只能用临时 glue code 串联多阶段模型，缺少统一 admission、streaming、data plane 和 session semantics。

Method

pipeline specification、central orchestrator、stage replicas、OmniConnector、stream demultiplexing、sticky sessions、stage-local quant/offload/compile/cache。

Architecture

API/admission → orchestrator → stage DAG + replica pools → connector data plane → streamed heterogeneous outputs；session control 维持长生命周期状态。

Key Innovation

以 stage 为统一执行和优化边界，把 AR、DiT、codec、action generator 与 full-duplex session 放入同一 control plane。

Experiments

H100/H200 nightly CI，Qwen3-Omni、TTS、image/video、world model、robot 与 duplex；报告 TTFP、RTF、throughput、WER 和失败配置。

Editorial Assessment

Why It Matters

它为“多模型拼装”升级为可调度、可监控、可部署的统一 serving runtime 提供了实际开源基座。

Limitations

不同模型的评测不可直接横比；部分 deep sleep/wake hooks 未完成；full-duplex turn-mode 存在 13% 额外语音错误，报告明确未作为有效结果。

Editor Note

Must Read。优点是工程边界披露充分，包括负结果；但读者应把模型专用优化与 runtime 通用收益分开。

Abstract

Original Abstract Summary

ResidualQuant exploits cross-loop similarity in looped Transformers. It stores the final-loop KV state as a reference and quantizes other loops as residuals, adding least-squares scaling, rotations and loop-wise mixed precision to preserve quality while enabling efficient reconstruction.

中文摘要

参数共享的循环 Transformer 节省权重却会为每轮累积 KV。ResidualQuant 观察到各轮 KV 彼此相似，因而把冗余表示改为 reference 加低位残差，使 2-bit 压缩仍能接近 BF16 质量。

Technical Analysis

Problem

loop 数增加时 KV 仍线性增长；通用低比特 KV 量化在 INT2 下精度损失明显。

Method

final-loop reference、residual coding、least-squares scale、rotation、loop-wise mixed precision 与 fused reconstruction。

Architecture

Per-layer loop KV → reference selection → residual transform/INT2 pack → paged storage → on-demand dequant/reconstruction → attention。

Key Innovation

把循环维度的结构冗余转化为可量化 residual，而非对每个 loop KV 独立压缩。

Experiments

多个 looped Transformer、数学/代码 benchmarks、rotation baselines、RTX 5090 fixed/peak batch throughput。

Editorial Assessment

Why It Matters

循环架构若进入主流，KV 会成为其隐藏成本；该方法把模型结构与 runtime cache representation 联合设计。

Limitations

只适用于 looped Transformer；理论压缩率与端到端峰值依赖 batch/shape；代码未公开，通用 paged-KV integration 待验证。

Editor Note

结果很强，但适用面窄于 KIVI/QuaRot 一类通用 KV quant；因此评分低于 CoMoE 与 vLLM-Omni。

Abstract

Original Abstract Summary

The work represents speculative decoding as a Markov reward process and derives an Expected Decoding Rounds objective. State occupancies weight local rejection costs, yielding an exact temporal-difference gradient and an offline evaluator for paired drafter comparisons on shared target-model rollouts.

中文摘要

并行 drafter 一次预测整块 token，但一轮从何处开始取决于之前接受了多少 token；局部训练目标忽略了这种跨轮耦合。EDR 直接以完成生成所需的期望轮次数为目标，从 target rollout 得到无偏梯度。

Technical Analysis

Problem

block-local loss 与真正的 decoding rounds 不一致，可能提升局部接受率却未减少整体 target passes。

Method

Markov reward process、state occupancy weighting、expected decoding rounds、exact TD gradient、offline paired evaluation。

Architecture

Target rollouts → MRP state/transition estimator → EDR loss → DSpark/DFly drafter finetuning → parallel verify runtime。

Key Innovation

把 serving 的全局 round cost 写成可训练且无辅助超参的精确目标。

Experiments

DSpark、DFly；9 个 math/code/chat benchmarks；对比多种 surrogate objective 与 mean accepted length。

Editorial Assessment

Why It Matters

草稿模型训练终于与推理调度真实开销对齐，可减少需要昂贵 target verification 的轮数。

Limitations

摘要未披露 wall-clock speedup、batch-level serving 或 kernel overhead；代码未公开；收益可能被 verify/copy 成本稀释。

Editor Note

纳入主报告但不列 Top 3：理论目标清晰，系统结果仍应补真实端到端 tokens/s 与 latency。

Abstract

Original Abstract Summary

The paper finds strong, early-stabilizing correlations in expert choices within and across MoE layers. Correlated placement co-locates experts selected together, while token shuffling uses sequence-parallel reduce-scatter to move tokens toward GPUs predicted to own next-layer experts.

中文摘要

MoE router 并非随机地产生通信：少数专家对被大量 token 共同选择，且前一层选择可预测下一层。论文把这一统计结构转化为 placement 与 token relocation，减少跨 GPU/跨节点 dispatch。

Technical Analysis

Problem

高 EP 和高 top-k 时两次 All-to-All 可占训练 step 近半甚至更多，而常规 placement 忽略 router 产生的相关结构。

Method

co-selection matrix、correlated expert placement、one-send-per-GPU dispatcher、cross-layer predictor、reduce-scatter token shuffling。

Architecture

Router traces → correlation/prediction → placement compiler → Megatron-LM EP dispatcher → attention RS-integrated token shuffle → local experts。

Key Innovation

不改 routing decision 或 expert parameters，而是从 router learned structure 推导通信布局。

Experiments

8×MI300X/node，EP8–64，top-2/top-6，Megatron-LM；测 row volume、locality、All-to-All 与 step time。

Editorial Assessment

Why It Matters

它说明 MoE 通信不必只依赖更快 collective；模型学习到的路由统计本身可成为系统优化信号。

Limitations

需要相关性稳定及周期性统计；动态负载均衡与 placement migration 成本未完全披露；代码未公开。

Editor Note

Top 3。与 DeepEP 等低层通信库正交，可叠加，且对高 top-k 模型价值更大。

Abstract

Original Abstract Summary

MemFerry combines on-GPU computation with Direct Host Access to data in CPU memory. A scheduler assigns selected parameter layers to DHA while overlapping transfers for the remainder; a shadow model unifies split storage, and GO-MemFerry adds DP-optimized gradient offload.

中文摘要

ZeRO-Offload 把 optimizer 放到 CPU，但 GPU 利用率、通信重叠和 offload 粒度仍受限。MemFerry 让 accelerator 直接访问并计算 host memory 中的数据，把“搬数据还是就地算”变成调度决策。

Technical Analysis

Problem

纯 H2D offload 传输暴露，纯 CPU update 算力不足，固定 offload policy 不能适配 forward/backward 与不同互连。

Method

DHA、hybrid execution scheduler、shadow model、gradient offload dynamic programming、adaptive multipath transfer。

Architecture

Partitioned model → shadow address space → scheduler → GPU-local compute ∥ DHA compute ∥ H2D → DP gradient offload → optimizer。

Key Innovation

在层级调度中同时选择计算位置与数据移动，并扩展到 scale-up NPU 互连多路径。

Experiments

单 GPU、8 GPU DP 与 Huawei CloudMatrix384 8 NPU；对照 ZeRO-Offload/DeepSpeed，测速度、容量与 iteration time。

Editorial Assessment

Why It Matters

为训练 offload 增加第三种选择：既非搬到 device，也非交给 CPU，而是 accelerator 直接消费 host-resident tensor。

Limitations

DHA 硬件/软件支持并不普遍；模型、batch 与互连敏感；代码未公开；摘要中的系统名有一次排版缺失。

Editor Note

结果完整且跨 GPU/NPU；实际采用取决于 Direct Host Access 的可移植性与安全隔离。

Abstract

Original Abstract Summary

Exploration-Distillation trains one or more explorer policies with aggressive novelty rewards, filters their trajectories for correctness and quality, and distills them into a separate student trained without novelty incentives. Alternating these phases scales exploration without degrading the deployment policy.

中文摘要

RLVR 的可验证奖励只覆盖模型能力的一小部分，直接对同一策略施加强探索奖励会破坏已有能力。ExpDis 把“发现新轨迹”和“稳定吸收轨迹”分到不同策略与阶段，再循环执行。

Technical Analysis

Problem

novelty bonus 能增加探索却会让 policy 远离已有强分布，而稀疏可验证奖励不足以修复整体质量。

Method

multi-explorer RLVR、novelty reward、correctness/quality filter、student distillation、iterative rounds。

Architecture

Base policy → parallel explorers/rollouts → verifier & quality filter → distillation dataset → student optimization → next exploration round。

Key Innovation

通过 actor-role separation 解耦 exploration objective 与 final policy objective，而不是在单一 PPO/GRPO loss 中折中。

Experiments

7 个 math benchmarks、2 个模型家族、同 wall-clock budget 对照 DAPO、pass@k diversity；代码与 checkpoints 公开。

Editorial Assessment

Why It Matters

为异步/多 actor RL 系统提供自然结构：探索 worker 可更激进，learner 只消费筛选后的高价值经验。

Limitations

主要是算法与训练 pipeline，不是大规模系统实现；摘要未披露 GPU 规模、通信/colocation、trajectory efficiency；数学域为主。

Editor Note

因公开代码与等 wall-clock 证据入选，但不应把它误读为 rollout 系统吞吐论文。
