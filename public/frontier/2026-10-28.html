Abstract

Original Abstract Summary

This prerelease advances TensorRT-LLM serving around KV Cache Manager V2, disaggregated serving, low-precision execution, Rubin support, and model-specific kernels. It also introduces breaking request and transceiver changes and documents a known RPC tensor-parallel initialization hang.

中文摘要

这不是单一算法论文，而是面向生产 serving 的大版本候选。核心主线是让 KV cache 的保留、跨轮复用、跨节点搬运和混合精度成为统一 runtime 能力，同时推进 Rubin/Blackwell 上的模型专用 kernel。

Technical Analysis

Problem

长对话、PD 分离和新模型结构要求 KV 生命周期跨轮、跨节点、跨精度管理；旧 KVCM 与兼容层难以继续承载。

Method

升级 KVCM V2 retention/reuse；定义 KV transfer backend contract；Mooncake 零拷贝；加入混合精度 KV 与 FP4 MLA disaggregation；收敛 API 与执行器。

Architecture

Python/C++ serving runtime + Modeling V2 + KVCM V2 + transceiver/backend contract + Mooncake/NIXL/UCX 数据面 + CUDA/CuTe DSL kernels。

Key Innovation

把此前分散的 KV reuse、connector reuse blocks、SWA fork、disaggregated FP4 与多轮状态统一进 V2 生命周期。

Experiments

官方 release note 给出功能与 CI/性能 sanity 覆盖，但没有同一硬件、模型、负载下的统一 benchmark；因此不推断总体加速。

Editorial Assessment

Why It Matters

对用户当前关注的 SGLang/TRT‑LLM serving 而言，这一版直接影响 KV 数据面、Kimi K3、Mooncake 与 Rubin 路线选择。

Limitations

prerelease；已知 RPC orchestration 复用 MPI worker pool 可能在 TP 初始化时挂起；Python wheel 使用 1.4.0rc2.post1；缺少统一性能报告。

Editor Note

优先看 KVCM V2、Mooncake zero-copy 和 Kimi K3 KDA replay buffer，而不是把几十个 PR 简化为一个“更快”结论。

Method

Abstract

Original Abstract Summary

GateRQ observes that the conditional-memory gate predicts which retrieved rows require precision. It stores rows as progressive one-bit residual codes, keeps the first level on GPU, and fetches deeper levels only for high-gate lookups, without retraining.

中文摘要

频繁访问并不等于重要：长尾实体通常稀有但 gate 更大。GateRQ先用最低精度得到 gate，再按 query 动态补读 residual code，从而优先保护真正影响输出的长尾事实。

Technical Analysis

Problem

Engram类大哈希表占用显存；按访问频率加位会优先保护低gate高频n-gram，反而伤害长尾知识。

Method

1-bit残差阶梯编码；GPU驻留第一级；根据gate排序选择 deeper levels；无需再训练。

Architecture

1-bit残差阶梯编码；GPU驻留第一级；根据gate排序选择 deeper levels；无需再训练。 系统结构围绕“把精度分配从静态行属性改为每次 lookup 的动态执行决策。”组织。

Key Innovation

把精度分配从静态行属性改为每次 lookup 的动态执行决策。

Experiments

DeepSeek‑V4.1‑Flash与另一模型；vLLM吞吐、PopQA和显存；摘要未披露完整GPU与并发配置。

Editorial Assessment

Why It Matters

条件记忆正成为新型 KV/权重之外的第三类大状态，逐查找精度可能是其服务关键。

Limitations

依赖gate与重要性的相关性；需额外不规则读取；模型和工作负载覆盖有限，代码未核实。

Editor Note

对Kimi/DeepSeek一类带外部记忆结构的模型很值得关注，但吞吐增益必须连同访问预算和质量损失一起看。

Abstract

Original Abstract Summary

The work identifies batch invariance as a missing reliability property in generated serving kernels. A plug-in combines contract-guided static analysis with dynamic bitwise tests across batch contexts and feeds failures back into the optimization loop.

中文摘要

动态batch会让同一请求与不同邻居一起执行。如果kernel把batch位置或归约顺序错误地写入结果，同一输入会发生数值变化。该工作把这类问题从事后测试前移到agent acceptance gate。

Technical Analysis

Problem

现有kernel agent只检查常规正确性和速度，忽略serving动态batch下的输入独立性。

Method

静态依赖契约 + 多batch位级动态验证 + agent反馈门；通过后才进行性能benchmark。

Architecture

静态依赖契约 + 多batch位级动态验证 + agent反馈门；通过后才进行性能benchmark。 系统结构围绕“把生产serving的可复现性属性显式加入自动kernel优化目标。”组织。

把生产serving的可复现性属性显式加入自动kernel优化目标。

Experiments

Editorial Assessment

Why It Matters
