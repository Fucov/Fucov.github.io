Abstract

Original Abstract Summary（英文概述，非原文）

The authors replace persistent per-layer token caches with learned compact memory states. A shared sparse retrieval decision selects the states required for the next input, and attention layers reconstruct the selected keys and values. Evaluation covers training from scratch and adaptation of existing language models.

中文摘要

将历史先压缩成少量末层状态，下轮输入只检索相关状态，再恢复各注意力层需要的 KV；研究同时比较从头训练与冻结主干后的适配。

Technical Analysis

Problem

长会话持续增长时，逐层保留完整历史 KV 的显存和读取成本很高；固定状态压缩又容易丢失细节。

Method

用记忆编码器写入压缩状态；对新输入计算一次稀疏索引并跨层复用，避免各层重复检索。

Architecture

历史 token → 末层记忆状态 → 共享 top-K 检索 → 对所选状态逐层恢复 KV → 当前输入注意力。

Key Innovation

同时重构持久存储粒度与检索位置；减少的是记忆状态存储和重复检索，不能把它理解成无损 KV 压缩。

Experiments

论文说明实验平台为单台 8×H100。默认压缩比 8、检索 K=64；评估包含 Qwen3.5-4B 的长上下文效率及多轮记忆任务，另有从头训练实验。

Key Results · 作者报告

作者报告，在 Qwen3.5-4B、1M 上下文实验中，相对原模型全上下文口径，记忆状态缓存缩小 1313×、prefill 延迟降低 6.9×。前者仅指状态缓存，不是进程总显存；未将这些数值当作生产 serving 承诺。

Editorial Assessment

Why It Matters · 编辑分析

对多轮和跨会话系统而言，可持久化的对象不一定是逐层 KV；存储、检索、恢复三者值得分别量化。

Limitations

需要架构适配和训练；重建的 KV 不等于原 KV，质量取决于压缩和检索。未核实独立代码仓库或部署集成。

Editor Note

复现时先分开计量索引、恢复、注意力和传输，再比较同质量预算下的完整峰值显存。

Related Work

01 · Qwen3.5

同为长上下文模型，也是适配主干；原模型保存自身注意力状态，MemOnce 加入跨层记忆恢复。

02 · PagedAttention

同样处理 KV 内存；分页改变分配方式，MemOnce 改变持久状态表示。

03 · Longformer

同样用稀疏注意力控制成本；Longformer 依赖局部/全局连接模式，MemOnce 为历史状态动态选取索引。

Abstract

Original Abstract Summary（英文概述，非原文）

The research announcement describes converting a pretrained GLM base into a recurrent-depth model. Gated residual updates, shared sparse indices, and a separate local cache for the later pass aim to make extra depth practical without retaining a second full-context cache.

中文摘要

智谱选择在预训练基座上继续训练，而非从零训练循环模型。后续迭代共享首轮稀疏注意力的选择结果，并保留自身近期窗口的 KV，以平衡深度增量与服务成本。

Technical Analysis

Problem

重复执行共享层虽然不按深度增加参数量，却仍增加每 token 计算和缓存开销；直接改造还会扰动残差分布。

Method

用逐 token 的残差更新门缓和分布变化，继续训练已有模型；稀疏索引仅首轮计算，后轮复用。

Architecture

在 750B 级底座中间选择 28 层执行两轮；第二轮可利用首轮全局稀疏 KV，并维护独立滑动窗口。

Key Innovation

参数共享、跨轮 KV 复用和核融合联合设计；新增深度不必再保留一份完整历史缓存。

Experiments

官方称在 1B、4B、30B 和 750B 级基座逐步验证；30B 有等参数但训练量不同的对照，部署硬件、并发和测试配方未充分披露。

Key Results · 作者报告

官方报告 30B 等参数对照下循环版在若干推理与长上下文任务改善，但训练计算约多 10%。生产速度未列可比较硬件、并发与输入分布，故不作为同条件加速证据。

Editorial Assessment

Why It Matters · 编辑分析

对推理引擎而言，跨轮 KV 所有权、局部窗口与索引生命周期将影响缓存布局和调度，而不只是加一层循环。

Limitations

首发公告未确认权重、训练或 serving 代码开放。等参数不等计算，报告不足以单独识别循环结构贡献。

Editor Note

优先看相同 FLOPs、KV 上限和时延预算下的消融；不要从产品吞吐倒推出 kernel 效果。

Related Work

01 · Universal Transformer

同样按深度共享权重；GLM-5.4 增量是已有大模型的继续训练与跨轮缓存设计。

02 · Huginn

同样用递归深度扩展测试时算力；这里强调两轮共享块的大规模迁移及稀疏索引复用。

03 · GLM-5

共享底座谱系；GLM-5.4 改动是循环、残差门以及部署配套，不是单纯扩大底座。
