Abstract

Original Abstract Summary

This release aggregates 717 commits across serving startup, expert-parallel communication, scheduling, speculative decoding, model support, quantization, and security. It introduces GPU-resident preloaded weights and experimental CRIU snapshots, MoonEP communication, new RL weight-transfer paths, and specialized DeepSeek-V4.1 execution.

中文摘要

本次更新的主线不是单个模型适配，而是把“启动—调度—通信—投机解码—量化”同时推进：权重可提前驻留 GPU，EP 增加 MoonEP 与 DeepEPv2 路径，调度器开始显式处理 KV backpressure 和活跃序列上限。

Technical Analysis

Problem

大规模 serving engine 既受冷启动和重启成本影响，也受 MoE all-to-all、长上下文调度、KV 压力与新模型 kernel 路径共同制约。

Method

GPU-resident preload + CRIU snapshot；MoonEP/DeepEPv2 通信；KV-aware scheduling；多种 speculative verifier/drafter；模型专项 fused attention/MoE kernel。

Architecture

CLI preload / snapshot → engine scheduler & KV manager → model runner → attention/MoE/speculative backends → NCCL/MoonEP/DeepEP fabric。

Key Innovation

把快速恢复、EP 通信、RL 权重热更新和投机解码放入同一主线 release，形成更完整的生产运行时闭环。

Experiments

release notes 汇总 DeepSeek-V4.1-Flash、Qwen/Kimi/DeepSeek 等路径与 717 commits；缺少覆盖全版本的统一 benchmark，需部署侧逐模型回归。

Editorial Assessment

Why It Matters

vLLM 是核心 serving 基础设施；快速重启、EP 和 KV/backpressure 变化会直接影响生产升级收益、SLO 与故障恢复。

Limitations

变更面大且部分功能为 experimental；官方没有统一硬件、模型、负载下的端到端对照；升级需单独验证精度、CUDA Graph、connector 与 checkpoint 兼容性。

Abstract

Original Abstract Summary

RailWave is a phase-adaptive DeepEP communication layer for irregular expert-parallel All-to-All. RailBalance redistributes each source’s traffic across eligible network rails, while a reusable topology-derived permutation schedule limits concurrent senders per receiver; a calibrated selector chooses among paths by traffic shape.

中文摘要

即使 router 与专家放置固定，跨节点 rail 使用和 incast 仍会让同一 EP 流量出现大幅延迟差异。RailWave 分别从空间分流和时间错峰整形流量，并依据 phase 的字节量、稀疏度与冲突强度选择执行路径。

Technical Analysis

Problem

MoE dispatch/combine 的不规则 A2A 会造成多 rail 利用不均和 receiver incast，单纯优化路由或 expert placement 无法消除网络层瓶颈。

Method

source-local RailBalance；拓扑派生循环 permutation；并发 sender 限制；离线校准的 phase selector。

Architecture

Router demand → RailWave selector → RailBalance / permutation schedule → DeepEP transport → NIC rails → receiver experts。

Key Innovation

将 rail-level 空间重映射与无需逐 phase 重建的时间调度结合，并只依赖源端局部信息。

Experiments

4 节点/32 GPU H800 与 H20；GLM-4.5-Air 106B 训练派生的 45 层 MoE 通信 workload；对照 Native 与单机制变体。

Editorial Assessment

Why It Matters

它把 MoE 通信优化下沉到真实拓扑与 incast，而不是假设 all-to-all 代价只由总字节数决定；代码已公开。

Limitations

评估止于 4 节点、两类 NVIDIA 平台和 replay workload；rail-symmetric 假设、跨机房网络与端到端训练收益仍待验证。

Editor Note

今日必读。对 DeepEP/NCCL 调优最有迁移价值的是 selector 特征与 permutation 的拓扑构造。

Abstract

Original Abstract Summary

Coda exploits bounded flexibility in when coding-agent sessions are admitted and how ready requests share execution. Tiered-Aging accounts for KV preparation cost across storage tiers; Compatibility-Aware admission reduces mixed-context interference; multi-worker routing combines KV residency, load, and context compatibility.

中文摘要

编码智能体在 tool call 后异步恢复，KV 状态可能分散在 HBM、DRAM 或更慢存储，且不同长度请求混跑会拖累 decode。Coda 保留进度公平性的同时，延后代价高或不兼容请求，并选择更合适的 worker。

Technical Analysis

Problem

长期 agent session 的 ready 状态不等于立即执行最有效；tiered KV 准备成本与混合上下文 decode 互相放大。

Method

Tiered-Aging state admission；Compatibility-Aware execution admission；KV/load/context-aware worker routing。

Architecture

Ready sessions → state admission → KV prepare/restore → execution admission → model iteration → multi-worker router feedback。

Key Innovation

把 agent 服务的准入拆成状态准备和执行共享两个层次，并用有限 reorder 保持进度。

Experiments

多模型、多 agent workload；single/multi-worker；对照 vLLM 与先进 coding-agent serving systems；trace analysis + replay。

Editorial Assessment

Why It Matters

stateful/agentic serving 的关键从“能否复用 KV”转向“何时准备、与谁同批、路由到哪里”，直接影响 SLO。

Limitations

代码未公开；结果依赖 trace 与 tier 配置；aging 和 compatibility 参数需要针对实际业务校准。

Editor Note

适合与现有 session affinity、KV connector 和 tool-stall scheduler 对照阅读。

Abstract

Original Abstract Summary

AFORE observes upcoming expert-token demand on the attention side of an attention–FFN-disaggregated pipeline, solves a migration-aware microbatch placement problem, and moves experts over NVLink while preceding FFN microbatches are still computing.

中文摘要

AFD 将 attention 与 FFN 变成独立流水阶段，放大了 expert imbalance，但也创造了前视窗口。AFORE 在目标 microbatch 到达 FFN 前制定放置计划，并把迁移隐藏在前序计算之下。

Technical Analysis

Problem

AFD 中过载专家直接阻塞独立 FFN stage；历史 profile 来不及应对动态 demand，而同步迁移又会暴露在关键路径。

Method

attention-side demand prefetch；microbatch-aware migration scheduler；shared-memory plan delivery；NVLink GPU-to-GPU expert migration。

Architecture

Prefill/attention workers → demand prefetcher → placement scheduler → plan queue → FFN workers + placement migrator。

Key Innovation

将 AFD 的前视 demand 与流水 overlap 窗口转化为及时、近乎隐藏成本的 expert reconfiguration。

Experiments

110B MoE；四类动态 workload；静态 placement、现有 dynamic baseline 与 ablation；profiling 显示迁移延迟可完全隐藏。

Editorial Assessment

Why It Matters

说明 disaggregation 不只是资源隔离，也能提供新的调度信息与重叠窗口；对 MoE P/D/AFD 架构很关键。

Limitations

仅单一 110B 模型；依赖高速 NVLink 和 AFD runtime；代码、跨节点结果与重配置稳定性未公开。

Editor Note

重点看 scheduler objective 是否能与现有 EP load-balancer/replica manager 合并。

Abstract

Original Abstract Summary

EdgeAgent co-designs UMA-aware tensor parallelism, asymmetric memory layouts and SME microkernels with adaptive speculative draft budgets and asynchronous suspension of tool-stalled agents for on-device multi-agent inference.

中文摘要

统一内存不等于 CPU/GPU 协同免费：decode 会争夺同一带宽。EdgeAgent 通过不对称布局和零拷贝切分算子，再依据序列可预测性控制 draft 长度，并让等待工具的 agent 主动让出执行资源。

Technical Analysis

Problem

端侧多 agent workload 的 decode 带宽争用、draft 难度波动与 tool-induced fragmentation 使静态 batching 和常规 TP 效率低。

Method

UMA-aware zero-copy TP；asymmetric layouts；SME kernels；dynamic draft budget；async suspend-and-yield。

Architecture

Agent sessions/tool events → scheduler → adaptive speculator → CPU/GPU UMA tensor-parallel executor → shared memory fabric。

Key Innovation

把硬件统一内存布局与 agent 生命周期调度合成一个跨层系统。

Experiments

Apple M4 SoC；batched speculative decoding baseline；分离测量 UMA execution 与 tool-stall scheduling。

Editorial Assessment

Why It Matters

端侧 agent 服务不能照搬数据中心 GPU 调度；内存互联与 tool wait 必须共同建模。

Limitations

仅 Apple M4；模型规模、能耗与长期公平性披露有限；对 x86 APU/其他 NPU 的可移植性未知。

Editor Note

Abstract

Original Abstract Summary

ServeTwin combines a stateful serving loop with specification-driven analytical timing. iSTAGE derives iteration traces from model and engine specifications, decomposes component-owned timing, tracks KV evolution, and executes unmodified vLLM-compatible benchmarks.

中文摘要

多数 serving simulator 不是开环 trace replay，就是依赖目标硬件 profile。ServeTwin 让完成事件反过来改变队列、批次和 KV 状态，并把吞吐、scheduler 和 runtime 成本分属不同组件，以便跨平台局部重校准。

Technical Analysis

Problem

真实集群评估昂贵，而现有模拟器难同时支持闭环、多轮状态、P/D、未知目标硬件与未修改 benchmark。

Method

stateful event loop；spec-driven analytical trace；ragged batch/CUDA Graph padding；component-owned timing calibration。

Architecture

Benchmark client → vLLM-compatible interface → closed-loop scheduler/KV state → iSTAGE timing → event completion feedback。

Key Innovation

无需目标硬件 operator profiling，仍保留离散 engine 机制和状态反馈。

Experiments

对照真实 InferenceX 与 LMBenchmark 部署；稳态 frontier、多轮 agent workload 与 pre-silicon HBM sweep。

Editorial Assessment

Why It Matters

可在拿到目标芯片前探索 P/D、HBM 与并发设计，并避免 open-loop 模型在 stateful workload 上失真。

Limitations

Abstract

Original Abstract Summary

VenusRL fully disaggregates agentic RL and prioritizes sample groups likely to unblock the next learner step across admission, KV residency and cross-worker orchestration. Its environment manager combines memory-aware admission with template-keyed page sharing, write-protected aliasing and copy-on-write.

中文摘要

Agentic RL 的关键瓶颈不是平均 GPU 利用率，而是最慢 trajectory group 何时完成；同时 sandbox 按声明上限预留内存会造成巨大浪费。VenusRL 将这两个问题统一进 rollout 调度和环境内存管理。

Technical Analysis

Problem

多轮 tool interaction 产生严重 straggler；静态 sandbox 预留与重复基础状态浪费内存和成本。

Method

length-prediction priority；group-unblocking admission；KV residency priority；cross-worker orchestration；template page sharing + CoW。

Architecture

Learner → rollout groups → priority action scheduler → inference workers/tool sandboxes → environment memory manager → completed experience。

Key Innovation

优化目标从单 GPU 利用率改为“尽快凑齐可训练 group”，并把 sandbox OS memory sharing 纳入 RL system。

Experiments

多类 agentic RL workload；先进 baseline；端到端训练时间、group completion、sandbox density 与环境成本。

Editorial Assessment

Why It Matters

它同时击中 agentic RL 的两项真实成本：长尾 rollout 和外部环境；对 actor–learner/rollout 集群设计直接。

Limitations

优先级依赖长度预测启发式；共享页和 PTE aliasing 增加隔离/安全复杂度；代码与更大规模集群数据未公开。

Abstract

Original Abstract Summary

中文摘要

跨设施训练面对的不只是慢网，而是根本没有共享网络/文件系统、作业无法同步启动。该系统允许 0/1/N 个站点作为正常状态，利用带心跳的租约保证数据块不重不漏，并依据排队预测决定提交位置。

Technical Analysis

Problem

学术算力碎片化于不同设施、硬件栈和独立队列，传统同步分布式训练无法同时启动或共享数据。

Method

DiLoCo-style two-loop；token-weighted Nesterov outer step；DARL lease/heartbeat；`sbatch --test-only` queue probing。

Architecture

Global coordinator → facility queues → elastic local trainers → leased data blocks → periodic checkpoint/weight aggregation。

Key Innovation

把跨设施训练的优化、数据语义和 batch-queue metascheduling放在同一实部署系统。

Experiments

Snellius H100、LUMI/Frontier MI250X；跨 7,400 km；Qwen3-0.6B/C4；20k optimizer steps；planned departures。

Editorial Assessment

Why It Matters

首次给出公共 HPC 资源跨设施合并训练的完整可运行路径，并诚实量化质量与运营成本。

Limitations

作者明确称其“operational rather than competitive”；PPL 劣于集中式；queue 加速来自理想化 projection，模型仅 0.6B。
