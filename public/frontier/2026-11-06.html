Abstract

Original Abstract Summary

FlashOffloading is a host-DRAM-centric serving design that fully offloads KV state in both prefill and decode. Rolling and hot HBM caches, a reverse sparse index, and a compute-load overlapped kernel reduce the latency cost of offloading.

中文摘要

该系统不把卸载仅作为容量兜底，而是把 prefill 和 decode 的 KV 生命周期统一放在主机内存层次中，并围绕 TPOT 服务目标重构缓存、索引与数据搬运。

Technical Analysis

Problem

长上下文和高并发令 HBM 容量先耗尽；传统主机卸载虽释放容量，却因 H2D 与管理开销无法兑现吞吐。

Method

rolling HBM cache、decode hot cache、reverse sparse index、compute-load overlap。

Architecture

Ascend 910C prefill–decode disaggregated cluster；GLM-5.2；MTP3 speculative decoding；host DRAM 为 KV 主存。

Key Innovation

在完整推理流水线上全量卸载 KV，并以零额外 miss lookup 和重叠 kernel 处理延迟，而非只做分层容量扩展。

Experiments

报告同一模型与平台下的 prefill/decode 吞吐，并显式以 30 ms TPOT SLO 约束结果；节点数、上下文分布等细节需查正文。

Editorial Assessment

Why It Matters

证明主机内存层次可在严格 SLO 下提高有效吞吐，对长上下文与 PD 分离服务尤其重要。

Limitations

结果集中于 Ascend 910C 与单一 GLM-5.2/MTP3 配置；跨 GPU、PCIe/CXL 平台泛化未验证。

Editor Note

当天系统完整度最高的 KV 工作之一；数字必须与 30 ms TPOT、指定模型和平台绑定理解。

Abstract

Original Abstract Summary

FastAFD overlaps the MoE work of one microbatch with attention from another on GB200 NVL72. It compares against a tuned wide-EP baseline and decomposes benefit into batch gain, overlap gain, and GPU disaggregation cost.

中文摘要

工作纠正了“AFD 总会更快”的简单叙事：是否获益取决于释放专家权重后的 batch 扩张、跨微批重叠，以及被划给专家侧的 GPU 成本。

Technical Analysis

Problem

既有 AFD 结果常来自不同硬件、较窄 colocated baseline 或纯分析，无法回答 NVL72 上的生产部署选择。

Method

attention/MLP 角色分离、microbatch ping-pong、DeepEP 式 N2M/M2N 路径、profile-derived analytical model。

Architecture

GB200 NVL72；Qwen3、Qwen3.5、MiniMax-M2.5；vLLM wide EP baseline；EAGLE-3。

Key Innovation

不仅实现 AFD，还把部署判断压缩为三个可测增益/成本因子，并由现有 vLLM profile 预测。

Experiments

多模型、rack-scale NVLink、强基线；摘要报告最大吞吐比和 3% 预测误差，具体并发与 SLO 见正文。

Editorial Assessment

Why It Matters

给架构团队一个先 profile、后决定是否拆分的可执行判据，避免把 AFD 当作普适银弹。

Limitations

最大收益仅约 17%，且 MiniMax 无优势；对未来 SRAM expert accelerator 的 2.48× 是前瞻推断而非现有硬件实测。

Editor Note

Abstract

Original Abstract Summary

ZYFA introduces MI355X prefill kernels that approximate exponentials, overlap vector softmax with matrix instructions through a ping-pong schedule, and use power-of-two probability scaling to control rounding error.

中文摘要

FP8 只加速矩阵乘，softmax 仍在向量单元上运行；ZYFA 的关键是在 CDNA4 指令完成语义约束下重新安排矩阵与 softmax，并兼顾概率量化误差。

Technical Analysis

Problem

MI355X 上 FP8 attention 的矩阵峰值与端到端利用率脱节，且 attention 对量化更敏感。

Method

multiply-add/integer-conversion exponential approximation、thread-group ping-pong、power-of-two scale。

Architecture

AMD Instinct MI355X；长至 32K；HD128 与 DeepSeek-style MLA；AITER/Composable Kernel/Triton 对照。

Key Innovation

把 CDNA4 缺少硬件 completion tracking 的限制纳入 wave 调度，而不是只替换数据类型。

Experiments

同时报告真实模型捕获输入与 Gaussian kernel benchmark，并说明 operand-dependent sustained clock 会使随机输入误导。

Editorial Assessment

Why It Matters

为 AMD 长上下文推理补上可复现的高性能 attention 路径，也展示速度与数值误差可共同优化。

Limitations

仅 MI355X；结果对输入值、head dimension 与 MLA 形状敏感，不能横向外推。

Editor Note

实验对真实输入与随机 benchmark 的区分非常重要，避免把峰值 kernel 数字误当部署收益。

Abstract

Original Abstract Summary

BlockLock fixes the geometry observed by protected requests while retaining shared prefill. Rows mode uses fixed-width rows; Pack mode uses terminal-anchored packing and extracts protected KV state for target-only decode.

中文摘要

可复现性不必要求整批每个算子都固定。BlockLock 把契约缩到受保护请求，在保持共享 prefill 的同时固定其数值路径。

Technical Analysis

Problem

批内伴随请求变化会改变浮点归约路径；现有 batch-invariant kernel 或隔离方案牺牲性能。

Method

fixed-width rows 或 terminal-anchored packing；protected-request numerical path pinning。

Architecture

Qwen3 8B/14B、Llama-3.1-8B、Gemma-3 4B/12B；A6000/A100/H100；初步 2×A6000 TP。

Key Innovation

把确定性定义为 per-request deployment contract，而非全局 batch 形状不变。

Experiments

tinyBenchmarks、BFCL、单 GPU 三代卡与初步 TP；对照 vLLM Batch-Invariant。

Editorial Assessment

Why It Matters

审计、回归测试和高价值请求可按需获得 bitwise 复现，而普通流量保留 batching 效率。

Limitations

仅 dense 模型与有限 TP；per-deployment contract 对 kernel/版本变化的稳定性仍需验证。

Editor Note

切中生产确定性与吞吐冲突，收益显著；代码未披露限制复现分。

Abstract

Original Abstract Summary

TriAttention jointly assigns attention tiles to skip, four-bit, or eight-bit execution. A compact boundary representation and offline model-wide allocator select per-head policies, while a fused prefill kernel and compressed KV cache reuse quantized state during decode.

中文摘要

工作把稀疏与量化从两个独立开关变成同一预算分配问题：重要但耐量化的交互保留在 4-bit，而真正不重要的 tile 才被跳过。

Technical Analysis

Problem

仅稀疏会误删需要保留的交互，仅统一低比特又浪费对精度不敏感区域的机会。

Method

two-boundary policy、projected-output calibration、global allocator、precision-grouped fused traversal。

Architecture

long-context prefill fused kernel；4/8-bit QK；quantized K/V reused for decode。

Key Innovation

用常数大小的 head policy 联合决定 retention 与 precision，并把校准误差和完整 tile 成本一起优化。

Experiments

报告 Torch 与 BF16 两组端到端对照及质量任务；摘要未披露 GPU、模型与上下文长度，需正文核实。

Editorial Assessment

Why It Matters

同时减少 prefill compute 与 decode KV 读带宽，且策略存储不随上下文增长。

Limitations

最大加速对应的具体 workload 条件摘要未披露；离线校准对分布漂移的稳健性未知。

Editor Note

Abstract

Original Abstract Summary

StrataFlux co-designs a refinement representation, selective transfer, overlap, and reuse so higher-precision information from host RAM or SSD can repair aggressive low-bit weights and KV state without making every decode step wait.

中文摘要

它把低比特量化视为 GPU 常驻底座，把额外精度视为可缓存、可复用的分层数据，而不是必须同步加载的完整高精度副本。

Technical Analysis

Problem

更低比特节省容量和带宽却伤精度；传统高精度 offload 又会让生成等待慢层。

Method

selective precision streaming、overlapped delivery、cross-step reuse、weight/KV refinement。

Architecture

RTX 5090 dedicated GPU 与 unified-memory platforms；2–4-bit weights、2–3-bit KV；host RAM/SSD tiers。

Key Innovation

以“精度层次”而非完整 tensor 为单位穿越内存层次，使慢层只提供少量纠错信息。

Experiments

Llama-3.1-8B、Qwen3-8B；WikiText-2、AIME 2024/2025、128K context；与 vLLM AWQ/8-bit KV 比较。

Editorial Assessment

Why It Matters

把量化、offload 与层次缓存统一，可能扩展单卡长上下文和高并发能力。

Limitations

无代码；选择器与数据集迁移性、SSD 耐久/尾延迟以及多请求争用未披露。

Editor Note

AIME 恢复幅度醒目，但需注意其是指定模型/量化组合，不等同于一般精度恢复。
